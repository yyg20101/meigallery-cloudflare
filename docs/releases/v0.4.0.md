# v0.4.0 通用广告归因平台

## 发布目标

将 Meta、TikTok 和 Google Ads 一次性切换到统一事实、Planner、Adapter、Queue、Workflow、凭证库和后台运维架构。本版本只执行 Expand 与新运行时切换，不包含旧系统 Contract 删除。

## 主要变更

- 业务层只创建 `Contact` / `CompleteRegistration` 标准事实，一条事实只允许一个不可变 provider。
- 三个平台使用独立 Browser destination、Server adapter、主 Queue 和 DLQ；冲突、无来源和未授权事实不创建广告投递。
- 新增 11 张最终 `attribution_*` 表、AES-GCM/HKDF 凭证域、可靠 Outbox、脱敏回执、Incident、质量快照和 Free 用量预警。
- 后台统一为 `总览 / 转化明细 / 投放链接 / 平台接入 / 发布与诊断`，平台通过 URL 上下文严格隔离。
- 固定 production 快照验证幂等历史回填；旧 Delivery、Outbox、验证、Incident 和技术日报不会迁移或重投。
- 生产部署收口为单一路径，删除重复的部署期 `verify:release` 和重复构建；完整验证由 release PR/CI 承担。
- 最终三平台查询已从 2,000 行旧 Meta 运维路由拆出，转化 SQL 统一下沉到 `attribution-dashboard` 服务；高覆盖率门禁只针对最终通用运行时，不以旧兼容代码稀释结果。

## 执行与验收

```bash
./scripts/deploy.sh production
```

脚本顺序固定为：`verify:quick -> preflight -> backup -> 0051 -> API -> Web -> Workflow -> backfill -> reconcile -> identity/SEO smoke`。脚本不调整 rollout、不写平台凭证、不发送测试事件、不伪造 Live Evidence。

部署后先确认三个新连接均为 disabled、Browser/Server/rollout 均为 0，再从统一后台按 Meta、TikTok、Google 顺序配置和验证。Meta 先恢复 10%，观察严格来源隔离、Browser/Server 配对去重、Queue/DLQ 和敏感日志后再扩大范围。

## 回滚

- preflight 或备份失败：production 未写入，无需回滚。
- Expand 后 Worker 部署失败：部署上一 Worker；旧表未修改，可继续运行。
- 新 Worker 已部署但回填/对账失败：保持新平台 rollout 0，修复后重复执行幂等 backfill/reconcile，不执行 Contract。
- Contract 前保留旧 Worker 版本、D1 备份、Time Travel bookmark、旧技术表与旧 Queue。
