# Recommendation-3 地区作用域选择与安全回退开发基线

日期：2026-08-20

状态：源码开发完成；配置、migration 执行、构建、专项测试与环境验证统一后置

## 1. 结论

Recommendation-3 补齐 Recommendation-1 已保存但此前只在规则执行末端校验的 `targetRegionCodes`。Cloudflare 现在会在选择 `scheduled`、`active` 或历史回退版本时同时校验请求地区和客户端版本，非目标地区不会先选中错误规则后才失败，也不会为了维持数量而执行其他地区的配置。

本增量不新增 App API 字段、D1 表、配置项或页面，交付时累计 App API v2 契约为 `1.25.0`；Membership-7 后仓库当前累计为 `1.26.0`。Figma 仍为 99 个 Page ID / 408 个正式状态，Mobile 50/208、Admin 49/200。

## 2. 已修复的缺口

Recommendation-1 已允许运营配置最多 50 个目标地区，但此前运行时先按状态和时间选出规则，直到排序前才检查地区。这会产生三类问题：

- 到点的地区排期可能覆盖仍可服务其他地区的 active 版本；
- 当前规则不适用于请求地区时，不会继续寻找明确登记且覆盖该地区的安全回退；
- 后台允许启用回退范围小于目标范围的规则，灰度未命中的会话可能在运行期失败。

因此，保存目标地区并不等于 ROP-FR-014 的地区灰度已经闭环。本增量把地区作用域提升为规则选择条件，并把范围覆盖纳入启用门禁。

## 3. 地区作用域语义

规则中的 `targetRegionCodes` 使用以下固定语义：

- `[]`：全局规则，可服务未选择地区和任意合法地区；
- 非空数组：地区规则，只能服务数组中明确列出的规范化地区代码；
- bootstrap capability 探测不绑定具体地区，只判断是否存在至少一个格式有效且当前客户端可执行的规则；
- 推荐请求没有 `regionCode` 时，只能选择全局规则，不能猜测地区；
- JSON、数组长度或地区代码格式异常时，该规则安全失效，不进入可执行候选。

地区代码仍只允许 2–32 位小写字母、数字和连字符，目标数组最多 50 项。运行时解析与后台创建/编辑使用一致边界。

## 4. 运行时选择与降级

新推荐会话按以下顺序选择完整规则版本：

1. 读取已到生效时间的 `scheduled` 与当前 `active` 候选；
2. 按排期优先级检查地区作用域和 `minimumClientVersion`；
3. 新排期不覆盖该地区或当前客户端不兼容时，继续尝试仍有效的 active 版本；
4. 直接候选均不可执行时，只尝试各候选明确登记、已生效过、未过期且通过环境门禁的回退版本；
5. 回退版本必须同时覆盖请求地区并支持当前客户端；
6. 没有安全规则时返回明确未就绪/维护错误，不执行其他地区规则，也不放宽公开人物资格。

会话灰度未命中目标桶时会再次校验回退版本的地区作用域。签名游标继续绑定实际 `ruleVersionId`、模式、地区和偏好摘要；条件或规则变化后旧游标明确失效，不跨地区或跨版本混排。

个性化 `auto` 选择也使用同一地区规则门禁。当前地区没有可执行个性化规则时，`auto` 只回落到非个性化模式；显式请求 `personalized` 则返回不可用，不把其他地区个性化规则误当作可用。

## 5. 后台启用与回退覆盖

正常启用、保留 active 和显式回滚都会复用同一地区校验：

- 地区规则即使 `rolloutPercent=100` 且最低客户端版本等于策略基线，也必须绑定已生效过的安全回退；
- 全局目标只能使用全局回退；
- 地区目标可使用全局回退，或使用包含目标全部地区的地区回退；
- 回退仍必须满足同入口、同模式、客户端版本不高于目标、有效期、历史生效和 production-ready 门禁；
- 个性化目标与回退仍必须使用同一 taxonomy 目录，运行依赖也会重新校验。

范围不完整时启用返回既有规则校验错误并留在当前工作台，不形成部分地区可执行、部分目标地区运行失败的发布状态。所有后台写操作继续写入既有规则事件和 `admin_audit_logs`，本增量不增加旁路状态机。

## 6. 后台、KMP 与 Figma 边界

`ADM-REC-01/02/03/04` 已有规则范围、回退和错误反馈足以承载本增量；`APP-DSC-01` 已有地区选择、加载失败和维护反馈。没有新增字段、页面动作或视觉状态，因此未调用 Figma 工具，也不修改页面注册表。

KMP 已发送规范化 `regionCode`，并依赖服务端返回实际执行模式、规则版本和 fallback。客户端不自行解析运营规则、不决定回退版本，也不需要 DTO 或 UI 改动。

## 7. 明确未越过的决策门禁

本增量不实现或假定：

- OQ-009 热度公式、反刷样本和聚合任务；
- OQ-020 推荐证据保留、purge 和跨会话重复曝光上限；
- OQ-023 个性化法律决策与行为信号扩展；
- 依赖曝光事实的指标、反指标和自动停止阈值；
- 真实首发地区、地区流量比例或生产排期。

## 8. 统一后置验证

按当前开发顺序，本阶段不运行构建或测试。全部开发结束后的统一验证至少覆盖：

- 全局规则服务未选地区和明确地区；
- 地区规则不服务空地区或非目标地区；
- 地区 scheduled 到点后，非目标地区继续使用兼容 active；
- 目标规则不可执行时，只使用同时覆盖地区与客户端版本的显式回退；
- 全局目标绑定地区回退、地区目标绑定范围子集时阻断启用；
- 非法地区 JSON、超过 50 项或非规范代码安全关闭；
- 个性化 `auto` 的地区回退与显式个性化拒绝；
- 游标不能跨地区或实际规则版本继续分页。

当前没有修改 Wrangler，没有执行 `0083` 或任何后续 migration，没有启用推荐 capability，也没有运行 API/KMP 构建、测试、模拟器/真机或截图 QA。
