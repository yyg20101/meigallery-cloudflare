# 心享会员、金币与虚拟商品设计

App 版本：1.0

日期：2026-07-20

状态：需求讨论中

## 1. 商业化原则

- 权益透明：明确展示功能、额度、期限、接收主体、续订和退款。
- 会员不等于认证：付费不改变真人认证、推荐真实性或安全处置。
- 不出售关系结果：不保证真人本人回复、回复时效或线下结果。
- 闭环虚拟经济：金币不可提现、转账、兑换法币或用于概率商品。
- 账本是真相：余额由只追加账本推导，禁止直接改余额。
- 配置与代码分离：名称、价格、额度和商品配置化；新客户端能力仍需发版。

## 2. 心享会员

### 2.1 五级品牌

| rank | 等级 | 核心文案 | 产品定位 |
|-----:|------|----------|----------|
| 10 | 心遇 | 从遇见开始，解锁真人私信 | 入门互动 |
| 20 | 心悦 | 看见更多喜欢，发现更加从容 | 进阶发现 |
| 30 | 心知 | 更懂你的偏好，互动更进一步 | 深度体验 |
| 40 | 心契 | 享受高阶服务与专属装扮 | 高阶服务 |
| 50 | 心耀 | 心享至高等级，汇集完整权益 | 旗舰权益 |

首版五级全部展示和销售。名称与文案是品牌层，授权只看 rank 和 entitlement。高等级默认继承低等级权益。

### 2.2 Entitlement 分类

| 权限键示例 | 类型 | 说明 |
|------------|------|------|
| `direct_message.create` | bool | 是否可创建真人私信 |
| `direct_message.new_threads_per_day` | quota | 每日新会话额度 |
| `discovery.filter_tier` | enum | 基础/进阶/高级筛选档位 |
| `discovery.saved_filters` | quota | 保存筛选数量 |
| `history.retention_days` | quota | 浏览历史保留时长 |
| `favorite.folder_count` | quota | 收藏文件夹数量 |
| `wallet.monthly_bonus_coins` | quota | 每周期赠送金币 |
| `gift.catalog_tier` | enum | 可购买礼物目录档位 |
| `cosmetic.frame_tier` | enum | 头像框档位 |
| `cosmetic.profile_skin_tier` | enum | 主页皮肤档位 |
| `cosmetic.chat_skin_tier` | enum | 聊天皮肤档位 |
| `badge.animation` | bool | 动态会员徽章 |
| `support.priority` | enum | 客服服务优先级 |
| `feature.early_access` | set | 可提前体验的已实现能力 |

具体额度和价格由服务端版本化目录提供。任何销售页面必须显示已解析的明确值，不得出现“待定”“更多权益”等占位。

### 2.3 权益边界

任何等级都不能：

- 绕过举报、拉黑、内容审核、频控、年龄或地区限制。
- 改变真人认证结论或获得认证标识。
- 获得精确位置、私密身份信息或内部管理员信息。
- 保证本人回复、平台回复时限或关系结果。
- 提现、转账、删除账本或跳过高风险订单验证。

## 3. 会员目录与兼容

服务端目录包含：目录版本、rank、名称、文案、视觉 token、地区/渠道、商品 ID、价格展示、期限、续订类型、entitlement、最低客户端版本、生效时间和下线时间。

- 现有字段的名称、顺序、价格、额度、可见性和资产可远程调整。
- 新页面、新原生 SDK、新消息媒体或客户端没有的交互必须提高最低版本或发版。
- 旧客户端忽略未知 entitlement，不推断默认授权。
- 配置发布需 schema 校验、预览、审批、灰度、回滚和审计。

## 4. 购买生命周期

```text
created → pending_payment → verifying → active
   ├→ failed
   ├→ cancelled
active → renewed / expired / refunded / revoked / disputed
```

- 移动端数字商品遵循目标商店允许的购买方式。
- 客户端交易结果不是最终凭证，服务端完成验证后发放权益。
- 商店回调、补单和恢复购买必须幂等。
- 升级默认立即生效；降级默认下一周期生效；实际规则在 SKU 中明确。
- 到期后回落免费权限，不删除历史会话、订单和账本。
- 退款和撤销通过 entitlement 回收及反向账本处理，不编辑原记录。

## 5. 金币钱包

### 5.1 约束

- 金币仅用于目录允许的礼物和装扮。
- 购买币原则上不主动过期；赠送币可有明确有效期，消费顺序由规则固定。
- 所有数量使用整数最小单位，服务端时间为准。
- 用户离线时只能查看缓存余额，不得离线扣币或赠礼。

### 5.2 账本分录

每笔分录至少包括：

```text
entry_id
account_id
direction (credit/debit)
amount
currency_type
business_type
business_id
reason_code
user_visible_description
operator_id / approval_id（如适用）
idempotency_key
created_at
balance_after
reversal_of（冲正时）
```

余额可使用缓存快照提升查询性能，但必须能与分录重新汇总核对。

### 5.3 明细类型

- 金币充值
- 会员周期赠送
- 合规活动赠送
- 礼物消费
- 装扮消费
- 管理员加币/扣币
- 退款和冲正
- 过期（仅适用于明确标识的赠送币）

## 6. 管理员加币和扣币

### 6.1 操作流程

```text
选择账号 → 选择操作类型 → 输入数量
→ 选择标准原因 → 填写用户说明/内部备注/工单
→ 风险判断 → 直接生效或进入双人复核
→ 追加账本 → 通知用户 → 对账与审计
```

### 6.2 规则

- 对普通用户和会员采用同一账本模型，不按身份分账。
- 管理员只能新增调整申请，不能编辑余额或历史分录。
- 原因代码和用户可见说明必填；内部备注不能替代用户说明。
- 超过阈值、高频、批量、跨地区或导致负余额的操作需要双人复核。
- 发起人与复核人不得相同；复核前余额不变化。
- 错误操作以关联冲正分录修复。
- 用户收到数量、方向、原因、时间和申诉入口；安全敏感细节可不公开。
- 批量调币逐项幂等，支持预览、暂停和失败明细。

## 7. 礼物

- 礼物是固定名称、固定资产、固定金币价格的非提现互动商品。
- 赠送目标是 `PersonProfile`，接收真人不获得金币或分成。
- 赠礼确认显示目标、接收模式、单价、数量、总价和余额。
- 扣币与礼物记录原子完成；重试使用同一幂等键。
- 礼物可显示在会话或互动明细，但平台代运营不得伪造真人本人感谢。
- 资料暂停、拉黑、会话关闭、商品下架或安全受限时禁止赠送。
- 不提供概率礼物、礼物收益榜或诱导攀比的实时消费榜。

## 8. 头像框与皮肤

统一商品类型：`avatar_frame`、`profile_skin`、`chat_skin`。

期限类型：

- 永久。
- 固定到期日。
- 领取/购买后有效天数。
- 会员附赠，随 entitlement 有效。

用户可预览、购买、装备、卸下和恢复默认。同一槽位只能启用一个资源。资源失败时回退默认视觉。

商品下架后不得新购；永久已购资源原则上继续可用。因安全、版权或合规必须撤回时，展示原因并进入补偿/退款流程。

## 9. 商品目录

统一目录字段至少包含：

- 商品 ID、类型、名称、说明和资源版本。
- 币种、价格、原价展示规则和地区/渠道。
- 会员门槛、购买限制、期限和库存规则。
- 可售时间、上下架、最低客户端版本和灰度。
- 退款、撤回、会员到期和版权下架规则。

价格版本一经产生订单不可覆盖；新价格创建新版本。

## 10. 订单、退款与对账

- 订单状态：创建、待支付、验证中、生效、失败、取消、退款、撤销、争议。
- 每个外部交易 ID、业务订单 ID 和幂等键具有唯一约束。
- 会员、金币和商品发放记录关联原订单。
- 退款不删除订单；通过状态变化、权益回收和反向分录表达。
- 日对账比较商店交易、订单、entitlement、账本和库存。
- 差异进入队列，禁止用手工覆盖余额“抹平”。

## 11. 权限与审计

| 操作 | 建议角色 | 复核 |
|------|----------|------|
| 编辑会员/商品草稿 | 商业运营 | 发布审批 |
| 发布价格与权益 | 商业负责人 | 必须 |
| 低风险单笔补偿 | 授权客服 | 按阈值 |
| 高额/批量加扣币 | 财务 | 双人复核 |
| 退款/冲正 | 财务/客服 | 按金额和原因 |
| 查看完整对账 | 财务审计 | 独立只读权限 |

审计事件记录操作者、角色、目标、请求、原因、前后状态、审批链、时间和关联工单，但不记录完整支付凭证。

## 12. 安全与风控

- 防止重复回调、凭证重放、盗刷、越权调币和批量撞库。
- 购买和赠礼同时校验账号、设备、地区、商品、目标和频率。
- 高风险交易可延迟发货或进入人工审核，并明确告知状态。
- 不以高消费降低安全限制、举报权重或真人认证标准。
- 异常告警覆盖负余额、分录断号、订单已付未发、重复发货和审批绕过。

## 13. 验收标准

- **COM-AC-001**：首版同时展示五级心享会员及可比较的明确权益。
- **COM-AC-002**：更改已有文案或额度后，支持字段的客户端无需升级即可刷新。
- **COM-AC-003**：同一商店凭证或赠礼幂等键不会重复发货/扣币。
- **COM-AC-004**：任一余额可由有效账本分录重建并与快照核对。
- **COM-AC-005**：管理员扣币产生用户可见说明，超过阈值未复核时余额不变。
- **COM-AC-006**：错误分录通过冲正修复，原记录保持不可变。
- **COM-AC-007**：礼物不产生真人可提现余额或平台外价值。
- **COM-AC-008**：会员到期后受限能力自动失效，但历史合法记录保留。
