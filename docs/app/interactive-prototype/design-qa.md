## 3. 逐页捕获与映射规则

每张原型图均由以下键唯一确定：

`Page ID + state + variant`

其中：

- `default`：92 个页面各一张默认状态。
- `key_state`：54 个 P0 页面各一张最关键的异常、受限、冲突或完成状态。
- 文件名、图片替代文本、画面标题和右侧需求说明均显示同一 Page ID 和状态。
- `manifest.json` 记录源 URL、图片路径、尺寸、字节数和 SHA-256。
- DOCX 生成器只读取已标记为 `verified` 的清单；数量或状态不符时直接停止生成。

## 4. 必查视觉表面

### 4.1 字体与信息层级

- 标题、正文、辅助说明、状态标签和按钮层级在移动端及后台保持一致。
- 关键规则不依赖超小字号；长文案可换行，不与操作按钮重叠。
- 金额、编号、时间和 Page ID 具有足够辨识度。

### 4.2 间距与布局

- 1600 × 1000 文档捕获模式中，原型预览与需求说明固定分栏。
- 卡片、表单、列表和操作区未出现截断、异常留白或横向溢出。
- 移动端安全区域、底部导航和后台侧栏保持稳定。

### 4.3 颜色、圆角与状态

- 玫红仅用于品牌和主操作；危险操作、警告、成功与中性信息使用独立语义色。
- 卡片圆角、输入框、标签和按钮边界一致。
- 禁用、处理中、失败、冲突和只读状态不只依赖颜色表达。

### 4.4 图片与人物素材

- 人物图使用可用的真实素材，不使用占位框、表情符号或代码绘制替代。
- 图片裁切保持主体面部与核心构图完整，无拉伸、低清或错误比例。
- 管理后台缩略图与移动端真人资料指向同一类内容语义。

### 4.5 文案与产品边界

- 当前沟通入口统一为“发起话题”，持续显示“平台接收”。
- `platform_managed` 页面不出现“给她私信”“与本人聊天”“本人已读”“正在输入”或保证回复。
- 五级会员统一为心遇、心悦、心知、心契、心耀。
- App 1.0 不出现在线购买、充值、送礼、转账或提现入口。
- 金币页面明确“不具现金价值”，后台以申请、审批和追加式分录改变余额。
- 普通注册账号只作为观看者；公开真人仅来自管理员创建或认证发布。

## 5. 关键业务旅程回归

### 5.1 会员与平台话题

已验证：

1. 普通观看者从真人详情点击“发起话题”后进入会员门槛，不创建会话。
2. 用户选择等级并提交站内会员申请，申请本身不产生 entitlement。
3. 后台审核后创建 grant，grant 生效后 App 才刷新权限。
4. 会话顶部、首屏说明和回复身份持续披露“平台运营接收”。
5. 用户消息具有发送中、审核中、已送达、平台运营已读和失败状态。
6. 会员到期后历史会话可读、输入区只读，不继续发送。

### 5.2 内容、认证与发布

已验证：

- 管理员新建或导入只生成真人草稿。
- 认证未完成时发布操作不可用；授权、认证和发布审核为独立事实。
- 暂停或授权撤回后，推荐、搜索、详情和受保护媒体访问同步失效。
- 画面不把“管理员上传”错误表达为“本人已入驻”。

### 5.3 金币与审计

已验证：

- 用户钱包只读展示余额和追加式明细，不提供充值、转账或提现。
- 管理员调币先申请、后由独立角色审批；直接加扣余额不存在 UI 入口。
- 冲突、重复、余额不足和审批完成均有独立页面状态。
- 审计详情展示操作者、时间、原因、关联单号和前后事实。

## 6. 本轮问题、修正与复核

### P1：客户文档原型与章节功能点错配

- 问题：旧 DOCX 使用模块拼图，章节内图片同时包含多个功能，客户无法确认图片对应哪一项需求。
- 修正：建立 92 个 Page ID 的独立默认原型，并为 54 个 P0 页面增加关键状态；章节内图片也替换为精确 Page ID。
- 复核：清单、Markdown、DOCX 生成链路统一按 Page ID 引用，不再依赖人工挑图。

### P1：逐页截图缺少需求上下文

- 问题：单独手机或后台画面无法说明角色、前置、规则、权限和验收。
- 修正：文档捕获模式在原型右侧同步展示页面目的、业务规则、交互、状态和风险说明。
- 复核：146 张原型均为 1600 × 1000 完整说明画面。

### P2：动画与浏览器编码影响截图稳定性

- 问题：淡入中间态和浏览器返回 JPEG 字节可能造成截图外观或格式不稳定。
- 修正：捕获模式关闭动画，等待图片加载和 `data-capture-ready`；校验脚本统一规范化为真实 PNG。
- 复核：146 张文件均为真实 PNG、尺寸一致且无重复哈希。

## 7. 最终结论

未发现待处理的 P0、P1 或 P2 设计问题。

当前原型已具备逐页确认、开发拆解和测试验收所需的信息：每个页面有独立默认原型，每个 P0 页面有关键状态，且产品语义、视觉、交互和文档引用保持一致。

final result: passed
