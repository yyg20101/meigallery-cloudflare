## 1. 文档目的

本文定义独立 App 在现有 Nuxt 管理后台中的目标信息架构、页面编号、角色入口、关键表单、状态、并发规则和页面布局。目标是让内容、审核、代运营、会员、财务、安全和审计人员在同一后台工作，同时保持职责分离和对象级权限。

43 个后台 Page ID 均已进入 [App 1.0 逐页交互设计库](./interactive-prototype/pages.html)，可独立访问、切换必备状态并查看页面目标、入口、主次操作和验收说明；完整目录见 [逐页产品与交互设计](./APP_PAGE_LEVEL_PRODUCT_DESIGN.md)，逐页角色、规则、权限、需求编号、验收与原型见 [详细功能与逐页原型说明](./APP_DETAILED_FUNCTION_PROTOTYPE_SPEC.md)，上游需求对应关系见 [需求追踪矩阵](./APP_REQUIREMENTS_TRACEABILITY.md)。

本文仍是 43 个目标后台 Page ID 的设计事实源。当前仅落地人物供给 M1 最小闭环：`/admin/app/persons`、`/admin/app/persons/new` 和 `/admin/app/persons/{personId}`，认证与发布复核暂时嵌入单人物工作台，复用现有 admin+ 会话和 `/api/admin/app/persons/*`。其余页面仍未实现；任何 production migration、真实人物/证据导入和生产后台变更均未授权。

M1 页面已实现的交互边界：三轴状态、内容/线上版本并列、`expectedVersion` 冲突保护、用途授权登记/撤销、四项认证提交/通过/退回/撤销、全门禁发布/退回/暂停、审批历史与证据引用。正式职责分离尚未冻结，因此当前通用骨架只记录操作员与完整审计，不把“同人不可审批”等策略硬编码；生产启用前必须按 G-02 决定。

## 2. 范围和边界

### 2.1 App 1.0 后台包含

- 运营总览、异常中心和数据质量状态。
- 真人手动上传、MeiGallery 导入、来源/授权、认证与发布。
- Taxonomy、地区、分类、推荐规则、热度和运营精选。
- 平台话题运营队列、分配、平台身份回复、内部备注和安全升级。
- 举报、拉黑联动、审核处置和申诉。
- 五级会员目录、typed entitlement、手动发放、复核和迁移差异。
- 金币钱包查询、加币/扣币/补偿、批量任务、复核、冲正和对账。
- 站内通知事件/模板状态、只读生成结果和必要的受控运营任务。
- 审计查询、完整性状态、异常处置和受控导出。

### 2.2 App 1.0 不显示可执行模块

- 在线商品价格、订单、支付、退款和金币充值。
- 礼物、头像框和皮肤商品管理。
- 系统推送供应商、推送证书和系统通知群发。
- 真人本人认领和历史会话交接。

未来模块立项前不在正式导航显示，也不以“未开通”卡片占用 1.0 工作空间。

### 3.2 设计路由命名

建议将 App 共享核心后台置于 `/admin/app/*` 信息域，避免与 legacy 图库后台对象混淆。此路径是设计建议，最终路由由技术方案冻结；Page ID 不随路由改变。

### 3.3 角色边界

| 角色 | 可见领域 | 关键限制 |
|------|----------|----------|
| Owner | 跨域摘要和授权配置 | 不默认查看话题正文或敏感证据；应急动作同样审计 |
| 内容运营 | 真人、媒体、taxonomy、推荐草稿 | 不能独立完成要求复核的认证/发布 |
| 认证审核 | 来源、授权和认证案件 | 不能修改原始导入事实或会员/金币 |
| 发布审核 | 公开预览、发布/暂停/归档 | 不能把未认证资料发布 |
| 代运营人员 | 被分配的会话和必要上下文 | 只能以平台运营身份发送 |
| 代运营组长 | 队列、班次、分配和质量 | 不能解除安全冻结 |
| 安全审核 | 举报案件和最小证据 | 证据按案件授权，不能改账本 |
| 会员运营 | 目录草稿和会员发放申请 | 不能批准自己的高风险申请 |
| 财务运营 | 钱包摘要和调币申请 | 不能直接改余额或批准自己的申请 |
| 复核人员 | 指定会员/调币复核队列 | 不能改申请原文后批准 |
| 审计人员 | 跨域只读审计和完整性 | 不能执行业务动作或删除事件 |
| SRE | 技术健康和异常 | 不读取业务正文 |

角色同时受对象范围、地区、运营组、案件和临时授权约束；菜单可见不等于对象可读。

## 4. 全局后台框架

### 4.1 信息架构

```text
运营总览
├── 跨域摘要
└── 异常中心
真人与内容
├── 真人列表 / 新建
├── 导入任务
├── 认证审核
└── 发布审核
发现运营
├── Taxonomy / 地区 / 分类
├── 推荐规则
└── 运营精选 / 热度
互动与安全
├── 代运营会话
├── 举报审核
└── 申诉
会员与金币
├── 会员目录 / Entitlement
├── 会员申请 / 发放 / 复核
├── 钱包 / 调币 / 批量
└── 对账差异
站内通知
├── 事件定义
├── 模板版本
└── 生成结果
审计
├── 审计查询
├── 完整性状态
└── 受控导出
```

用户只看到拥有至少一个动作或读取权限的导航组。无权限模块不展示数量、名称或对象存在性。

### 4.2 桌面框架

```text
┌──────────────┬────────────────────────────────────────────┐
│ 产品/环境     │ 页面标题   数据范围   搜索   任务   管理员菜单 │
│ 运营总览      ├────────────────────────────────────────────┤
│ 真人与内容    │ 面包屑 / 页面说明 / 数据新鲜度 / 主操作       │
│ 发现运营      │                                            │
│ 互动与安全    │       页面工作区：列表 / 详情 / 看板           │
│ 会员与金币    │                                            │
│ 站内通知      │                                            │
│ 审计          ├────────────────────────────────────────────┤
│              │ 请求 ID / 帮助 / 当前权限范围                 │
└──────────────┴────────────────────────────────────────────┘
```

- 顶部始终显示环境和数据范围，生产环境使用文字与图标双重警示。
- 页面主操作固定在标题区，列表批量操作仅在选择后出现。
- 中宽窗口使用“列表 + 详情”，超窄窗口退化为导航栈；不得压缩关键原因、金额或身份标签。
- 路由切换保留列表筛选；对象状态变化或权限撤销时强制刷新详情。

### 4.3 通用列表

所有列表必须提供：

- 数据范围、时间、状态、Owner/分组等允许筛选。
- 服务端分页、排序字段说明、已应用筛选摘要和清空。
- 数据新鲜度、质量状态和“未知 ≠ 0”的表达。
- 列设置只影响个人视图，不改变导出和权限。
- 选择后的批量操作必须先预览影响，单项失败不重做成功项。
- 空状态区分“尚无数据”和“当前筛选无结果”。

### 4.4 通用详情与表单

- 详情标题显示稳定对象 ID 的安全短码、状态、版本和最近更新。
- 只读事实、可编辑草稿和审批结论分区；不能让审核人在同一字段上边改边批。
- 保存草稿不等于提交，提交不等于批准，批准不等于执行成功。
- 高风险操作展示前后差异、影响对象、用户可见文案、内部原因、复核要求和幂等业务单号。
- 并发更新使用版本/ETag；冲突时提供“查看最新版本”和“复制我的草稿”，禁止静默覆盖。

### 5.3 Taxonomy 与推荐运营

| Page ID | 设计路由 | 页面 | 主操作 | 关键状态 |
|---------|----------|------|----------|----------|
| `ADM-TAX-01` | `/admin/app/taxonomy` | 目录树 | 新建词条、搜索、选择版本 | 草稿/生效/归档目录 |
| `ADM-TAX-02` | `/admin/app/taxonomy/{termId}` | 词条详情 | 编辑草稿、alias、映射、合并预览 | 被引用、合并冲突、版本过期 |
| `ADM-TAX-03` | `/admin/app/taxonomy/releases/{id}` | 目录发布 | 校验、影响预览、复核、发布/回滚 | 未知引用、客户端不兼容 |
| `ADM-REC-01` | `/admin/app/recommendation/rules` | 规则版本 | 创建草稿、复制、停用 | 当前生效、灰度、回滚 |
| `ADM-REC-02` | `/admin/app/recommendation/rules/{id}` | 规则编辑 | 配置候选/排序、保存、提交 | schema 错误、越过安全过滤 |
| `ADM-REC-03` | `/admin/app/recommendation/rules/{id}/preview` | Dry-run | 选择合成场景、比较版本 | 样本不足、数据延迟 |
| `ADM-REC-04` | `/admin/app/recommendation/placements` | 运营精选 | 创建排期、预览披露、暂停 | 时间冲突、资料下架 |

推荐规则页面不能编辑认证/授权资格；安全过滤作为不可关闭前置显示。

Taxonomy-1 已按 `ADM-TAX-01/02/03` 完成 Nuxt 开发基线：目录页按固定 11 类展示稳定词条并提供筛选、草稿创建、目录版本和 legacy 映射治理；详情页覆盖编辑、别名、复核、生命周期、稳定合并、修订历史和快照引用；发布页展示不可变快照、父级/重定向结构检查、公开与客户端影响，并要求兼容性和不可变性双重确认。`ADM-PER-03` 同步提供目录选择、稳定词条标注、失效项显式处理和草稿/线上投影对比。所有状态操作携带 `expectedVersion`，高风险操作由服务端审计。当前服务端没有显式目录回滚契约，页面不生成伪回滚入口；回退通过新快照加后续配置切换完成，正式回滚 API 仍后置。

Search-2 在 `ADM-TAX-01` 发现目录治理下增加 `/admin/app/search` 只读运维子视图，不增加客户功能 Page ID，也不提供可执行配置动作。页面按“运行门禁 → 不可变策略 → taxonomy/会员依赖 → 隐私聚合健康 → 目录迁移引用”组织，只显示非敏感版本与聚合计数；搜索词、保存条件名称、用户明细和 term 组合不得进入响应或后台界面。

Recommendation-1 已按上述四个 Page ID 完成 Nuxt 开发基线：规则列表支持门禁摘要、筛选、创建和版本状态；规则详情支持权重、多样性、灰度、排期、回退、职责分离和时间线；Dry-run 只使用合成地区与空偏好场景，不读取真实用户历史；精选页面固定显示“平台精选”披露并在全生命周期复核人物公开资格。所有写操作使用 `expectedVersion`，创建/复制使用幂等键。当前后台 capability 默认关闭，配置、migration 和专项验证按统一收尾阶段执行。

`ADM-MBR-03` 必须区分“用户申请状态”和“会员 grant 状态”：申请获批不等于权限已经生效。操作员批准申请后仍需进入 `ADM-MBR-04` 的发放预览与必要复核；只有 grant 事务成功，用户申请才显示“已发放”。管理员也可在无用户申请时直接创建发放申请，但原因和业务单号仍为必填。

### 6.1 通用列表 + 详情

```text
┌──────────┬──────────────────────┬────────────────────────────┐
│ 左侧导航  │ 列表与筛选             │ 对象详情                     │
```

列表选择不改变浏览器历史中的筛选；详情 route 可复制但打开后重新鉴权。

### 6.2 真人认证与发布 `ADM-PER-03/05/06`

```text
┌──────────┬───────────────────┬──────────────────────────────┐
│ 真人列表  │ 版本与审核时间线     │ 真人工作台                     │
```

### 6.3 代运营会话 `ADM-MSG-02`

```text

│          │ 用户消息                 │ 内部备注（永不发送给用户）       │
│          │ [平台回复输入框] [发送]    │ [转派] [升级安全] [交班]       │
└──────────┴────────────────────────┴───────────────────────────┘
```

- 回复输入与内部备注使用不同区域、标题、背景语义和提交按钮。
- 平台回复按钮只调用平台身份接口，页面不存在 sender type 选择器。
- 未获得会话租约、会员到期、用户拉黑或安全冻结时回复区只读。

## 7. 核心后台旅程

### 7.1 真人从导入到公开

```text
创建导入任务 → 校验来源/结构/重复 → 逐项生成草稿
→ 内容运营补充授权和公开字段 → 提交认证
→ 认证审核通过 → 提交发布
→ 发布审核预览公开投影 → 发布
→ App 各公开入口可见
```

任一步失败只影响对应项目；暂停、撤销认证或授权失效后，后台显示撤权范围和执行进度。

### 7.2 代运营处理新会话

```text
会话进入待分配 → 规则建议组/操作员 → 操作员领取租约
→ 核对平台接收披露和必要上下文 → 平台身份回复
→ 待用户 / 待平台状态流转 → 交班、转派、关闭或升级安全
```

队列无值班或超容量时进入异常中心，不自动发送虚假回复。

### 7.3 会员手动发放

```text
搜索并二次确认账号 → 选择动作/等级/区间
→ 填写标准原因、用户说明和工单 → 预览前后权益
→ 提交 → 直接执行或等待独立复核
→ grant 生效 → entitlement 刷新 → 站内通知 → 审计/对账
```

### 7.4 管理员调币

```text
搜索账号 → 选择方向和正整数数量 → 填写原因/说明/工单
→ 预览余额与风险 → 提交 → 必要复核
→ 再校验余额 → 追加分录 → 更新快照
→ 通知用户 → 对账
```

误操作通过新冲正申请处理，不能编辑原分录。

### 7.5 异常处置

```text
告警进入异常中心 → 分级与认领 → 查看影响/Runbook
→ 必要时执行授权安全开关 → 对应业务流程 forward-fix
→ 对账和恢复验证 → 关闭并关联复盘
```

## 8. 批量、并发和长任务

### 8.1 批量任务

- 采用“上传/选择 → 校验 → 影响预览 → 提交/复核 → 异步执行 → 逐项结果”。
- 结果页显示成功、失败、重复、跳过和可重试；成功项永不因重试再次执行。
- 任务暂停只影响尚未执行项目；取消不承诺回滚已生效项目。
- 导出失败结果需短期凭证和权限校验，不包含不必要敏感字段。

### 8.2 并发冲突

| 场景 | 页面行为 |
|------|----------|
| 对象版本已变化 | 阻止保存，展示最新差异和复制本人草稿 |
| 会话租约被占用 | 回复区只读，允许刷新或申请转派 |
| 复核单已处理 | 展示最新结论，禁用当前提交 |
| 钱包余额在复核后变化 | 阻止沿用旧预览，返回重新评估 |
| 目录/推荐版本已发布 | 当前草稿保留为新版本，不覆盖生效版本 |

### 8.3 长任务反馈

- 导入、迁移、批量调币、导出和数据修复显示服务端状态，不用前端进度动画伪造百分比。
- 离开页面后任务继续；任务中心和站内后台提醒可重新进入。
- 失败显示阶段、可重试性、安全错误码和 Request ID，不展示内部堆栈。

## 9. 高风险操作规范

以下动作必须包含影响预览、强认证/近期认证、原因、必要复核、明确按钮和审计：

- 发布、暂停、归档真人或撤销认证。
- 合并 taxonomy、发布/回滚推荐规则。
- 查看敏感证据、跨组私信或执行安全处置。
- 发放、替换、撤销会员和批量迁移。
- 扣币、批量调币、冲正和解除钱包冻结。
- 执行安全开关、导出审计或敏感报表。

确认弹窗只用于最后确认，不代替前一页完整影响预览。按钮使用“发布真人资料”“提交扣币复核”等事实动词，不使用模糊“确定”。

## 10. 键盘、无障碍与响应式

- Tab 顺序遵循导航 → 标题操作 → 筛选 → 列表 → 详情 → 底部状态；焦点不能跳入隐藏面板。
- 列表支持方向键浏览或明确的标准表格导航；选择变化后不无故抢焦点。
- Dialog 打开时聚焦标题/首个安全控件，关闭后返回触发元素；Escape 不直接确认危险操作。
- 图表提供同口径数据表；状态、风险、正负方向和环境不能只依赖颜色。
- 200% 缩放时主要操作、原因、前后差异和接收主体不截断。
- 窄窗口从三栏变为单列导航栈，回复、复核和危险操作不能被折叠为无文字图标。

## 11. 后台页面验收

- **AUI-AC-001**：不同角色登录后只看到授权导航和对象范围，不能通过复制详情路由扩大权限。
- **AUI-AC-002**：认证和发布是独立状态与操作；未认证/授权失效资料不能发布。
- **AUI-AC-003**：代运营工作台不存在 person sender 选择，平台回复与内部备注在视觉和 API 上隔离。
- **AUI-AC-004**：无会话租约、用户拉黑、会员到期或安全冻结时，操作员不能继续发送。
- **AUI-AC-005**：会员发放提交前展示等级、区间和 entitlement 前后变化；需复核时批准前不生效。
- **AUI-AC-006**：管理员无法直接修改钱包余额或历史分录，错误只能通过冲正流程。
- **AUI-AC-007**：批量任务单项失败不回滚或重做成功项，逐项结果可追踪。
- **AUI-AC-008**：审计查询和导出不能修改业务；敏感导出有复核、水印、短期凭证和自身审计。
- **AUI-AC-009**：数据延迟显示未知/延迟，不以 0 替代；支付、礼物和推送未启用时看板不出现相应指标。
- **AUI-AC-010**：键盘和 200% 缩放下可完成认证、代运营回复、会员复核、调币复核和审计查询。

## 12. 设计交付要求

后台高保真和点击原型必须：

1. 使用本文 Page ID 标注 Frame，并标出角色和对象范围。
2. 给出列表、详情、空、错误、无权限、并发冲突和长任务状态。
3. 对所有审批区分草稿、提交、批准、执行和生效。
4. 标注用户可见文案与内部原因的边界。
5. 标注敏感证据、私信正文和财务数据的访问权限。
6. 标注 API 资源、幂等业务单、审计 action 和埋点 event key。
7. 将 Future 模块放入独立设计文件，不混入 App 1.0 导航原型。
