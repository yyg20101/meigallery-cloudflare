# “心动遇见你”独立交友 App 产品需求文档

版本：1.0（设计基线）

日期：2026-07-19
状态：`[已确认方向 / 目标设计]`

## 1. 产品概述

“心动遇见你”是面向成年用户的实名、非匿名、强调安全边界的中文交友 App。产品帮助用户发现同城或兴趣相近的人，在对方同意后建立匹配关系并进行即时沟通。

产品以独立 App 形态发布，但账号、权益、授权媒体、标签和管理员体系最终由共享业务平台统一提供。现有 MeiGallery Web 将按模块渐进迁移到共享平台，迁移期间保持可用。

### 1.1 核心价值

- 可信：手机号、年龄和身份核验状态可验证，认证徽章不与付费等级混淆。
- 克制：陌生人不能无限发送私信，匹配或接受招呼后才能持续聊天。
- 安全：拉黑、举报、内容过滤、人工审核和申诉形成闭环。
- 隐私：默认只展示城市和模糊距离，不公开精确位置、身份证信息或活动轨迹。
- 可迁移：现有 MeiGallery 数据按授权和质量门禁复用，不制造虚假交友资料。

### 1.2 差异化要求

Apple 对同质化交友 App 的审核较严格，因此“粉色视觉 + 附近的人 + 聊天”不足以构成差异化。公开上架版本必须至少证明以下差异：

1. 分层认证：手机号、身份、真人状态分开表达，用户能理解每个徽章代表什么。
2. 同意后聊天：招呼、匹配和持续会话边界明确，减少骚扰。
3. 安全中心：举报进度、证据留存、拉黑、会面安全提醒和隐私控制可见。
4. 数据来源透明：迁移账号、资料媒体和运营内容都有来源与授权状态。

## 2. 用户与角色

| 角色 | 定义 | 核心权限 |
|------|------|----------|
| 访客 | 未登录用户 | 查看品牌说明、服务条款、隐私政策和登录入口 |
| 待激活用户 | 已登录但未完成成年人验证或交友授权 | 管理账号、完成验证，不进入发现流或聊天 |
| 普通用户 | 完成必要验证并创建已审核资料 | 发现、有限招呼、匹配后聊天、举报和拉黑 |
| VIP 用户 | 拥有有效 App 权益 | 高级筛选、更多招呼额度、访客记录等；不绕过安全限制 |
| 审核员 | 处理资料、媒体和举报 | 仅访问任务所需信息，所有操作写审计日志 |
| 客服 | 处理账号、订单和申诉 | 不得查看无关私聊内容或完整身份材料 |
| 管理员 | 管理用户、审核、运营配置 | 按最小权限授权，后台写操作全部审计 |
| Owner | 管理角色、支付配置和高风险操作 | 高风险操作需要二次确认或双人复核 |

## 3. 产品范围

### 3.1 首个内测版本 M1

- 手机号注册/登录、现有账号绑定、登录设备管理。
- 成年人声明、手机号核验、服务协议与隐私授权留痕。
- 创建资料：昵称、出生年份、城市、职业、简介、兴趣标签、头像和照片。
- 资料与媒体先审后发；审核未通过时提供明确原因和申诉入口。
- 推荐、附近、活跃三个发现入口；支持基础筛选和非个性化排序。
- 喜欢、跳过、发送一次招呼、接受或拒绝招呼、双向匹配。
- 匹配后文字、表情和官方贴纸聊天；首版不开放用户聊天图片、语音和视频。
- 消息送达/已读、撤回窗口、会话静音、解除匹配。
- 拉黑、举报、证据快照、安全中心和审核后台。
- 管理员手动授予 App 权益，兼容现有会员来源。
- 数据导出、撤回同意、账号注销申请和处理进度。

### 3.2 公开发布版本 M2

- Apple App Store 与目标 Android 渠道的合规内购。
- VIP 订阅、金币充值、确定性虚拟礼物和完整账本。
- APNs、FCM 以及经评估后的中国 Android 厂商推送。
- 访客记录、更多筛选条件、资料曝光控制。
- 聊天图片在内容过滤和审核能力达标后灰度开放。
- 风险分层限流、设备风险、异常充值和骚扰行为检测。
- 运营活动、订阅恢复、退款和订单对账。

### 3.3 后续能力 M3+

- 语音消息、音视频通话和视频资料。
- 经审批的更细推荐模型与实验平台。
- 多地区、多语言和区域化合规。
- 用户活动或线下活动组织能力。
- 端到端加密只作为独立研究项目，不在当前消息审核架构中承诺。

### 3.4 明确不做

- 不允许未满 18 周岁用户使用交友功能。
- 不做随机或匿名聊天、阅后即焚、匿名群聊。
- 不做“颜值打分”“热门女生排行”等物化真人的机制。
- 不提供色情、裸露、性交易、陪侍招募或成人服务撮合。
- 不开放用户直播，不接入博彩、抽奖式礼物或随机付费道具。
- 金币不可提现、不可兑换法币、不可跨产品转移、不可用户间直接转账。
- 不出售“绕过拉黑”“查看精确位置”“强制开聊”等权益。
- 不把私聊内容用于广告画像或模型训练。

## 4. 核心用户旅程

### 4.1 新用户激活

1. 用户查看成年人提示、条款和隐私摘要。
2. 用户通过手机号验证码登录；高风险请求完成 Turnstile 验证。
3. 系统确认用户年满 18 周岁，并完成必要的身份/年龄核验。
4. 用户逐项授权资料展示、模糊位置、个性化推荐和营销通知。
5. 用户创建资料并提交审核。
6. 审核通过后资料才进入发现流。

验收要点：拒绝位置权限时允许手动选择城市；拒绝个性化推荐时仍能使用按活跃度或时间排序的发现流。

### 4.2 现有 MeiGallery 用户迁移

1. 用户使用原账号完成一次重新认证。
2. 系统展示“加入独立交友产品”的数据迁移说明。
3. 用户明确选择要迁移的基础字段和已授权媒体。
4. 系统完成手机号、成年人和新条款核验。
5. 用户补全交友资料并提交审核。
6. 未同意或未完成审核的用户绝不出现在发现流。

### 4.3 发现与匹配

1. 用户进入推荐、附近或活跃列表。
2. 卡片只展示完成审核的公开资料、认证状态和模糊位置。
3. 用户可喜欢、跳过或发送一条受限招呼。
4. 对方接受招呼或双方互相喜欢时创建匹配。
5. 匹配建立后开放持续聊天；任一方解除匹配或拉黑后立即关闭发送能力。

### 4.4 举报与拉黑

1. 用户从资料页或会话页打开安全菜单。
2. “拉黑”和“举报”作为两个独立、清晰的动作。
3. 拉黑即时生效：互相不可发现、不可发消息、不可查看访客记录。
4. 举报允许选择最近消息作为证据，并告知处理时限。
5. 高危类别进入优先队列；处理完成后向举报者反馈可披露的结果。

### 4.5 购买与赠礼

1. 用户查看权益或金币用途、价格、订阅周期和自动续费规则。
2. 购买通过对应应用商店支付系统完成。
3. 服务端验证交易并以幂等方式记入权益或金币账本。
4. 发送礼物时先完成金币扣减，再生成不可兑现的礼物事件。
5. 退款、撤销或商店通知触发账本冲正，不直接修改余额。

## 5. 功能需求

### 5.1 账号与身份

- **FR-AUTH-001**：手机号是 App 首发主登录方式；邮箱密码仅用于现有账号迁移或恢复。
- **FR-AUTH-002**：登录令牌必须支持单设备撤销、全部设备退出和刷新令牌轮换。
- **FR-AUTH-003**：第三方登录只能作为辅助方式，不能替代必要的手机号和成年人核验。
- **FR-AUTH-004**：认证状态至少拆分为 `phone_verified`、`age_verified`、`identity_verified`、`liveness_verified`。
- **FR-AUTH-005**：未接入符合要求的认证流程前，界面不得展示“实名认证”或“真人认证”徽章。
- **FR-AUTH-006**：VIP 徽章与认证徽章必须使用不同形状、颜色和说明文案。

### 5.2 资料与媒体

- **FR-PRO-001**：资料包含公开字段、仅匹配可见字段和私密字段三个可见性层级。
- **FR-PRO-002**：出生日期、手机号、身份凭证和精确位置永不公开。
- **FR-PRO-003**：公开资料变更经过审核后生效；旧版本在新版本审核期间保持可用，违规修正除外。
- **FR-PRO-004**：每张资料媒体必须记录主体授权、来源、审核状态和展示用途。
- **FR-PRO-005**：删除资料媒体时同步撤销所有公开变体和访问凭证。

### 5.3 发现、推荐与位置

- **FR-DIS-001**：推荐流只能包含可发现、审核通过、未被当前用户拉黑且满足双方偏好的资料。
- **FR-DIS-002**：附近流使用城市和模糊距离段，不返回精确经纬度或可反推出住所的稳定距离。
- **FR-DIS-003**：在线状态使用“在线”“近期活跃”等宽粒度状态，不披露精确最后在线时间。
- **FR-DIS-004**：用户可以关闭个性化推荐并使用非个性化排序。
- **FR-DIS-005**：用户可以暂停被发现、隐藏距离和限制谁可以发送招呼。
- **FR-DIS-006**：推荐接口必须提供可审计的主要排序因素和版本号，不向客户端返回内部风险分。

### 5.4 互动、匹配与聊天

- **FR-MAT-001**：喜欢、跳过、招呼和匹配必须幂等。
- **FR-MAT-002**：普通用户的陌生招呼存在每日额度；付费只能提高合理额度，不能无限骚扰。
- **FR-MAT-003**：持续聊天要求双方匹配或收件人明确接受招呼。
- **FR-CHAT-001**：同一会话消息拥有严格递增序号，用于排序、补拉和去重。
- **FR-CHAT-002**：发送消息必须携带客户端幂等键；重试不得产生重复消息或重复礼物扣款。
- **FR-CHAT-003**：拉黑、封禁、解除匹配和成年人状态失效后，发送权限立即失效。
- **FR-CHAT-004**：首版消息类型仅包含文本、官方表情、官方贴纸、系统通知和虚拟礼物。
- **FR-CHAT-005**：聊天页面始终提供举报、拉黑、静音和解除匹配入口。

### 5.5 安全治理

- **FR-SAFE-001**：公开资料和媒体先审后发；文本消息采用实时规则过滤和事后举报审核。
- **FR-SAFE-002**：举报分类至少覆盖色情、诈骗、骚扰、冒充、未成年人、线下安全威胁和其他违法内容。
- **FR-SAFE-003**：未成年人或疑似未成年人举报必须进入最高优先级并冻结相关发现和聊天能力。
- **FR-SAFE-004**：审核员只能查看完成任务所需的最小证据，查看行为写入审计日志。
- **FR-SAFE-005**：用户可以查看举报状态和申诉入口，但不能看到审核员身份或他人敏感信息。

### 5.6 会员、金币与礼物

- **FR-COM-001**：权益判断基于 entitlement 或数字 rank，不在业务逻辑中硬编码 `vip` 名称。
- **FR-COM-002**：已购买金币不得过期；赠送或运营补偿金币须以独立批次和清晰规则记录。
- **FR-COM-003**：余额是账本投影，任何人工调整、退款、冲正和冻结都必须新增账本分录。
- **FR-COM-004**：虚拟礼物是确定性商品，不包含随机奖励，不可兑现或转赠。
- **FR-COM-005**：会员和金币不能购买认证结果、审核优先放行或安全规则豁免。

### 5.7 通知与设置

- **FR-NOT-001**：推送按消息、匹配、访客、活动和交易分组授权。
- **FR-NOT-002**：敏感消息推送默认不展示正文，只显示“你有一条新消息”。
- **FR-NOT-003**：用户可以在 App 内关闭营销通知，不影响安全或交易通知。
- **FR-SET-001**：账号设置提供隐私、黑名单、设备、订单、数据导出、撤回同意和注销入口。

### 5.8 管理后台

- **FR-ADM-001**：后台增加资料审核、举报、申诉、身份核验结果、交易对账和迁移任务模块。
- **FR-ADM-002**：所有后台写操作写入不可由普通管理员删除的审计日志。
- **FR-ADM-003**：封禁、身份状态修改、金币人工调整和批量迁移为高风险操作，要求二次确认；达到配置阈值时要求双人复核。
- **FR-ADM-004**：审核任务按数据最小化显示，身份证号码、手机号和精确位置默认脱敏。

## 6. 信息架构

底部一级导航固定为四项：

1. 遇见：推荐、附近、活跃、筛选。
2. 动态：首版作为个人状态和运营内容入口，不开放公共无限信息流。
3. 消息：招呼、匹配、会话和系统通知。
4. 我的：资料、认证、会员、金币、安全与设置。

“安全中心”同时从“我的”和资料/会话的更多菜单进入，不藏在客服页面。

## 7. 业务规则

### 7.1 可发现条件

用户同时满足以下条件才可进入发现流：

- 账号有效且未封禁。
- 年满 18 周岁的核验状态有效。
- 已接受当前版本交友服务协议和隐私政策。
- 资料状态为 `approved`，至少有一张审核通过的主头像。
- 用户主动开启“允许被发现”。
- 不处于注销、身份复核或高危安全调查状态。

### 7.2 匹配状态机

```text
none → liked / greeted
liked + reciprocal_like → matched
greeted + accepted → matched
greeted → rejected / expired
matched → unmatched / blocked / suspended
```

任何状态都可能因安全处置进入 `suspended`；`blocked` 高于其他互动状态。

### 7.3 资料审核状态机

```text
draft → submitted → reviewing → approved
                         ├→ changes_required → submitted
                         └→ rejected → appeal_submitted → reviewing
approved → update_pending → approved
approved → suspended
```

## 8. 非功能需求

- **NFR-001**：公开 API 月度可用性目标 99.9%，实时聊天月度可用性目标 99.9%。
- **NFR-002**：正常网络下 API P95 小于 500ms；消息接受确认 P95 小于 800ms。
- **NFR-003**：消息断线重连后必须从最后确认序号补拉，不丢失已接受消息。
- **NFR-004**：所有管理写操作、身份状态和账本变动可审计。
- **NFR-005**：支持 375、390、430dp 主流手机宽度、系统字体放大和深色模式。
- **NFR-006**：所有关键流程支持无障碍标签、动态字体、屏幕阅读器和不依赖颜色的状态表达。
- **NFR-007**：用户数据导出、注销和删除按文档承诺时限可跟踪完成。

## 9. 成功指标与护栏指标

### 9.1 核心成功指标

- 激活完成率：开始创建资料后 24 小时内通过审核的用户占比。
- 有效匹配率：产生双向回复或持续对话的匹配占比。
- 首次有效对话时间：激活到收到非系统回复的中位时间。
- 7 日安全留存：未举报、未拉黑且仍活跃的用户占比。
- 举报闭环率：在承诺时限内处理并反馈的举报占比。

### 9.2 护栏指标

- 每千次招呼的拉黑率和举报率。
- 女性及其他高风险群体的骚扰率差异。
- 认证误判、资料审核申诉改判率。
- 推荐曝光集中度、重复曝光率和非个性化流可用性。
- 退款率、拒付率、负余额和账本不平衡数。
- 未成年人疑似账号发现与处置时长。

任何增长实验都不能以提高骚扰率、诱导付费或降低举报可见性为代价。

## 10. 产品级验收

- **AC-P-001**：给定未同意交友数据用途的现有账号，当迁移任务运行时，该账号不会创建可发现资料。
- **AC-P-002**：给定用户拒绝定位权限，当其完成城市选择后，仍可使用推荐和附近的城市级结果。
- **AC-P-003**：给定双方未匹配且收件人未接受招呼，发送者不能继续发送第二条消息。
- **AC-P-004**：给定任一方拉黑对方，双方立即无法互发消息或再次出现在彼此发现流。
- **AC-P-005**：给定购买回调重复到达，权益或金币只入账一次。
- **AC-P-006**：给定资料媒体没有交友用途授权，系统拒绝把该媒体关联到公开交友资料。
- **AC-P-007**：给定用户关闭个性化推荐，系统停止使用该用户画像进行排序并切换到可说明的非个性化规则。
- **AC-P-008**：给定用户提交注销，界面显示处理范围、预计时间、订阅处理方式和不可删除的法定留存类别。

## 11. 外部规则基线

- Apple 要求 UGC/社交产品提供内容过滤、举报、拉黑和公开联系方式，并对随机匿名聊天和物化真人内容保持严格限制：[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。
- Apple 要求支持账号创建的 App 提供 App 内账号删除入口：[Offering account deletion in your app](https://developer.apple.com/support/offering-account-deletion-in-your-app/)。
