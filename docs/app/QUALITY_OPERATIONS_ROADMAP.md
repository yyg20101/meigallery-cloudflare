版本：1.0

日期：2026-07-19
状态：`[目标设计 / 文档计划]`

## 1. 交付策略

本项目按“先安全闭环、再社交闭环、最后商业化”推进。每一阶段都是可验证、可回滚的完整湖，不把支付、审核、迁移或删除留成上线后的补丁。

当前阶段只完成文档。任何工程启动都需要将本路线图拆成带负责人、估算、依赖和验收证据的实施计划。

## 3. 分阶段路线图

### 阶段 0：决策与证据准备

目标：把不可逆或高风险决策在写代码前解决。

- 确定正式品牌、Bundle ID/package name、域名、运营主体和首发地区。
- 确定首发 iOS/Android 渠道及支付范围。
- 完成用户研究，验证“认证 + 同意后聊天 + 安全中心”的差异化价值。
- 形成数据流图、数据字典、保留期限和个人信息保护影响评估。
- 取得 Cloudflare 数据位置/跨境、身份核验、短信、推送和支付的书面评估。
- 高保真设计覆盖全部状态和无障碍。

退出门禁：开放决策 OQ-001 至 OQ-010 全部关闭；法务声明允许进入受控开发和测试。

### 阶段 1：共享平台地基

目标：App 不依赖 legacy schema，也不改变线上 Web 行为。

- 建立核心 D1、社交 D1、v2 API 骨架和版本化共享类型。
- 建立 account、legacy link、同意、角色、审计和 feature flag。
- 建立迁移批次、幂等、outbox、Queue/DLQ 和 Workflow 基础。
- 为现有用户生成影子映射并完成数量/语义对账。
- 建立 App 短 token/refresh token 与管理员 MFA 方案。

退出门禁：legacy 流量零回归；影子迁移可重复运行；越权和审计测试通过。

### 阶段 2：封闭 Alpha（M1）

目标：小规模受邀成年用户完成可信匹配和安全聊天闭环。

- 手机登录、旧账号绑定、成年人核验、条款/同意。
- 资料创建、媒体授权、先审后发和申诉。
- 推荐/附近/活跃、喜欢、招呼、匹配。
- Durable Objects 文本聊天、断线补拉、举报、拉黑、解除匹配。
- 后台审核、举报、封禁和审计。
- 数据导出、注销和删除 Workflow。

Alpha 限制：人工邀请、人工审核、无公开支付、无聊天图片、无语音视频、无开放注册。

退出门禁：零 P0 未解决安全缺陷；举报与拉黑演练通过；消息和注销恢复演练通过。

### 阶段 3：Beta 与商业化准备

目标：证明容量、审核和值班能够支撑扩大用户量。

- APNs/FCM、通知偏好和敏感正文保护。
- VIP/金币/礼物 sandbox、商店通知、恢复购买、退款和日对账。
- 风控限流、异常设备/订单、审核分级和 DLQ 运营。
- 可用性、容量、账本、推荐公平和骚扰护栏看板。
- App Store/Google Play/目标 Android 渠道预审材料。

退出门禁：账本零不平衡；sandbox 全场景通过；审核队列在目标 SLA 内；商店政策清单无阻断项。

### 阶段 4：受控公开发布（M2）

目标：在批准的地区和渠道按小流量发布。

- 分地区、客户端版本、账号批次灰度。
- 先开放注册/匹配，再按商店审核结果开放支付。
- 每个灰度阶梯观察安全、稳定性、退款和骚扰指标。
- 任一护栏越界自动停止扩大流量，可按功能回退。

退出门禁：连续观察窗口内 SLO 和安全护栏达标；商店、备案和隐私声明与真实行为一致。

### 阶段 5：Web 渐进迁移

目标：现有 MeiGallery Web 的共享能力切换到 v2，最终退役 legacy 核心表。

顺序：账号只读 → 权益双读 → 媒体服务 → 管理员角色/审计 → 账号写入 → legacy 只读归档。

图库展示、SEO、广告归因和现有联系转化仍属于 Web 业务域，不因共享账号而进入交友推荐。

## 4. 测试架构

### 4.1 测试金字塔

| 层级 | 范围 | 关键内容 |
|------|------|----------|
| 单元 | 纯业务规则 | rank/entitlement、匹配状态机、距离模糊、账本、保留策略、错误映射 |
| 组件 | 移动 UI 和状态 | 动态字体、屏幕阅读器、错误/空/离线、安全受限、深色模式 |
| 契约 | App/Web/API/Queue/WebSocket | OpenAPI/JSON Schema、事件 schema、向后兼容、错误码 |
| 集成 | D1/R2/DO/Queues/Workflows | 事务、幂等、DLQ、休眠恢复、删除和迁移 |
| E2E | 真实客户端 + dev/staging | 激活、资料审核、匹配、聊天、举报、购买、注销 |
| 安全 | SAST/DAST/授权/滥用 | IDOR、令牌、上传、限流、日志泄密、管理员越权 |
| 性能 | API/DO/Queue/客户端 | P95、并发连接、消息突发、冷启动、弱网、电量 |
| 恢复 | 备份、Queue、Workflow | D1/R2/DO 恢复、商店回调重放、迁移回滚 |

### 4.2 必测业务矩阵

#### 身份与迁移

- 旧账号不存在、重复邮箱、disabled、未验证邮箱和角色冲突。
- 同一旧账号并发绑定两个 App 账号。
- 用户不授权、部分授权、撤回授权和重新同意。
- 认证过期、供应商超时、回调重复和结果反转。

#### 推荐与安全

- 关闭个性化、拒绝定位、隐藏距离、暂停发现。
- 双向偏好、拉黑、封禁、未成年疑似和资料审核中。
- 连续测距不能稳定反推精确位置。
- 推荐不泄露内部安全分或不可见标签。

#### 消息

- 重复发送、乱序、离线 outbox、断线补拉和 DO 休眠恢复。
- 匹配建立/解除、拉黑竞态、会话关闭后在途消息。
- 内容拒绝、撤回、审核隐藏、已读序号回退。
- Queue 投影失败、推送失败和重复事件。

#### 商业化

- 购买成功/取消/待处理/退款/撤销/续订/过期。
- 商店回调重复、乱序、伪造、错误 bundle/SKU/账号。
- 礼物并发扣币、余额不足、事件重复和投影失败。
- 人工补偿、阈值双人复核、负余额和日对账。

#### 数据权利

- 导出数据范围、短期链接过期、越权下载。
- 注销期间登录/匹配/消息/推送/支付全部受控。
- 法定留存与业务删除隔离；备份最终清理。
- App 内和 Web 删除入口状态一致。

### 4.3 测试数据

- 默认使用完全合成的成人资料和媒体，不复制生产人物照片。
- 身份和商店使用官方 sandbox/签名 fixture。
- 迁移演练使用脱敏数据，仍按敏感数据权限处理。
- 测试覆盖不同性别、年龄段、地域、网络、设备和辅助功能。

## 5. 性能与容量基线

具体容量由业务预测和 Cloudflare 当前套餐核对。首轮压测至少覆盖：

- API：持续 100 RPS、短时 500 RPS 的代表性混合负载。
- Realtime：10,000 个测试 WebSocket 连接、每会话 2 个成员、消息突发与休眠恢复。
- Queue：推送/投影 consumer 延迟、重复和 DLQ。
- 迁移：10 万账号、权益和映射的批处理内存/时间/失败恢复。
- 客户端：中端 Android 与近三代 iPhone 的冷启动、内存、图片滚动和弱网。

这些数字是首轮验证目标，不是对 Cloudflare 产品限制或最终生产容量的陈述。实施时必须核对最新官方限制与账单模型。

## 6. SLO 与告警

| 指标 | 目标 | 告警条件示例 |
|------|------|--------------|
| API 可用性 | 月度 99.9% | 5 分钟窗口错误率超过阈值 |
| API P95 | < 500ms | 连续 10 分钟超过目标 |
| 消息接受确认 P95 | < 800ms | 连续 5 分钟超过目标 |
| 消息最终投影 | 99.9% 在 60 秒内 | Queue oldest age 超标 |
| 推送投递尝试 | 99% 在 2 分钟内 | consumer/DLQ 堆积 |
| 举报 P0 首次响应 | 目标 15 分钟 | 即时值班告警 |
| 账本平衡 | 100% | 任一不平衡立即 P0 |
| 迁移对账 | 100% 分类 | 出现未分类记录阻断切换 |

安全和账本告警不能只依赖月度 SLO，单个高危事件也可触发响应。

## 7. 可观测性看板

### 7.1 产品与安全

- 激活漏斗、资料审核通过/改判、匹配和有效对话。
- 招呼额度、拒绝、拉黑、举报和复犯。
- 未成年人疑似、诈骗和高危内容队列。
- 个性化关闭率和非个性化流使用情况。

### 7.2 技术

- Worker 请求、错误、延迟和限流。
- Durable Object 连接、消息、重连、序号缺口和存储失败。
- Queue 深度、最老消息、重试、DLQ 和 consumer 延迟。
- Workflow 状态、失败步骤和人工等待。
- D1 查询延迟、错误、容量和 Time Travel/导出状态。

### 7.3 商业化

- 商店验证成功率、回调延迟、订阅状态。
- 金币入账/消费/退款/冲正和账本平衡。
- 礼物投递延迟、重复抑制和负余额。
- 退款、拒付、恢复购买和人工调整。

所有看板使用聚合或去标识化维度，禁止把私聊正文、证件和精确位置写入分析事件。

## 8. 发布与回滚

### 8.1 发布层次

1. 内部员工与合成账号。
2. 受邀成年测试用户。
3. 单地区、无支付的小流量 Alpha。
4. sandbox 商业化 Beta。
5. 商店批准后的地区灰度。
6. 按安全和稳定性指标扩大流量。

### 8.2 功能开关

至少支持：注册、旧账号迁移、附近、招呼、聊天、推送、聊天图片、VIP、金币、礼物、个性化推荐和各地区可用性。

安全开关默认保守：聊天图片、语音、视频、支付和精确位置能力默认关闭。

### 8.3 回滚等级

- 客户端：停止发布、远程关闭高风险功能、要求升级。
- API：回滚 Worker 版本，维持兼容 schema。
- 数据：切换读权威、停止写入；财务/消息通过补偿而非覆盖回滚。
- 地区：暂停新注册或特定功能，不影响用户的数据权利和安全入口。

## 9. 运营准备

- 7×24 P0 事件联络，P1 至少覆盖公开服务时段。
- 审核员培训、规则版本、质量抽检、心理健康支持和权限复核。
- 客服脚本覆盖认证、封禁、举报、订阅、退款、负余额、注销和数据导出。
- 商店审核演示账号、完整功能说明、支付 SKU、隐私标签和删除入口。
- 用户公开社区规则、安全指南、联系方式、投诉和申诉政策。
- 每季度安全、隐私、供应商、权限和恢复演练。

## 10. 风险登记

| 风险 | 等级 | 缓解 |
|------|------|------|
| 现有图库人物被误当真人交友用户 | 极高 | 默认禁止；逐账号激活、主体授权和重新审核 |
| 中国大陆数据驻留/跨境不明确 | 极高 | 公开上线硬门禁；法律与 Cloudflare 书面确认 |
| 未成年人进入服务 | 极高 | 18+、年龄核验、疑似冻结、人工复核和举报优先级 |
| 诈骗、骚扰、性交易 | 极高 | 同意后聊天、额度、内容规则、举报拉黑、人工值班 |
| 账本/商店回调重复导致资金损失 | 极高 | 单事务、幂等、复式账本、服务端验证和日对账 |
| Durable Object 单会话热点 | 高 | 一会话一对象、消息大小限制、压力测试和降级 |
| 跨 D1 最终一致造成展示延迟 | 中 | 权威读回退、outbox、幂等投影和修复任务 |
| 商店认为产品同质化 | 高 | 强化认证透明、同意后聊天、安全中心和差异化证据 |
| 人工审核容量不足 | 高 | 先审范围控制、优先级、邀请制和扩量门禁 |
| 第三方身份/推送/支付供应商故障 | 高 | 适配器、超时降级、人工路径和退出方案 |

## 12. 阶段完成定义

每个工程阶段必须：

1. 更新项目状态和对应文档状态。
2. 完成 API、Web、移动端相关测试和构建。
3. 完成安全、隐私、无障碍和恢复证据。
4. 形成可回滚的本地提交；关键闭环再推远端并触发 CI。
5. 不把开放决策、失败迁移、账本差异或 P0 安全问题带入下一阶段。
