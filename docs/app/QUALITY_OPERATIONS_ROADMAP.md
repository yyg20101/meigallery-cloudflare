# 质量、运营与实施路线图

App 版本：1.0

日期：2026-07-20

状态：需求讨论中

## 1. 交付策略

按照“数据与信任地基 → 真人发现 → 私信与商业化 → 本人认领 → 跨平台和区域扩展”推进。每个阶段必须形成可验证、可回滚、可运营的闭环，不把授权、代运营披露、审核、账本或数据权利留作上线后的补丁。

## 2. 工作流

| 工作流 | 范围 | 横向依赖 |
|--------|------|----------|
| P 产品与设计 | PRD、流程、文案、线框、高保真、可访问性 | 所有阶段 |
| D 数据与迁移 | Person/Profile、授权、映射、投影和迁移 | M0–M4 |
| B 共享后端 | 账号、发现、互动、消息、商业和审核 | M0–M4 |
| C KMP 客户端 | Android/iOS，共享业务和 UI；Desktop 后续 | M1–M4 |
| A 管理后台 | 真人、代运营、商品、调币、认领和审计 | M0–M3 |
| S 信任与安全 | 认证、授权、举报、风控、隐私和事件响应 | 所有阶段 |
| O 运营与客服 | 内容供给、排班、SLA、商品和申诉 | M1–M4 |
| Q 质量与发布 | 测试、压测、可观测性、恢复和门禁 | 所有阶段 |

## 3. M0：数据与产品地基

### 3.1 目标

在不改变现有 Web 行为的前提下，冻结正确领域模型和共享契约，建立真实可导入的供给与商业底座。

### 3.2 交付

- 产品总纲、Feature PRD、UI 交互基础和决策清单。
- `Account`、`Person`、`PersonProfile`、`Gallery`、授权、认证、运营和认领模型。
- MeiGallery 数据盘点、stable ID、影子映射、导入和对账方案。
- 心享会员五级、entitlement、商品、订单、钱包和只追加账本模型。
- KMP/CMP 技术 Spike、版本矩阵、契约生成和平台适配边界。
- 后台 RBAC、审计、内容/财务职责分离。

### 3.3 退出条件

- 所有公开人物候选默认不可见，缺少授权证据不能发布。
- 普通账号不会生成真人资料。
- 数据模型、API schema、权限和迁移有评审结论。
- KMP Android/iOS 空壳、网络、序列化、存储和平台桥接技术验证通过（进入实现阶段后执行）。
- M1 必需开放问题关闭，风险和负责人明确。

## 4. M1：真人发现闭环

### 4.1 目标

让受控用户能够安全注册、发现已认证真人、查看媒体并进行单向互动，同时让管理员完成供给和审核闭环。

### 4.2 用户能力

- 注册、登录、设备和隐私设置。
- 推荐、地区、热门、最新、搜索和筛选。
- 真人详情、图库媒体、喜欢、关注、收藏和浏览历史。
- 通知、举报、拉黑、帮助、数据导出和注销。

### 4.3 后台与运营

- 真人上传、MeiGallery 导入、授权证据、认证、发布、暂停和归档。
- 标签、地区、推荐位、热度规则和公开投影。
- 举报队列、申诉、审计、值班和撤回演练。

### 4.4 退出条件

- Android/iOS 核心旅程 E2E 通过。
- 所有公开入口只返回 `verified + published`。
- 暂停资料和媒体凭证撤回满足目标时限。
- 个性化关闭、非个性化入口和数据清除有效。
- 无障碍、性能、崩溃、数据权利和安全门禁通过。

## 5. M2：私信与商业化

### 5.1 目标

上线五级心享会员、披露式管理员代运营私信，以及可对账的金币、礼物和装扮闭环。

### 5.2 用户能力

- 五级会员比较、购买、恢复、升级、到期和权益刷新。
- 会员直接创建私信、文本/表情/审核图片消息和会话控制。
- 金币充值、明细、固定礼物、头像框、主页皮肤和聊天皮肤。
- 交易、权益、消息和安全通知。

### 5.3 后台与运营

- 代运营队列、分配、平台身份回复、内部备注、响应和安全升级。
- 会员/entitlement、商品/资源、价格和上下架。
- 订单、退款、钱包、调币、双人复核、冲正和对账。
- 消息审核、举报、客服和交易争议流程。

### 5.4 退出条件

- 代运营披露通过法务、用户理解和 UI 一致性检查。
- 管理员无法发送 `person` 身份消息或伪造本人状态。
- 消息顺序、幂等、重连、补拉、拉黑和撤权压测通过。
- 商店凭证、订单、entitlement、账本和库存日对账无未解释差异。
- 调币阈值、双人复核、用户说明和审计通过演练。
- 客服排班和安全队列容量支持邀请规模。

## 6. M3：真人本人入驻

### 6.1 目标

让合格真人安全认领资料并接收新会话，同时保护代运营时期的消息和运营数据。

### 6.2 交付

- 认领申请、身份核验、授权复核、冲突和申诉。
- 账号绑定、资料字段权限、本人收件箱和运营模式切换。
- 新会话路由、历史交接同意、系统披露和撤回机制。
- 真人端安全、设备、通知和数据权利。

### 6.3 退出条件

- 冒领、重复认领、证据过期和争议演练通过。
- 新会话路由正确，历史会话默认隔离。
- 交接 consent、审批、审计和回滚验证通过。
- 真人本人消息与平台运营消息在 UI、API 和审计中清晰区分。

## 7. M4：桌面与区域扩展

### 7.1 目标

基于同一业务核心提供 Windows/macOS 客户端，并按真实业务扩展多语言、多地区、视频和实验能力。

### 7.2 交付

- Desktop 三栏布局、键盘、窗口、通知、安全存储、签名和更新。
- 多语言、地区目录、条款、支付/推送/身份适配和数据路由。
- 视频资料和经安全评审的新消息媒体。
- Web 按模块迁移到共享账号、权益、真人和内容核心。

### 7.3 退出条件

- Windows/macOS 目标平台构建、签名、更新和回滚验证通过。
- 核心功能与移动端契约一致，平台差异有专项测试。
- 新地区法律、数据、商店、客服和内容供给门禁关闭。

## 8. 测试策略

| 层级 | 范围 | 重点 |
|------|------|------|
| 单元 | 纯业务规则 | 状态机、rank/entitlement、推荐过滤、额度、账本和保留 |
| 契约 | Kotlin/TypeScript/API/Queue/实时事件 | schema、错误码、未知字段、破坏性变更 |
| 集成 | D1/R2/DO/Queue/Workflow/商店适配器 | 事务、幂等、乱序、重试、休眠和恢复 |
| 权限 | 用户和后台对象矩阵 | 越权 ID、角色、会话主体、财务和证据访问 |
| E2E | Android/iOS/管理后台 | 发现、互动、代运营、购买、调币、举报、注销 |
| 非功能 | 性能、容量、安全、无障碍、恢复 | 冷启动、列表、消息、账本、键盘、屏幕阅读器和灾备 |

## 9. 必测场景

### 9.1 真人与发现

- 普通账号永远不会进入真人列表。
- 未认证、未发布、暂停和归档资料在所有入口一致过滤。
- 授权撤回后媒体和分享链接停止可用。
- 推荐个性化关闭、规则切换和游标过期。

### 9.2 私信

- 无会员、会员到期、额度耗尽和客户端重试。
- 平台运营/本人运营身份、会话切换和系统消息。
- 多设备、断线、乱序、重复、DO 休眠和 HTTP 兜底。
- 拉黑、举报、账号冻结和资料暂停时的在途消息。
- 内部备注永远不进入用户 API。

### 9.3 商业与账本

- 商店回调重复/乱序、恢复购买、退款和撤销。
- 金币不足、并发赠礼、商品下架、资源撤回和装扮到期。
- 低风险调币、高风险复核、批量部分失败和冲正。
- 余额重建、订单/发放/分录/库存逐笔对账。

### 9.4 认领

- 冒领、同一真人重复申请、同一账号认领多个冲突资料。
- 认领批准、撤回、争议和运营模式回滚。
- 无 consent 的历史消息访问必须失败。

## 10. 质量目标

具体数值在容量与用户地区确认后冻结，但每项必须在实现前建立测量方式：

- App 冷启动、推荐首屏、详情和消息补拉延迟。
- API 成功率、D1/DO/Queue/Workflow 错误和积压。
- 消息发送成功、重复率、顺序错误和首次响应。
- 订单已付未发、重复发货、账本差异和调币异常。
- 崩溃率、ANR、客户端版本分布和强制升级比例。
- 无障碍关键路径完成率和严重问题数。

核心正确性目标（越权、冒充、重复扣费、账本不平、无授权发布）不因性能预算而放宽。

## 11. 可观测性

- Request/Trace ID 贯穿客户端、Worker、DO、Queue、Workflow 和适配器。
- Dashboard 分产品、消息、商业、安全、迁移和基础设施。
- 日志和分析禁止包含私信正文、证件、授权原件、完整支付凭证和访问令牌。
- 告警有严重级别、Owner、响应时限、Runbook 和升级渠道。
- 关键审计缺失、平台运营身份异常和账本差异属于高优先级事件。

## 12. 运营准备

### 内容运营

- 首批真人名单、授权完整率、资料质量、更新频率和争议渠道。
- 认证/发布、暂停和权利撤回排班与容量。

### 代运营

- 服务时段、会话分配、响应目标、话术边界、禁止冒充培训和抽检。
- 高危内容升级、用户投诉和真人认领衔接。

### 商业与客服

- 五级权益说明、价格、续订、退款、订单异常和调币授权。
- 金币/礼物/装扮争议、版权撤回和补偿流程。

### 安全与隐私

- 举报、申诉、高危事件、数据请求、账号注销和安全事件值班。

## 13. 发布门禁

每个候选版本至少完成：

- 需求与设计验收、开放决策检查和文案审核。
- API/数据 migration 兼容性、备份、回滚和数据质量验证。
- 自动化测试、目标设备 E2E、安全、隐私和无障碍测试。
- 商店、地区、数据、内容、客服、支付和财务检查（按版本范围）。
- 监控、告警、Runbook、值班、feature flag 和回滚演练。
- 发布说明和客服知识库与实际功能一致。

## 14. 需求文档完成定义

进入实现排期前，每个 Feature PRD 必须包含：用户、场景、入口、主流程、异常、状态、权限、安全、埋点、验收和不做项。价格、额度、供应商和地区等参数必须在对应最晚关闭点前进入决策登记；不得用“以后再说”替代规则。

需求讨论期间所有文档保持 App 版本 1.0，直接更新当前结论。App 发布新版本时再统一更新文档版本。

## 15. 项目级验收

- **OPS-AC-001**：M0–M4 每阶段均有范围、退出条件、Owner 和证据。
- **OPS-AC-002**：实现任务能追溯到 PRD 要求、设计状态、API/数据契约和测试。
- **OPS-AC-003**：没有授权、代运营、安全、财务或数据权利 Owner 的阶段不能公开发布。
- **OPS-AC-004**：发布失败可通过 feature flag、路由切换或 forward-fix 安全停止扩散。
- **OPS-AC-005**：核心正确性事件有告警、Runbook、值班和复盘。
- **OPS-AC-006**：文档、商店文案、客服话术和真实实现不存在接收主体或权益差异。
