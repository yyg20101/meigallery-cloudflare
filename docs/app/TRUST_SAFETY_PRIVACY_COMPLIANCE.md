# 信任、安全、隐私与合规方案

App 版本：1.0

日期：2026-07-20

状态：需求讨论中

## 1. 文档性质

本文是产品与工程安全基线，不构成法律意见。面向具体地区发布前，运营主体、法律顾问、隐私、安全和商店运营负责人必须基于真实业务、数据流和地区规则完成复核。

## 2. 核心风险

平台处理真人身份与授权、公开媒体、观看者偏好、私信、消费和管理员操作。最高风险不是双方配对，而是：

- 未获授权的真人或媒体被用于独立 App、推荐、商业化或互动。
- 观看者误以为管理员回复来自真人本人。
- 认证、热度、付费或运营推荐相互混淆。
- 会员私信被用于骚扰、诈骗、违法内容或批量攻击。
- 管理员越权访问会话、静默加扣币或修改审计。
- 真人认领后未经同意获得历史代运营消息。
- 账号、消息、身份、位置和支付数据被过量收集或泄露。

## 3. 不可突破的原则

- 只有来源、用途授权、认证和发布状态均满足要求的真人资料才能公开。
- 管理员代运营必须在私信入口、会话列表和会话内持续披露。
- 平台运营不得伪造真人在线、输入、已读、回复、感谢或线下意愿。
- 会员和金币不能绕过对象权限、频控、举报、拉黑、审核或地区/资格限制。
- 后台遵循最小权限、职责分离、强认证和全量审计。
- 金币与礼物不可提现，不形成真人收益或关系结果承诺。
- 数据按目的最少收集、最短保留、分级访问并支持数据权利。

## 4. 真人来源、授权与认证

### 4.1 来源

允许来源：管理员直接上传、MeiGallery 合规导入、外部权利主体提交后管理员审核。任何来源都不能绕过证据要求。

每个真人至少记录：

- 主体稳定 ID 和资料版本。
- 提交来源、提交人、时间和业务用途。
- 身份/真人核验的范围、结果、时间和有效期。
- 肖像、媒体、独立 App 展示、推荐、商业化和互动用途授权。
- 运营模式、管理员分配、争议和撤回状态。
- 认证、发布、暂停、归档的审批和审计。

### 4.2 认证标识

认证标识只声明实际完成的核验，例如“资料与授权已由平台审核”，不得宣称绝对安全、必定本人运营或不存在欺诈。

认证、会员和运营标识分别使用：

- 真人认证：盾牌勾。
- 心享会员：星/光环，仅观看者账号可见场景。
- 平台代运营：平台客服/运营标识和文字。
- 热门/推荐：趋势或运营标识，不使用认证图形。

证据过期、重大资料变化、授权争议或冒名投诉时，资料进入复核并暂停必要展示。

## 5. 公开内容治理

- 只允许合法的写真、时尚、生活和艺术类图片/视频，不允许露骨、违法、侵权或未经同意内容。
- 发布前校验文件类型、恶意内容、敏感元数据、内容规则和授权范围。
- 公开字段采用资料白名单；法定姓名、证件、联系方式、精确住址和实时位置默认不公开。
- 管理员编辑和发布是不同能力；高风险类别可要求双人复核。
- 资料暂停后从推荐、搜索、分享和新私信中撤回，受保护媒体停止签发新凭证。
- 权利人可通过公开渠道请求更正、暂停、下架或提出争议。

## 6. 代运营私信透明度

### 6.1 用户侧披露

未认领真人的私信必须至少在三个位置披露：

1. 真人详情的私信按钮附近。
2. 会话创建确认/首次会话说明。
3. 会话列表标签和会话页顶部。

推荐文案：“消息由平台运营接收和回复”。禁止文案：“她在等你”“她已读”“本人客服代聊”等会造成接收主体误解的表达。

### 6.2 消息身份

- 观看者消息：`viewer`。
- 管理员回复：`platform_operator`，用户侧显示平台运营身份。
- 已认领真人回复：`person`，仅允许绑定且有权限的真人账号产生。
- 状态说明：`system`。

管理员客户端不能自行指定 `person` sender type。实际管理员 ID 进入受限审计，不向用户公开个人敏感信息。

### 6.3 会话操作

- 内部备注与用户消息隔离，用户 API 永不返回内部备注。
- 管理员只有在被分配或有审核权限时查看会话。
- 批量导出默认关闭；必要导出需审批、水印和审计。
- 会话访问、搜索、回复、转派、关闭和证据查看均记录审计。
- 会员获得私信权益不保证平台或真人回复，也不提供隐性优先于安全举报的待遇。

## 7. 消息内容安全

### 7.1 发送前与发送后

- 账号、设备、目标、会员、额度、拉黑、会话和风险状态校验。
- 文本规则、链接/联系方式风险、重复内容和频率检测。
- 图片开放时执行类型、恶意文件、版权/违规内容和人工升级流程。
- 高风险内容可拒绝、延迟审核、限制账号或触发紧急升级。
- 不在通用日志或分析事件记录消息正文。

### 7.2 用户控制

每个真人详情和会话提供举报、拉黑和帮助入口；会话另提供静音、关闭和消息级举报。

拉黑后：

- 目标不再进入推荐。
- 禁止新会话和新消息。
- 已有会话转为只读或关闭。
- 解除拉黑不自动重新打开会话。

### 7.3 举报状态

```text
submitted → triaged → investigating → actioned / no_violation
                                      → appealed → upheld / changed
```

举报人只看到必要状态和结果，不获得内部规则、被举报人隐私或执法细节。

## 8. 未成年人和资格

具体访问与私信年龄门槛在 [开放问题](./DECISIONS_AND_OPEN_QUESTIONS.md) 中关闭。无论最终门槛如何：

- 公开真人资料必须满足适用年龄、授权和内容要求。
- 资格核验只收集必要结果，优先由合规供应商处理原始证件。
- 出现疑似未成年人、冒名、胁迫或性剥削信号时立即暂停相关资料/账号和互动，进入专业处置流程。
- 不允许会员或管理员指令跳过资格和高危处置。

## 9. 推荐与位置隐私

- 地区按城市或配置的模糊区域展示，不建立持续精确位置轨迹。
- 推荐可使用明确披露的地区、标签、行为和热度信号。
- 用户可选择非个性化排序、关闭个性化并清除相关行为记录。
- 推荐理由使用可理解枚举，运营置顶显式标识。
- 不根据消费金额提高真人认证可信度或隐性降低举报处理。
- 不公开观看者敏感偏好、消费或互动排行榜。

## 10. 商业化安全

- 购买前展示价格、期限、续订、明确权益、额度、接收主体和退款入口。
- 不使用虚假倒计时、隐藏续订、默认勾选或难以取消的设计。
- 金币不可提现、转账、兑换法币或用于随机博彩。
- 礼物不形成真人收入，不宣称真人本人已收取或感谢。
- 管理员调币使用标准原因、用户说明、追加账本和高风险双人复核。
- 订单、账本和调币异常进入独立告警与对账，不使用手工改余额修复。

## 11. 真人认领与消息交接

认领至少包含身份核验、权利/授权复核、账号安全、管理员批准和绑定生效。

- 认领成功默认只改变新会话路由。
- 真人账号默认不能查看认领前历史私信或内部备注。
- 历史交接要求观看者明确同意、真人权利确认和管理员批准。
- 交接前展示范围、接收主体和不可逆影响；交接后生成系统消息与审计。
- 认领撤回、争议或账号受限时可以暂停新私信或切回平台运营。

## 12. 管理后台安全

### 12.1 职责分离

内容编辑、认证、发布、代运营、审核、客服、商业运营、财务、财务复核和审计只读使用独立角色。

### 12.2 高风险操作

以下操作需要强认证、新鲜会话、原因和审计；按阈值增加双人复核：

- 发布/撤回真人资料和认证。
- 查看完整授权或身份材料。
- 查看/导出私信证据。
- 大额或批量加币、扣币、退款和冲正。
- 真人认领批准和历史会话交接。
- 更改安全规则、会员价格或核心 entitlement。

### 12.3 审计

审计记录操作者、角色、目标、动作、原因、请求 ID、前后状态、审批链和时间。禁止管理员编辑/删除审计；敏感正文以受控证据引用替代。

## 13. 数据分类和访问

| 级别 | 示例 | 控制 |
|------|------|------|
| 公开 | 已发布展示名、模糊地区、标签、审核媒体 | 公共投影、版本和撤回 |
| 内部 | 运营分配、工单、普通审计 | RBAC、最小权限 |
| 敏感 | 账号标识、偏好、私信、订单、设备 | 加密传输、对象权限、受限日志 |
| 高敏感 | 身份材料、授权证据、支付凭证引用、高危证据 | 分存储、强认证、审批访问、严格保留 |

Secrets 仅使用 Cloudflare Secret/经批准的密钥系统，不进入仓库、日志或客户端。

## 14. 数据权利与保留

- 用户可访问隐私说明、关闭个性化、清除历史、导出数据和申请注销。
- 真人/权利人可申请访问、纠正、限制展示、撤回授权和处理争议。
- 删除 Workflow 立即撤销登录和新处理，再按数据类别执行删除、匿名化或法定隔离保留。
- 账务、安全和法律证据有独立期限与访问范围，不用“永久保留”作为默认值。
- 日志、备份、导出和第三方适配器都纳入删除和保留清单。

## 15. 第三方与供应链

- 商店、推送、短信、身份核验和内容审核供应商在接入前完成数据流、权限、DPA、地区和删除能力评估。
- SDK 只启用必要功能，禁用无关广告标识、通讯录或位置采集。
- 依赖版本锁定、漏洞扫描、许可证审查和来源校验进入 CI。
- 第三方故障不得使认证、消息身份或支付状态被乐观伪造。

## 16. 事件响应

建立安全事件等级、值班、证据保全、隔离、用户/监管通知、修复和复盘流程。重点演练：

- 未授权真人/媒体公开。
- 管理员冒充或会话越权访问。
- 支付凭证重放、账本差异和恶意调币。
- 身份/授权证据或私信泄漏。
- 认领冲突和历史消息误交接。
- 大规模爬取、骚扰和违规图片传播。

## 17. 上线门禁

- 真人来源、认证、授权、暂停和争议 Workflow 完成演练。
- 代运营披露通过产品、法务和用户理解测试。
- 举报、拉黑、审核、申诉和值班具备真实人员和 SLA。
- 对象权限、管理员 RBAC、审计和高风险复核通过安全测试。
- App 1.0 会员手动发放、金币调币、账本和对账在测试环境通过；商店购买与退款在未来在线商业化启用前完成 sandbox 验证。
- 隐私政策、条款、商品说明、数据权利和客服渠道与真实实现一致。
- App 1.0 目标地区的数据位置、跨境、备案、年龄和目标商店结论关闭；支付结论在未来在线商业化启用前关闭。

## 18. 验收标准

- **SAFE-AC-001**：没有有效用途授权和发布审批的资料不能公开。
- **SAFE-AC-002**：平台管理员无法通过客户端或 API 伪造真人本人消息身份。
- **SAFE-AC-003**：代运营接收主体在核心链路持续可见且文案一致。
- **SAFE-AC-004**：拉黑后目标立即停止推荐、建会话和消息发送。
- **SAFE-AC-005**：后台越权查看私信、证据或财务数据被拒绝并告警。
- **SAFE-AC-006**：会员和消费不会改变认证、审核或安全限制。
- **SAFE-AC-007**：认领后没有同意记录的历史会话对真人账号不可见。
- **SAFE-AC-008**：数据导出和注销不会泄露其他主体数据或内部备注。
