# 信任、安全、隐私与合规方案

版本：1.1

日期：2026-07-20
状态：`[目标设计 / 上线门禁]`

## 1. 文档性质

本文件是产品和工程基线，不构成法律意见。面向目标地区公开发布前，必须由具有对应司法辖区经验的法律顾问、隐私负责人和商店运营负责人复核。

交友产品同时处理身份、位置、社交关系、通信内容、消费记录和用户生成内容。安全治理不是后台补充功能，而是注册、发现、匹配、聊天和商业化的共同前置条件。

## 2. 安全产品边界

- 仅允许年满 18 周岁的用户进入交友功能。
- 非匿名：账号需完成手机号验证，公开资料使用昵称但平台能够依法核验账号主体。
- 禁止随机陌生人无限聊天；持续聊天要求双方匹配或收件人明确接受招呼。
- 禁止色情、裸露、性交易、陪侍、诈骗、冒充、仇恨、骚扰、威胁和未成年人相关不当内容。
- 不做颜值评分、真人排行榜、偷拍交易、位置追踪或“谁离我最近”的精确排序。
- 不允许 VIP、金币或运营人工指令绕过安全规则。

## 3. 年龄与身份认证

### 3.1 认证分层

| 状态 | 证明范围 | 可公开文案 | 不代表 |
|------|----------|------------|--------|
| `phone_verified` | 控制已验证手机号 | “手机已验证” | 真实姓名、成年人或真人照片 |
| `age_verified` | 已通过合规流程确认成年 | “年龄已核验” | 公开生日、身份真实性的全部维度 |
| `identity_verified` | 身份信息与账号主体通过核验 | “身份已核验” | 每张照片均为本人、线下行为可信 |
| `liveness_verified` | 在指定时间完成人脸活体/自拍比对 | “真人状态已核验” | 永久保证、无风险或官方背书 |

认证徽章可点击查看核验范围、完成时间和有效期。认证服务失效、证据过期或用户资料重大变化时，相关徽章必须降级或进入复核。

### 3.2 最小化处理

- 首选由合规身份核验服务处理证件和生物识别，平台只保存状态、时间、供应商引用和必要审计证据。
- 平台不得在普通日志、分析系统或客服页面存储完整证件、人脸模板或手持证件照。
- 使用生物识别前取得单独同意，说明必要性、处理方式、保存期限和拒绝后的替代路径。
- 未完成供应商、合同、数据位置和影响评估前，不启用生产身份/活体核验，也不展示对应徽章。

### 3.3 疑似未成年人

- 用户自述、照片、举报或风控信号表明可能未成年时，立即暂停发现、匹配、聊天和付费。
- 进入最高优先级人工复核，不向举报者披露身份材料。
- 确认未成年后终止交友服务，并按法律和安全需要处理数据、退款和证据。
- 不通过简单修改出生日期解除限制。

## 4. 用户生成内容治理

### 4.1 内容范围

UGC 包括资料文字、头像/照片、聊天文本、表情、举报说明以及后续可能开放的图片、语音和视频。

### 4.2 发布策略

| 内容 | M1 策略 | 公开前门禁 |
|------|---------|------------|
| 资料文字 | 规则过滤 + 人工先审后发 | 词库、风险规则、审核 SLA 和申诉 |
| 资料图片 | 人工先审后发，自动基础文件校验 | 权利证明、未成年人/裸露/证件规则、哈希与人工复核 |
| 聊天文本 | 实时高危规则 + 举报后审核 | 拦截说明、误判申诉、骚扰频率限制 |
| 官方表情/贴纸 | 运营审核后发布 | 版权和内容清单 |
| 聊天图片 | M1 关闭 | 自动过滤、举报证据、人工审核与容量验证全部达标 |
| 语音/视频 | M3 评估 | 转码、审核、未成年人和隐私方案单独评审 |

### 4.3 规则类别

- 未成年人性剥削和任何儿童性虐待材料：零容忍，立即隔离并依法处置。
- 色情、裸露、性交易或外部成人服务导流。
- 诈骗、投资/博彩、借贷、虚假身份、导流收费。
- 骚扰、仇恨、侮辱、威胁、跟踪、泄露隐私。
- 非自有照片、冒充名人、盗图或未经同意的第三方信息。
- 毒品、武器、违法交易和其他适用法律禁止内容。

## 5. 举报、拉黑与申诉

### 5.1 拉黑

- 拉黑无需先举报，立即生效。
- 拉黑后双方互相不可发现、不可发消息、不可查看访客记录。
- 已有会话进入只读或从普通列表隐藏，举报所需证据保留在受控区域。
- 解除拉黑不自动恢复匹配或会话。

### 5.2 举报

举报入口同时存在于资料页和聊天页，步骤：

1. 选择举报对象与类别。
2. 可选择最近消息或媒体作为证据。
3. 对即时人身危险、未成年人和诈骗提供高优先级入口。
4. 提交后给出案件编号、预计处理时间和安全建议。

举报者可以拉黑后继续完成举报，不能因拉黑导致证据丢失。

### 5.3 服务目标

| 优先级 | 示例 | 首次响应目标 | 处置目标 |
|--------|------|--------------|----------|
| P0 | 疑似未成年人、具体人身威胁、儿童性虐待材料 | 15 分钟 | 立即限制账号并升级专门流程 |
| P1 | 诈骗、性交易、严重骚扰、身份冒充 | 2 小时 | 24 小时内完成初步决定 |
| P2 | 普通骚扰、不当资料、版权投诉 | 24 小时 | 72 小时内完成初步决定 |
| P3 | 一般体验、标签和非安全投诉 | 2 个工作日 | 5 个工作日内完成 |

以上是内部目标，不向用户承诺无法保证的绝对时限；运营排班必须与目标一致。

### 5.4 审核决定

可采取：内容隐藏、资料退回、招呼限流、聊天冻结、发现暂停、临时封禁、永久封禁、身份复核和无违规结案。

决定必须包含规则代码、证据引用、操作者、时间、有效期和申诉路径。自动规则不能直接作出永久封禁，法律要求或明确高危证据除外且仍需人工复核。

## 6. 反骚扰与线下安全

- 陌生招呼每日限额，且同一目标只能有一个待处理招呼。
- 连续被拒绝、被拉黑或被举报时动态降低额度并触发审核。
- 禁止在资料中公开手机号、二维码、精确地址和外部联系方式；必要时提示遮挡。
- 首次讨论线下见面时提示选择公共场所、告知亲友、不要转账、确认返程安排。
- 提供“暂停被发现”和“仅已喜欢的人可招呼”等控制。
- 不向任何用户出售精确距离、最后在线时间或拉黑绕过能力。

## 7. 隐私设计

### 7.1 数据分类

| 级别 | 示例 | 处理规则 |
|------|------|----------|
| 公开资料 | 昵称、简介、主动公开标签 | 仅审核通过且用户开启发现时展示 |
| 受限资料 | 匹配偏好、访客记录、聊天关系 | 仅授权用户和业务服务访问 |
| 敏感个人信息 | 身份、精确位置、行踪、通信内容、支付与生物识别 | 单独同意、最小化、加密、严格审计 |
| 安全证据 | 举报消息快照、封禁原因、设备风险 | 目的限制、访问审计、独立保留策略 |
| 运营数据 | 聚合事件、性能、错误 | 去标识化；不得复制私聊正文或证件信息 |

### 7.2 同意矩阵

| 目的 | 是否必要 | 拒绝影响 |
|------|----------|----------|
| 提供账号和交友服务 | 必要 | 无法激活交友资料 |
| 成年人/身份核验 | 必要，具体方式需评估 | 无法进入发现和聊天 |
| 模糊位置附近推荐 | 可选 | 使用手动城市和非位置结果 |
| 个性化推荐 | 可选 | 使用非个性化排序 |
| 推送通知 | 可选 | 使用 App 内消息中心 |
| 营销与活动 | 可选 | 不影响核心服务 |
| 迁移旧账号字段 | 逐字段选择 | 未选择字段不迁移 |

任何可选同意不得与必要条款捆绑，不得默认勾选。用户撤回后停止对应处理并更新投影/缓存。

### 7.3 位置

- 原始坐标只用于当前附近计算并按最短期限保存；不建立持续轨迹。
- 公开结果使用城市和距离段，并加入稳定性保护，避免通过连续查询三角定位。
- 用户可隐藏距离、暂停发现或仅使用手动城市。
- 后台普通审核员看不到精确坐标。

### 7.4 推荐与自动化决策

- 用户可以关闭个性化推荐。
- 提供非个性化排序和主要推荐因素说明。
- 不使用私聊正文、身份材料或未授权的旧站行为训练推荐模型。
- 不以性别、民族、宗教、健康等敏感属性作不透明差别待遇。
- 对重大安全或账号决定提供人工申诉，不只依赖自动判断。

## 8. 数据主体权利

App 与 Web 必须提供：

- 查阅和复制个人信息。
- 更正和补充资料。
- 撤回可选同意。
- 关闭个性化推荐。
- 删除单项媒体和 UGC。
- 导出可携带数据。
- 注销账号并删除关联数据。
- 对审核和自动决定提出申诉。

Google Play 要求账号创建产品同时提供 App 内和 Web 删除入口；Apple 要求 App 内可发起删除，不能只提供停用账号。

## 9. 数据保留原则

具体期限由法务和业务 owner 在上线前审批，并进入配置与数据字典。当前强制原则：

- 验证码和 Turnstile token 只保留完成验证所需的最短时间。
- 精确位置不用于历史轨迹，达到实时计算目的后删除或降精度。
- 未通过的资料草稿和媒体有明确清理窗口。
- 账号注销后，公开资料和非必要 UGC及时删除或匿名化。
- 账务、退款、争议与重大安全证据只在适用法律和明确目的允许的期限内保留。
- 备份和缓存有同步过期机制，不能成为永久数据副本。

## 10. 安全控制

### 10.1 客户端

- access/refresh token 使用 Keychain/Keystore/OS credential store，禁止普通明文文件、偏好设置或日志存储。
- 截图、剪贴板和通知正文按敏感页面/消息策略限制。
- 越狱/root 仅作为风险信号，不作为唯一封禁依据。
- 桌面调试器、篡改安装包、不可信更新源和受损系统环境只作为分层风险信号；高风险时限制敏感操作并提供申诉/恢复路径。
- Windows/macOS 安装包、更新清单和增量包必须签名并验证来源；签名失败时禁止安装或更新。
- 第三方 SDK 有清单、目的、数据字段和开关；未声明 SDK 不得进入构建。

### 10.2 服务端

- 服务端对象授权、RBAC、最小权限 secret、WAF 和强限流。
- 敏感字段应用层加密，密钥轮换并与业务数据分离。
- 所有身份、举报证据、消息审查和账本访问写审计日志。
- 依赖和镜像进行供应链检查；生产部署使用可追溯构建产物。
- 备份恢复、密钥泄露、账号接管和内容安全事件有演练手册。

## 11. 商店规则门禁

### 11.1 Apple App Store

- UGC 产品必须提供过滤、举报、拉黑和公开联系方式。
- 随机/匿名聊天、色情用途或物化真人的服务可能被拒绝或下架。
- 数字会员、金币和礼物使用 In-App Purchase；购买金币不得过期。
- 支持账号创建时必须提供 App 内账号删除。
- 交友品类必须证明有明显差异和持续价值，不能只是同质模板。

依据：[App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) 与 [Account deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app/)。

### 11.2 Google Play

- UGC 产品需要用户条款、持续审核、举报和拉黑。
- 交友功能需要合理有效地限制未成年人访问。
- 数字内容、交友订阅和虚拟币通常需要 Google Play Billing；虚拟币只在购买它的 App 内使用。
- 账号创建产品同时提供 App 内和 Web 删除入口，并完成 Data safety 声明。

依据：[UGC policy](https://support.google.com/googleplay/android-developer/answer/9876937)、[Dating restrictions](https://support.google.com/googleplay/android-developer/answer/16838200)、[Payments](https://support.google.com/googleplay/android-developer/answer/9858738) 与 [Account deletion](https://support.google.com/googleplay/android-developer/answer/13327111)。

## 12. 中国大陆上线门禁

### 12.1 必备事项

- 完成 APP 备案；经营性互联网信息服务的许可适用性由法律顾问确认。
- 对信息发布和即时通讯用户落实适用的真实身份认证。
- 个人信息处理规则、敏感个人信息单独同意和个人信息保护影响评估完成。
- 推荐算法的备案、显著标识、关闭入口和用户选择义务完成适用性评估。
- 未成年人网络保护、网络欺凌、消费和陌生人信息防护义务完成评估。
- 跨境传输和数据驻留方案获得书面结论。
- 建立内容审核、违法信息处置、投诉举报、应急响应和主管部门联络流程。

### 12.2 官方依据

- 工信部已开展移动互联网应用程序备案工作：[APP 备案通知解读](https://www.miit.gov.cn/zwgk/zcjd/art/2023/art_39b4f1acc36745b98478e0ec3e07128d.html)。
- 即时通讯和信息发布服务涉及真实身份认证：[移动互联网应用程序信息服务管理规定](https://www.cac.gov.cn/2022-06/14/c_1656821626455324.htm)。
- 位置、通信、金融、身份和生物识别等数据需按个人信息/敏感个人信息规则处理：[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。
- 自动化决策需要保证透明、公平、公正；信息推送和商业营销应同时提供非个性化选项或便捷拒绝方式：[中华人民共和国个人信息保护法第二十四条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。
- 未成年人网络保护条例自 2024 年施行，网络社交服务承担相应保护义务：[未成年人网络保护条例](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)。

## 13. 事件响应

| 事件 | 立即动作 | 后续动作 |
|------|----------|----------|
| 账号接管 | 撤销 session、冻结高风险操作、通知用户 | 设备/登录审计、恢复流程、根因修复 |
| 身份数据泄露 | 隔离访问、停止相关流程、保全证据 | 风险评估、依法通知、密钥/供应商处置 |
| 儿童安全事件 | 隔离内容和账号、最高优先级人工处理 | 按适用法律报告、限制扩散、专门复盘 |
| 大规模骚扰/诈骗 | 限流、冻结相关网络、提高审核级别 | 规则更新、受害者支持、跨账号关联调查 |
| 账本异常 | 暂停相关 SKU/支付入口、不覆盖历史 | 对账、冲正、商店沟通和用户通知 |
| 消息泄露 | 撤销访问、审计查询、停止日志扩散 | 影响范围、通知、权限与保留策略修复 |

## 14. 上线检查清单

- [ ] 18+ 门槛和有效年龄核验经过攻击测试。
- [ ] 认证徽章文案与证据一一对应。
- [ ] 拉黑即时生效，举报和证据保留端到端通过。
- [ ] UGC 条款、过滤、人工审核、申诉和公开联系方式可用。
- [ ] 精确位置不出现在公开 API、日志或后台普通视图。
- [ ] App 内与 Web 的账号删除入口均通过演练。
- [ ] 商店隐私标签/Data safety 与真实 SDK 和数据流一致。
- [ ] APP 备案、许可、算法、跨境和数据驻留结论已归档。
- [ ] 供应商 DPA、安全评估、密钥和退出方案完成。
- [ ] 应急联系人、值班、证据保全和外部报告流程完成演练。
