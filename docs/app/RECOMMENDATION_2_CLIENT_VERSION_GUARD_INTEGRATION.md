# Recommendation-2 客户端版本门禁与安全回退开发基线

日期：2026-08-20

状态：源码开发完成；配置、migration 执行、构建、专项测试与环境验证统一后置

## 1. 结论

Recommendation-2 补齐 Recommendation-1 已保存但此前未执行的 `minimumClientVersion` 运行语义。KMP 已在所有 App API 请求中发送 `X-Client-Version`，Cloudflare 现在会用同一套两段/三段数字版本比较规则完成策略门禁、规则选择、个性化 capability 和灰度回退校验。

后续 Recommendation-3 已在不改变本版本语义的前提下，把 `targetRegionCodes` 同步接入候选选择与回退覆盖校验；组合行为见 [Recommendation-3 地区作用域选择与安全回退开发基线](./RECOMMENDATION_3_REGION_SCOPE_AND_FALLBACK_INTEGRATION.md)。

本增量不新增响应字段、不提升 App API v2 累计契约版本、不增加 D1 表或真实业务数据，也不改变任何页面结构。Figma 仍为 99 个 Page ID / 408 个正式状态，Mobile 50/208、Admin 49/200。

## 2. 已修复的缺口

Recommendation-1 已在策略和规则中保存最低客户端版本，Nuxt 工作台也允许编辑该值，但此前：

- bootstrap 不使用 `X-Client-Version` 计算推荐 capability；
- 推荐规则选择不检查策略或规则最低版本；
- 个性化 capability 可能在当前客户端没有可执行个性化规则时仍显示为可用；
- 灰度回退版本可能要求比目标版本更高的客户端；
- 后台允许保存无法进行大小比较的任意版本字符串。

因此，字段存在并不等于 ROP-FR-014 所要求的客户端版本灰度已经执行。本增量把该声明收敛为真实服务端行为。

## 3. 服务端运行规则

### 3.1 请求头与格式

推荐流和本人推荐偏好接口要求：

```text
X-Client-Version: 1.0 | 1.25.0
```

只接受每段 1–5 位数字的两段或三段版本。缺失或非法时返回 `APP_CLIENT_VERSION_INVALID`，不会猜测客户端版本；低于策略最低版本时返回 `RECOMMENDATION_CLIENT_VERSION_UNSUPPORTED`。

bootstrap 继续保持公开兼容：请求头缺失或非法时，只把版本化推荐 capability 安全关闭，其他独立能力不受影响。KMP 当前公共请求构造器已经固定发送该请求头，因此不需要客户端 DTO 或 UI 改动。

### 3.2 策略与规则选择

执行顺序为：

1. 验证推荐总开关、生产门禁和运营安全控制；
2. 验证策略 `minimumClientVersion`；
3. 在当前已到生效时间的 `scheduled` 与 `active` 规则中，选择当前客户端可执行的最高优先版本；
4. 新排期要求更高版本时，旧客户端继续使用仍有效的 active 版本；
5. 当前 active 版本要求更高版本时，只允许使用其明确登记、已生效过、未过期且通过生产门禁的回退版本；
6. 找不到兼容规则时 capability 关闭，直接调用返回规则未就绪，不会放宽公开资格或执行不兼容配置。

个性化 capability 现在还要求存在当前客户端实际可执行的个性化规则，不能只凭策略开关宣称可用。

若未来 OQ-020 关闭并启用最小化推荐证据，客户端版本只进入会话 `contextHash` 的输入，不新增明文版本画像或账号字段；历史争议仍以实际 `ruleVersionId` 为主要复现依据。

### 3.3 灰度回退

会话分桶命中回退版本时，服务端再次检查回退版本的最低客户端版本。后台启用规则时同时要求：

- 小于 100% 的灰度继续必须登记完整回退版本；
- 规则最低版本高于策略基线时，即使目标灰度为 100%，也必须登记兼容回退版本；
- 回退版本最低版本不得高于目标规则最低版本；
- 回退版本仍需满足模式、taxonomy、历史生效、有效期、运行依赖和 production-ready 门禁。

这些检查同时用于正常启用、保留当前 active 版本和显式回滚，避免状态切换后形成只对部分客户端可执行、却没有安全退路的规则。

## 4. 后台与 Figma 边界

`ADM-REC-01/02/03/04` 继续使用既有 Figma 页面与状态。本增量只让既有“最低客户端版本”和“回滚版本”字段产生真实约束：

- 创建/编辑只接受可比较的数字版本；
- 启用失败复用既有校验错误反馈；
- 列表、详情、Dry-run、精选排期和审计时间线布局均不改变。

因此无需新增 Page ID、状态、视觉组件或 Figma 节点。

## 5. 明确未越过的决策门禁

本增量不实现或假定：

- OQ-009 热度公式、反刷样本和聚合任务；
- OQ-020 推荐证据保留、purge 和跨会话频控；
- OQ-023 个性化法律决策及行为信号扩展；
- 依赖曝光归因的指标/反指标和自动停止阈值；
- 真实客户端版本分布、扩量比例或生产发布参数。

## 6. 统一后置验证

按当前开发顺序，本阶段不运行构建或测试。全部开发完成后的统一验证至少覆盖：

- `1.0` 与 `1.0.0` 等价、数值比较而非字符串比较；
- 缺失、非法和低于策略最低版本的请求；
- 高版本 scheduled + 低版本 active 的分流；
- 高版本 active + 兼容显式回退；
- 灰度回退版本高于目标版本时阻断启用；
- 当前客户端不存在个性化规则时 capability 关闭；
- 同一推荐游标跨规则版本切换后继续安全失效。

当前没有修改 Wrangler、没有执行 `0083` 或任何后续 migration、没有启用推荐 capability，也没有运行 API/KMP 构建、测试或设备 QA。
