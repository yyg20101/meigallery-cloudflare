# Message-2 安全与运营跨仓集成边界

App 版本：1.0

日期：2026-08-07

状态：核心安全闭环已完成既有验证；ADM-MSG-02 内部协作/独立安全升级与 ADM-MSG-03 运营组/班次/自动分配开发完成，新增 migration、真实配置与专项测试后置；所有环境默认关闭

## 1. 目标

Message-2 在 Message-1 的仅文本平台话题上补齐可执行的安全与运营最小闭环。它解决“用户如何立即止扰、如何固定最小举报证据、谁能查看正文、运营过载时如何停写，以及在保留期尚未正式决定前如何阻止误上线”等问题。

本阶段仍是开发验证，不代表举报政策、真实值班、SLA、保留期、地区合规或生产发布已经批准。

## 2. 冻结范围

### 2.1 观看者侧

- 举报真人资料、媒体、本人会话或本人可见消息；举报不要求会员。
- 使用版本化原因目录和最多 500 字补充说明；不允许上传图片、视频或文件证据。
- 幂等提交举报，查看本人举报列表、必要状态、更新时间和用户可见说明。
- 拉黑/解除拉黑人物；拉黑立即清理喜欢/关注、关闭已有会话写权限，并阻止后续互动、建会话和消息。
- 解除拉黑不恢复旧互动或旧会话。
- 主动关闭本人会话；关闭后保留历史只读且不能重新打开。
- 在人物详情、会话和消息操作中进入相应安全动作；没有服务端成功响应不得显示成功。

### 2.2 运营与安全侧

- 会话列表保持无正文摘要；操作员必须先领取限时会话分配，才能读取正文、已读、回复或关闭。
- 每名操作员的活跃分配数和平台开放会话数受服务端容量门禁约束。
- 领取、续租、释放、正文访问、回复和关闭全部审计；过期租约不再授权。
- 当前有效租约持有人可追加运营/质量内部备注；备注与平台回复在数据、API 和 UI 上隔离，用户响应、通知、通用分析和通用审计均不得复制备注正文。
- 当前租约持有人可按稳定原因、目标管理员、交接说明和 `expectedAssignmentVersion` 显式转派；服务端重验目标状态与容量，在同一批次更新租约、写交接备注、转派事实、幂等结果和无正文审计，成功后原操作员立即失权。
- 当前租约持有人可按稳定原因、P0–P3 优先级和可选目标消息创建独立内部安全升级；案件与用户举报分表分队列，固定整个话题或目标消息前后一条的最小证据。
- 安全升级发起人不能领取本人创建的案件；独立审核员领取后才可读取内部说明和最小证据，并且只能形成“无需动作 / 话题只读 / 关闭”结论。内部说明与结论文案不返回用户，实际动作只使用固定系统消息说明。
- 管理员可查看无敏感正文的举报队列，领取案件后按 `safety_review` 目的读取最小证据窗口。
- 消息证据最多返回目标消息与前后各一条参与方可见消息；内部备注、其他举报人和无关会话不返回。
- 案件使用 `expectedVersion` 防止并发覆盖，可形成 `actioned` 或 `no_violation` 结论并返回最小用户说明。
- 全局运行控制可分别暂停新话题、观看者发送和运营发送；修改必须包含版本、原因和审计。
- 会话安全处置可以转为只读或关闭；真人资料紧急暂停继续复用现有发布暂停 Workflow，不创建第二套资料状态。
- Owner 可配置全局人工/自动分配策略、稳定运营组、组级容量、组长/操作员成员职责、个人容量和上海时区班次；跨日班次按服务端时间解释，不接受客户端时区决定。
- 路由规则按“真人 > 地区 > 默认”选择唯一最具体命中；自动分配只从命中组的当前有效值班成员中选择，并同时受个人/组活跃容量、服务日首次响应额度和全局容量约束。
- 自动候选按最低负载率、当前活跃数、最久未自动分配、稳定管理员 ID 排序；Owner 可对积压执行受批量上限约束的补偿分配。
- 分配策略一旦建立，人工领取与自动分配必须复用同一规则、组成员、班次和容量事实，不能通过会话队列绕过运营组范围。

### 2.3 保留策略门禁

- migration 建立版本化保留策略，但开发初始策略明确为 `unresolved`。
- 消息、举报和证据保留天数均为 `NULL`，自动清理 `purge_enabled=0`。
- OQ-020 未关闭前不得把策略发布或将 safety production-ready 设为 true。
- 本阶段不以“永久保留”替代正式决定，也不执行不可逆清理。

## 3. 本阶段不包含

- 申诉、复核改判、用户补充材料、客服工单和站内通知中心。
- 系统推送、WebSocket、Durable Objects、自动轮询或实时撤权事件。
- 用户上传证据、图片/语音/视频消息、媒体内容自动审核。
- 自动永久封禁、自动删除真人认证、仅凭举报数量下架或群众投票。
- 完整 capability/scope RBAC、强认证适配器、双人复核和 break-glass 告警通道。
- 自动保留期清理、数据导出/注销联动和法律隔离存储。
- 外部值班系统、P0/P1 电话/短信告警、正式 SLA 与质量看板。
- 会话质量抽检、评分、改进任务和质量看板。

这些能力必须在后续独立切片中冻结，不能通过远程字段在 App 1.0 中提前开放。

## 4. 契约与运行门禁

- App API v2 累计契约升级为 `1.6.0`。
- 新增 `capabilities.safety` 与版本化原因目录配置；未知原因、矛盾 capability 或非法文本上限时客户端安全关闭入口。
- 用户安全能力要求 Auth-1 与 `APP_SAFETY_ENABLED=true`。
- 后台安全能力要求 `APP_SAFETY_ADMIN_ENABLED=true`；消息工作台还要求原消息后台开关。
- production 额外要求 `APP_SAFETY_PRODUCTION_READY=true`，并必须在发布前验证原因目录和保留策略都为 `published + production_ready`。
- `APP_MESSAGING_ENABLED`/后台开关仍独立存在，但 Message-2 发布清单要求 safety 同时可用；不能只打开消息而跳过安全能力。
- production 所有新增开关保持 `false`。dev 只为 Safety-2 内部端到端联调开启用户端和后台安全开关，`APP_SAFETY_PRODUCTION_READY` 仍为 `false`；会员目录不切换到 Message-2 开发目录，消息 capability 继续关闭。

## 5. D1 权威模型

`0073_app_messaging_safety_operations.sql` 新增：

- Message-2 独立 `development` 会员目录，继承 Message-1 三项可执行消息 entitlement。
- 版本化举报原因目录与未决保留策略。
- 当前拉黑状态和追加式拉黑事件。
- 举报、最小证据引用、举报事件与独立幂等结果。
- 会话分配状态和追加式分配事件。
- 全局消息运行控制、容量阈值与保留策略引用。
- 会话限制/关闭原因字段。

`0084_app_conversation_collaboration.sql` 增加追加式内部备注、显式转派不可变事实和独立管理员幂等结果；不创建业务 seed，也不启用运行时开关。

`0085_app_conversation_safety_escalations.sql` 增加与用户举报隔离的内部安全升级案件、最小证据引用、追加式案件事件和独立幂等结果；不创建业务 seed，也不启用运行时开关。

`0086_app_conversation_routing_and_shifts.sql` 增加空的运营组、组成员与职责、个人/组容量、上海时区跨日班次、全局分配策略、真人/地区/默认路由规则、路由分配事实和独立管理员幂等结果；不创建业务 seed、不写入真实班次或规则，也不启用自动分配。

消息正文和举报说明只保存在受控业务表；通用日志、分析和 `admin_audit_logs` 只保存 ID、摘要、哈希、长度、状态与业务目的。

## 6. 关键一致性规则

- 拉黑写入、互动清理、会话关闭、系统消息和幂等结果必须在同一 D1 批次中收敛；任一步失败不得乐观显示完成。
- 举报提交由服务端解析目标归属并固定证据引用，客户端不能提交证据正文或声称目标版本。
- 消息/会话举报只能指向本人会话；资料和媒体目标必须存在并能解析到稳定人物资料。
- 拉黑、会话关闭、全局暂停和资料失效在每次发送时重新检查，旧页面和幂等重试不能绕过。
- 同一会话最多一个有效运营分配；过期、释放或转移后旧操作员立即失去正文和写权限。
- 内部备注读取继续复用 assignment 权限；转派以一次 assignment 版本跃迁为权威，不伪装成两个可独立失败的“释放 + 领取”操作。
- 内部安全升级创建必须绑定当前有效 assignment 版本；队列不返回说明或正文，发起人与审核人强制隔离，只有已领取审核员能按 `safety_escalation_review` 目的读取受控详情。
- 安全升级处置与固定用户系统消息、话题限制、assignment 释放、案件事件、幂等结果和审计必须在同一条件批次中收敛；竞争失败不得留下部分动作。
- 路由规则匹配只使用当前已发布人物 ID、会话地区和默认规则，按稳定优先级与 ID 决定唯一结果；不存在规则、班次或容量时保持未分配，不做跨组猜测。
- 自动分配的最终写入必须再次校验策略/规则/成员版本、班次、个人与组容量、服务日额度以及 assignment 当前版本；候选计算后的并发变化不能形成超容量或越权租约。
- 观看者消息写入是主事实，自动分配是其后的可恢复运营副作用；分配失败不得回滚已成功消息、向用户返回虚假失败或生成平台回复。
- 人工领取在未建立分配策略时保持既有兼容行为；策略一旦存在，必须与自动分配共享路由范围，且路由分配事实与 assignment 事件使用同一 mutation token 收敛。
- 案件和运行控制使用版本条件写入；并发旧版本返回冲突，不覆盖新状态。
- 所有需要跨语句收敛的副作用使用本次 mutation token 或前置系统消息作为条件；并发失败请求不能留下未绑定的互动清理、会话释放、处置或审计记录。
- 举报工作台默认只查询待处理状态（`submitted`、`triaged`、`investigating`）；已处置记录必须由运营显式切换状态筛选查看，避免历史记录挤占当前队列。

## 7. 验收基线

- 非会员账号可举报合格资料，但不能借举报获得消息权限。
- 重复举报幂等键只创建一个案件和一份证据引用。
- 拉黑后喜欢/关注被清理，既有会话关闭，建会话和发送均被服务端拒绝。
- 解除拉黑不恢复互动或会话。
- 未领取或租约过期的管理员不能读取正文、回复或查看消息证据，并产生拒绝/访问审计。
- 达到容量上限时拒绝新建会话或继续领取，不影响历史只读与举报。
- 紧急暂停启用后新写入立即拒绝，已有历史仍可读取。
- 保留策略未决或任一 production-ready 门禁未通过时 bootstrap 和写路由保持关闭。
- 管理审计不包含消息正文、举报说明或证据正文。
- 内部备注审计不包含备注正文；转派冲突、目标停用或目标容量已满时不留下备注、转派或审计残留。
- 内部安全升级队列不包含说明或消息正文；发起人不能领取本人案件，未领取审核员不能读取详情或处置。
- 安全升级结论不向用户泄露内部说明；“话题只读 / 关闭”只显示固定系统消息，版本或 assignment 竞争时不留下系统消息、限制或结论残留。
- 自动模式只把会话分配给命中运营组内当前值班且未超个人/组容量和服务日额度的有效成员；无候选时会话保持可诊断的未分配状态。
- 真人规则优先于地区规则，地区规则优先于默认规则；同层冲突在工作台可见，运行时仍以稳定优先级和规则 ID 收敛，不产生随机分配。
- 建立策略后，不属于命中组、已离班、停用或超容量的管理员不能从队列人工领取；条件竞争失败不留下分配事件、路由事实或审计残留。
- 补偿分配遵守策略批量上限和与新消息相同的候选算法；单个会话无候选不阻塞批次中其他会话。

## 8. 后续切片

Message-2 完成后仍不直接承诺实时化。优先顺序建议为：

1. Safety-2：最小申诉与独立复核已完成 dev 联调；后续补正式 RBAC/强认证、P0/P1 值班与 Runbook；
2. Privacy-1：正式保留期、导出/注销、法律隔离与自动清理；
3. Message-3：站内通知与可靠到达，再单独评估实时通道；
4. Membership-2：站内会员申请，继续保持无在线支付。
