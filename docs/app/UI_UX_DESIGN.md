# 真人发现与互动 App UI/UX 设计文档

App 版本：1.0

日期：2026-07-20

状态：需求讨论中

## 1. 设计输入与结论

原始概念图提供了粉色品牌氛围、登录页、双列真人卡片、聊天页、VIP 和金币入口。它可作为视觉情绪参考，但不是可直接开发的完整交互稿。

普通注册用户只是观看者，只有管理员认证并发布的真人进入列表；没有双方匹配；只有有效心享会员可以直接创建私信；未认领真人的消息由平台运营接收和回复并明确披露。

因此保留“温暖、浪漫、轻盈”的品牌感，移除会造成双边交友误解的匹配、在线承诺和本人代聊视觉。

## 2. 设计原则

1. 真人优先：内容和人物是视觉焦点，商业入口不挤占首页首屏。
2. 身份可理解：认证、运营主体、会员和热度使用不同图形与文案。
3. 权益先说明：在购买或创建私信前解释功能、额度、接收方和限制。
4. 状态不伪造：只有真实事件才显示在线、输入、已读和本人回复。
5. 可逆操作：喜欢、关注、收藏、静音、拉黑和装扮均提供明确反馈与撤销/恢复路径。
6. 安全不隐藏：举报、拉黑、隐私、申诉和交易明细容易找到。
7. 平台一致：Android/iOS 共享任务、文案和视觉 token；Nuxt 管理后台按桌面运营场景设计。普通用户桌面客户端未立项。

## 3. 概念稿修订表

| 概念稿表达 | 问题 | 正式设计规则 |
|------------|------|--------------|
| “高效真实的交友平台” | 容易理解为普通用户互相配对 | 使用“经认证的真人发现与互动平台” |
| “快速匹配” | 产品没有双方匹配 | 使用“发现喜欢的真人”或“按偏好推荐” |
| 卡片“在线” | 目前真人不操作账号 | 未有本人会话心跳证据时不得显示在线 |
| 精确 1km/2km | 暴露位置且可能不真实 | 展示城市/地区或模糊距离段，不展示轨迹 |
| VIP“无限次聊天” | 忽略新会话额度、安全和响应边界 | 展示明确等级额度及“互动仍受安全规则限制” |
| 真人头像回复 | 管理员代运营时构成误导 | 使用“平台运营”身份、头像和系统说明 |
| VIP 徽章接近认证盾牌 | 付费可能被误认成真实性 | 心享会员用星/光环，真人认证用盾牌勾 |

## 4. 信息架构

### 4.1 移动端

```text
推荐：为你推荐 / 地区 / 热门 / 最新 / 分类 / 搜索筛选 / 真人详情
关注：关注更新 / 喜欢 / 收藏夹 / 浏览历史
消息：私信 / 互动 / 交易权益 / 系统安全
我的：心享会员 / 金币 / 礼物装扮 / 账号设备 / 隐私数据权利
```

底部导航固定为“推荐、关注、消息、我的”。会员或金币不能成为一级导航。

### 4.2 Nuxt 管理后台桌面端

- 左侧：运营一级导航、管理员账号摘要和设置入口。
- 中间：真人、会话、会员、金币或审核列表，可键盘浏览。
- 右侧：真人详情、会话、调币或审核详情。
- 窗口较窄时退化为单列导航栈，不压缩关键文字。

App 1.0 不交付普通用户 Windows/macOS 客户端；如未来立项，需要单独产出用户桌面信息架构和高保真。

## 5. 关键页面

### 5.1 启动、登录和注册

- 品牌页保留概念稿柔和背景，但避免“马上遇到对象”等结果承诺。
- 登录方式由目标地区配置；条款、隐私、必要资格和客服入口在提交前可访问。
- 注册完成后进入偏好设置，可跳过；不要求创建公开人物资料。
- 偏好包括地区范围、标签、风格和内容类型，敏感偏好需说明用途。

状态：加载、验证码等待、验证失败、账号受限、网络不可用、条款更新和设备风险验证。

### 5.2 推荐首页

顶部区域：模糊地区选择、搜索、筛选和通知。二级页签：推荐、地区、热门、最新。

推荐卡至少包含：

- 已审核封面和展示名。
- 真人认证盾牌及可点击说明。
- 地区、核心标签、职业/风格等必要摘要。
- 推荐理由，例如“你关注了清新风格”“近期热门”。
- 喜欢、关注、收藏快捷操作。

列表可使用双列卡承接概念稿，但无障碍大字体或小屏切换单列。卡片不得显示虚假在线、精确距离、保证回复或消费排名。

### 5.3 搜索与筛选

- 搜索建议区分历史、热门标签和结果。
- 基础筛选向登录用户开放；高级筛选、保存条件数量由 entitlement 控制。
- 受限筛选仍可预览名称，但点击后展示所属会员等级和实际价值。
- 提供清空、查看结果数、无结果建议和非个性化排序切换。

### 5.4 真人详情

结构顺序：媒体头图 → 认证与展示名 → 地区/标签 → 简介 → 图库 → 运营与私信说明 → 相关真人。

固定操作：喜欢、关注、收藏、私信。更多菜单：举报、拉黑、分享。

- 普通观看者点击私信：打开会员说明半屏/页面，不创建会话。
- 会员点击私信：先由服务端校验；首次进入显示接收主体说明。
- 未认领资料显示“消息由平台运营接收和回复”。
- 已认领资料显示“消息由真人本人接收”；标识必须来自服务端状态。

### 5.5 关注、喜欢与收藏

- 关注页以更新为主；喜欢为轻量历史；收藏支持文件夹。
- 三类关系的图标、动词和空状态不同，不使用“配对成功”或爱心连线动画。
- 已下架资料保留最小记录和不可用说明，不继续展示受保护媒体。

### 5.6 消息中心

消息中心分为私信、互动、交易权益、系统安全四类。交易和安全通知不可被营销总开关关闭。

会话列表显示：真人封面、展示名、接收主体标签、最后一条可展示摘要、时间和未读数。平台运营会话在列表中持续显示“平台运营”。

### 5.7 会话页

顶部包含：返回、真人资料入口、接收主体标签和更多菜单。首次消息前显示不可删除的服务说明卡。

- 平台回复头像和名称统一使用平台运营身份，不使用真人头像冒充发送者。
- 用户消息和平台消息明确分栏；系统消息居中。
- 已读仅代表当前实际接收主体已查看。
- App 1.0 输入区支持文本和表情；图片、礼物及其他媒体入口不得显示，权限或安全受限时替换为状态条。
- 更多菜单包含接收主体说明、静音、举报、拉黑、关闭会话和帮助。
- 运营模式切换时插入系统消息，并要求用户确认历史是否可交接（如适用）。

### 5.8 心享会员页

首版必须同时展示五级，可使用横向等级标签 + 当前等级详情，桌面端使用完整比较表。

| 等级 | 主文案 | 建议视觉方向 |
|------|--------|--------------|
| 心遇 | 从遇见开始，解锁真人私信 | 樱粉、轻量心形 |
| 心悦 | 看见更多喜欢，发现更加从容 | 珊瑚粉、柔和光晕 |
| 心知 | 更懂你的偏好，互动更进一步 | 紫粉、渐变星芒 |
| 心契 | 享受高阶服务与专属装扮 | 深紫金、细线徽记 |
| 心耀 | 心享至高等级，汇集完整权益 | 黑金/玫瑰金、克制动态光效 |

App 1.0 每级展示获取方式、期限、具体 entitlement 和与上一级差异，不显示在线价格、购买、续订或退款入口。获取说明附近必须出现私信接收主体、额度限制和不保证回复。未来在线销售启用后，才增加价格、购买、续订和退款信息。不得只写“更多权益”。

### 5.9 金币、礼物和装扮

- App 1.0 钱包首屏只显示余额、金币明细和规则，不显示充值、提现或消费入口。
- 金币包、礼物确认、头像框和皮肤页面属于后续商业化设计，1.0 不展示入口。
- 未来金币包显示实付价格、到账数量和赠送部分，不使用虚假倒计时。
- 未来礼物确认单显示目标真人、接收模式、单价、数量、总价和余额。
- 未来头像框、主页皮肤、聊天皮肤分别预览真实使用场景，显示永久/限时和会员到期规则。
- 管理员调币明细以“平台调整”展示数量、原因、时间、关联工单/申诉入口；不暴露内部风控细节。

### 5.10 我的与设置

优先级：账号摘要 → 当前会员/金币 → 礼物装扮 → 浏览与收藏 → 设备安全 → 通知 → 隐私推荐 → 数据导出/注销 → 帮助。

用户无需填写对外公开的身高、职业、自我介绍或交友偏好。头像与昵称只用于本人账号和会话识别，不进入真人发现列表。

### 5.11 后台关键页面

- 真人列表：来源、认证、发布、运营模式、争议和更新时间。
- 真人编辑：资料字段、授权证据、媒体、标签、预览和发布审批。
- 代运营工作台：队列、分配、响应时限、接收主体、用户消息、内部备注和安全升级。
- 商业后台：五级会员、entitlement、商品资源、价格版本和上下架。
- 财务后台：订单、账本、调币申请、双人复核、冲正和对账差异。
- 认领后台：申请、身份/授权证据、冲突、批准和会话交接。

高风险动作使用原因、影响预览和二次确认；双人复核动作明确显示“尚未生效”。

## 6. 组件与视觉系统

### 6.1 语义 token

| Token | 用途 |
|-------|------|
| `brand.primary` | 主按钮、选中和品牌强调 |
| `person.verified` | 真人认证，只使用盾牌勾 |
| `operation.managed` | 平台代运营说明和消息身份 |
| `membership.10..50` | 五级心享会员展示，不参与权限 |
| `state.success/warning/danger/info` | 成功、警告、危险和中性说明 |
| `surface.base/raised/overlay` | 页面、卡片、弹层 |

颜色不是唯一状态载体；所有徽章同时包含图形和文本/无障碍标签。

### 6.2 核心组件

- `PersonCard`、`VerificationBadge`、`OperationModeBadge`
- `InteractionBar`、`EntitlementGate`、`MembershipTierCard`
- `ConversationRow`、`MessageBubble`、`SystemDisclosureCard`
- `WalletBalance`、`LedgerRow`、`GiftCard`、`CosmeticPreview`
- `EmptyState`、`ErrorState`、`RestrictedState`、`OfflineBanner`

组件通过服务端状态驱动，不在组件内部按等级名称写权限条件。

## 7. 状态、动效与反馈

- 加载优先骨架屏，超过合理时间显示可重试说明。
- 关注、喜欢和收藏可乐观更新，但失败必须回滚；扣币、赠礼和购买不得离线乐观完成。
- 动效用于层级切换和操作结果，不使用持续闪烁或消费刺激。
- 支持系统“减少动态效果”；关闭动效后所有结果仍通过文字和图标可理解。
- 危险操作、购买和调币不以轻触觉代替明确结果。

## 8. 文案规范

使用事实语言：

- 推荐：“因为你关注了清新风格”，不写“她在等你”。
- 私信：“由平台运营接收和回复”，不写“她会看到”。
- 会员：“每日可新建 X 个会话”，不写“无限畅聊”。
- 礼物：“向该真人资料赠送虚拟礼物”，不写“对方已收款”。
- 认证：“资料与授权已由平台审核”，不写“绝对真实可靠”。
- 失败：说明原因、是否扣费、可恢复时间和下一步。

## 9. 无障碍与适配

- 移动触控目标不小于目标平台推荐尺寸，元素间保留防误触间距。
- 支持动态字体；关键价格、额度、接收主体和错误文案不可截断。
- 图片提供内容描述或标记为装饰；敏感图片支持模糊预览和替代文案。
- 桌面端完整支持 Tab、Shift+Tab、方向键、Enter、Escape 和可见焦点。
- 会员比较表提供线性阅读顺序，不仅依赖横向滚动或颜色。
- 深色模式保持认证、运营身份、会员和危险色之间足够区分。

## 11. UI 验收

- **UI-AC-001**：任一真人卡片不会把会员、热度或运营推荐显示为认证。
- **UI-AC-002**：普通账号无法找到创建公开真人资料或参与匹配的入口。
- **UI-AC-003**：平台代运营私信在详情入口、会话列表和会话页均有持续标识。
- **UI-AC-004**：App 1.0 五级会员均显示具体权益、额度、获取方式、期限和限制，不显示在线支付入口；价格只在未来销售能力启用后验收。
- **UI-AC-005**：管理员调币在用户明细中显示可理解原因和申诉入口。
- **UI-AC-006**：大字体、屏幕阅读器、键盘和减少动态效果下可完成核心旅程。
- **UI-AC-007**：网络失败不会显示虚假购买、扣币、赠礼、送达或已读成功。
- **UI-AC-008**：资料暂停、会员到期、额度不足和安全受限都有专用状态与下一步。
