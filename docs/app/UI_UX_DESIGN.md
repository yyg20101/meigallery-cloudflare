# “心动遇见你”App UI/UX 设计文档

版本：1.1（概念稿评审与跨平台基线）

日期：2026-07-20
状态：`[目标设计]`

## 1. 评审范围

输入是一张以手机为载体的合成概念图，包含品牌宣传、登录、发现列表、聊天、VIP 和金币区域。它表达了品牌方向和少数核心页面，不是完整交互稿，也无法验证真实字号、对比度、触控尺寸、滚动行为、键盘避让和无障碍实现。概念图没有提供桌面稿，本文新增的桌面规范属于目标设计，不是对原图的推断。

本文件先审查概念稿，再定义进入移动端及后续 Windows/macOS 线框图和高保真设计前必须补齐的页面、状态和规则。共享 Compose UI 使用统一信息架构和设计 token，但导航、输入方式、窗口和平台习惯允许适配。

## 2. 概念稿观察

### 2.1 第一印象

- 产品表达：年轻、甜美、同城、以女性资料卡和即时聊天为主的交友 App。
- 首个视觉焦点：粉色品牌标题，其次是人物大图，再是发现列表和聊天。
- 优点：品牌色统一；登录主操作清晰；资料卡能快速扫描年龄、身高、职业和距离；底部导航符合移动端习惯；聊天气泡层级直观。
- 概念评分：设计完成度 `C+`。视觉方向明确，但安全、真实性、可访问性和完整交互不足以进入开发。

### 2.2 高优先级问题

| 问题 | 用户风险 | 设计修正 |
|------|----------|----------|
| 所有人物照片风格和五官高度相似，像生成图 | 削弱“真人在线”和“真人认证”的可信度 | 高保真稿必须使用有授权、可追溯的多样化真实测试素材，并展示不同认证状态 |
| “真人认证”与卡片上的“搭讪”标签缺少证据说明 | 用户可能把营销话术理解为身份保证 | 徽章可点击查看“核验了什么、何时过期、没有核验什么” |
| 卡片显示精确 `1km/2km` | 可能被多次测距推断位置 | 改为“同城”“约 2–5km”，提供隐藏距离开关 |
| VIP 文案写“无限次聊天” | 容易被理解为付费后可无限骚扰陌生人 | 改为“匹配后畅聊”，招呼额度仍受安全限制 |
| VIP 专属身份标识与真人认证概念接近 | 付费身份可能冒充信任认证 | VIP 用皇冠，认证用盾牌勾，颜色和文案彻底分开 |
| 金币充值和礼物曝光很强，安全入口不可见 | 商业化压过用户保护 | 资料和聊天的更多菜单固定显示举报、拉黑、安全帮助 |
| 登录页协议文字很小且默认勾选感强 | 同意可能不充分且无障碍较差 | 不预勾选；使用可点击的条款列表、摘要和独立同意状态 |
| 大面积浅粉与浅灰小字 | 对比度和户外可读性风险 | 正文达到 WCAG AA；粉色只承担强调，不承担长文本 |
| 发现页顶部“推荐/附近/活跃/筛选”拥挤 | 375dp 宽度下易误触 | 使用横向分段控件 + 独立筛选图标，触控区至少 44×44dp |
| 聊天页展示具体见面语境但无安全提醒 | 新匹配容易过早线下见面 | 首次讨论线下见面时展示克制的安全提示和分享行程入口 |

### 2.3 不采用的视觉模式

- 不使用性别单一、模板化美女卡片作为默认产品截图。
- 不使用“颜值”“女神榜”“被多少人追”等物化指标。
- 不让粉色成为女性专属暗示；品牌系统需要兼容不同性别与关系偏好。
- 不以心形、礼物、金币和皇冠填满所有页面；功能页面保持平静、少装饰。
- 不用会员色表达身份可信度或审核优先级。

## 3. 设计原则

1. 信任先于转化：认证、安全和资料来源比充值入口更清楚。
2. 同意先于互动：持续聊天建立在双方匹配或明确接受招呼之上。
3. 模糊位置优先：默认最少披露，用户主动提高可见性。
4. 一个页面一个主任务：发现页用于选择，聊天页用于沟通，钱包页用于理解账目。
5. 风险操作可恢复：误触跳过可短时撤销；拉黑即时生效且可在设置中管理。
6. 安全动作不藏：举报和拉黑在资料与会话中都可在两步内完成。
7. 商业化不制造压力：不使用倒计时、虚假稀缺、羞辱式文案或默认订阅。

## 5. 页面清单与完成定义

### 5.1 启动与登录

| 页面 | 主任务 | 必备状态 |
|------|--------|----------|
| 品牌启动 | 快速建立品牌，不阻塞过久 | 首次启动、普通启动、离线 |
| 成年人门槛 | 明确 18+ 和禁止内容 | 接受、退出、政策链接 |
| 手机号登录 | 获取/输入验证码 | 正常、发送中、倒计时、频率限制、号码格式错误、Turnstile |
| 其他登录 | 旧账号绑定、Apple/微信等 | 可用、取消、绑定冲突、恢复 |
| 条款与授权 | 分目的同意 | 必要条款、可选位置、推荐、营销；撤回说明 |

启动画面最多作为短暂品牌过渡，不要求用户等待动画结束。登录页主按钮是“手机号登录/注册”，第三方登录不抢占主操作。

### 5.2 资料创建

采用分步流程，每一步可保存：

1. 基础身份：昵称、出生年份、城市。
2. 展示偏好：希望遇见的人和年龄范围；提供“暂不填写”给非必要字段。
3. 职业、简介和兴趣。
4. 上传主头像和补充照片，显示授权与内容规则。
5. 隐私设置：距离、在线状态、谁能招呼。
6. 预览并提交审核。

审核状态页必须区分 `排队中`、`审核中`、`需修改`、`已通过`、`被拒绝`、`申诉中`，并给出下一步。

### 5.3 发现页

推荐布局：单列大卡优先，支持用户在“单列沉浸”和“双列快速浏览”之间选择。双列卡片只能承载摘要，点击进入详情。

卡片信息顺序：

1. 主媒体与安全的图片占位。
2. 在线/近期活跃状态。
3. 昵称、年龄、认证徽章。
4. 城市或模糊距离段。
5. 职业和最多两个共同兴趣。
6. 清晰的喜欢、跳过、招呼操作。

不得把身高设为所有用户的强制突出字段；由用户选择是否展示。

发现页状态：骨架屏、首次引导、正常、筛选后为空、暂时无更多、网络失败、定位拒绝、账号/资料受限。

### 5.4 资料详情

- 顶部媒体轮播支持页码，不自动播放视频声音。
- 资料摘要明确显示认证种类、更新时间和内容审核状态。
- 展示自我介绍、兴趣、生活方式和可公开字段。
- 固定底部操作为喜欢/招呼；更多菜单包含举报和拉黑。
- 距离文案可点击查看隐私说明，不展示地图点位。
- 安全状态异常时隐藏互动按钮并解释用户可执行的下一步。

### 5.5 消息页

消息首页分为：招呼、匹配、会话、系统通知。未读数超过两位时显示 `99+`，不持续制造焦虑。

会话详情：

- 顶栏显示头像、昵称、认证摘要和更多安全菜单。
- 新匹配顶部短提示说明双方已匹配以及社区规则。
- 输入区支持文字、官方表情、官方贴纸和礼物；首版不展示麦克风和相册入口。
- 发送中、失败、重试、已送达、已读和撤回状态可区分。
- 被拉黑/解除匹配/封禁时输入区替换为只读状态条。
- 礼物消息标明金币数量和不可退款/可申诉的具体规则入口，不使用赢钱或回报暗示。

### 5.6 我的、会员与金币

“我的”首页优先显示资料完成度、审核/认证和安全设置；VIP 和金币作为次级模块，不占据整个首屏。

VIP 页面必须展示：

- 每项权益的具体作用和限制。
- 订阅周期、价格、自动续费、恢复购买和取消方法。
- VIP 不等于认证，不提高审核通过率，不绕过安全限制。

金币页面必须展示：

- 可用余额和冻结余额。
- 充值、消费、退款、冲正、赠送批次的逐条账目。
- 已购买金币不设过期日。
- 金币不可提现、转账或跨产品兑换。

### 5.7 安全中心

- 黑名单管理。
- 举报记录与处理状态。
- 会面安全建议和紧急资源。
- 账号风险提醒和登录设备。
- 社区规则、官方联系方式和申诉。
- “暂停被发现”作为明显快捷开关。

### 5.8 注销与数据权利

注销页按顺序说明：

1. 会立即停止的能力。
2. 会删除或匿名化的数据。
3. 因账务、争议或安全义务需要保留的数据类别和期限说明。
4. 订阅取消不是账号删除，账号删除也不自动取消商店订阅的情况说明。
5. 冷静期、处理进度和完成通知。

不得只提供“停用账号”来代替删除。

## 6. 导航规范

- 手机一级底部导航固定四项，使用图标 + 文本；当前项不能只靠颜色表达。
- 顶部分段控件用于同一任务下的推荐/附近/活跃，不把它们放成第二套主导航。
- 所有深层页面有明确返回，保留未提交草稿时给出保存选择。
- 安全相关页面不通过营销弹窗或会员墙阻断。
- URL/deep link 定义与页面一一对应，支持通知跳转后返回原上下文。

### 6.1 桌面自适应布局

- Windows/macOS 使用左侧导航栏或可折叠 rail，不把手机底部导航等比例拉宽。
- 窗口按紧凑、中等、展开三类宽度适配；紧凑窗口可以回退为单栏，展开窗口最多使用“导航 + 列表 + 详情”三栏。
- 聊天页在展开窗口中同时显示会话列表和当前会话；资料详情可在独立详情栏展示，但举报、拉黑等安全动作仍保持固定位置。
- 支持键盘 Tab/Shift+Tab、方向键、Enter/Space、Esc 和平台标准复制粘贴；业务快捷键必须可发现且不得覆盖系统快捷键。
- 支持鼠标 hover、右键菜单、滚轮、触控板和窗口缩放；危险动作不能只出现在 hover 状态。
- 多窗口首版只允许会话或资料详情等受控场景，注销、封禁、远程登出时必须同步关闭或遮蔽所有敏感窗口。
- macOS 遵循菜单栏、窗口和通知习惯；Windows 遵循系统窗口、任务栏、通知和安装/卸载习惯。平台差异通过 Compose Multiplatform 平台适配实现。

## 7. 视觉系统

### 7.1 色彩

建议品牌主色：莓果粉，不直接沿用概念稿的高饱和大面积粉色。

| Token | 用途 | 要求 |
|-------|------|------|
| `brand.primary` | 主按钮、选中态 | 与白字满足 WCAG AA |
| `brand.soft` | 轻量背景 | 不承载关键小字 |
| `surface.primary` | 主页面背景 | 浅色与深色模式分别定义 |
| `text.primary` | 标题与正文 | 正文对比度至少 4.5:1 |
| `text.secondary` | 辅助信息 | 最小字号仍满足对比度 |
| `semantic.success` | 在线、完成 | 必须同时有文字或图标 |
| `semantic.warning` | 审核、风险提示 | 不与金币色混淆 |
| `semantic.danger` | 举报、封禁、删除 | 只用于危险语义 |
| `membership.vip` | VIP 身份 | 与认证、警告色分开 |

### 7.2 排版

- 中文正文使用平台高质量系统中文字体，品牌标题可评估一款有授权的展示字体。
- 手机正文默认不小于 16sp；辅助信息不小于 12sp，并支持系统字体缩放。桌面字号根据观看距离和系统缩放单独验收，不直接复用手机密度结果。
- 标题、正文、说明使用稳定的 4–5 级比例，不通过大量不同粉色区分层级。
- 数字余额和账本列使用等宽数字特性，避免跳动。

### 7.3 间距与形状

- 使用 4dp 基础间距，常用为 8/12/16/24/32dp。
- 手机触控目标至少 44×44dp；桌面指针目标、焦点框和点击热区按平台规范验收；相邻危险与普通操作保留足够间隔。
- 卡片只有在整体可点击或表达独立资料时使用，不把所有设置项包成装饰卡片。
- 头像、资料卡、弹窗和按钮使用不同圆角层级，避免全部“大圆角泡泡”。

### 7.4 图像

- 所有设计与商店截图使用有授权素材并保留来源记录。
- 测试数据覆盖不同性别、年龄段、肤色、体型、职业和辅助需求，避免模板化单一审美。
- 媒体加载失败使用中性占位，不显示可识别的旧缓存。
- 敏感或待审核媒体默认模糊且不可通过客户端参数解除。

## 8. 组件状态

每个组件必须设计以下状态：默认、hover、按下、键盘聚焦、禁用、加载、成功、错误、空、离线、权限不足和安全受限。手机不依赖 hover，桌面不允许缺少可见焦点。

重点组件：

- `ProfileCard`：单列/双列、媒体失败、认证徽章、模糊距离、已互动。
- `VerificationBadge`：手机号、年龄、身份、真人四类，含解释弹层。
- `MembershipBadge`：只表达权益层级。
- `ConsentRow`：必要/可选、当前版本、撤回影响。
- `ChatComposer`：正常、发送中、离线排队、会话关闭。
- `MessageBubble`：发送中、送达、已读、失败、撤回、审核隐藏。
- `ReportSheet`：类别、证据选择、紧急风险和提交状态。
- `WalletLedgerRow`：充值、消费、退款、冲正、赠送、冻结。

## 9. 动效与触觉

- 页面进入 180–260ms，使用 ease-out；退出更短。
- 喜欢和匹配可以有一次轻量反馈，但不阻塞操作、不重复轰炸。
- 消息发送以位置和透明度反馈，不做大幅弹跳。
- 充值、礼物和订阅不得使用赌博式灯效、连击或高压倒计时。
- 尊重 `Reduce Motion`，关闭非必要位移和粒子效果。
- 触觉反馈只用于明确操作：喜欢、匹配、发送成功、危险确认。

## 10. 可访问性

- 支持 VoiceOver/TalkBack 以及目标 Windows/macOS 屏幕阅读器的语义标签、阅读顺序和操作提示。
- 支持动态字体至 200%，核心功能不截断、不遮挡。
- 状态不只靠红/绿或粉/灰表示；使用图标和文字。
- 图片提供由用户填写或系统生成的非敏感替代描述；用户可编辑。
- 键盘导航和外接键盘可访问主要动作。
- 桌面端完全不使用鼠标也能完成登录、发现、匹配、聊天、举报、拉黑、设置和注销。
- 窗口缩放、系统显示缩放和高对比度模式下不丢失安全入口或主操作。
- 表单标签始终可见，不能只使用 placeholder。
- 错误信息说明发生了什么和如何修正，并定位到对应字段。

## 11. 隐私权限时机

| 权限 | 请求时机 | 拒绝后的替代 |
|------|----------|--------------|
| 定位 | 用户首次进入“附近”并理解用途后 | 手动选择城市，展示非精确结果 |
| 通知 | 首次匹配或用户主动打开通知设置时 | 客户端内消息中心 |
| 相册/文件 | 用户主动上传资料媒体时 | 拍摄、文件选择器或稍后上传 |
| 相机 | 用户主动拍摄/核验时 | 相册、文件选择器或其他合规核验路径 |
| 麦克风 | M3 用户主动发送语音/发起通话时 | 文本聊天 |

不得在启动时一次性索要全部权限。

## 12. 设计交付物清单

进入开发前，设计团队必须提供：

- 信息架构和所有页面流转图。
- M1 全页面低保真线框图。
- 浅色/深色高保真稿，覆盖 375/390/430dp。
- 桌面高保真稿覆盖紧凑窗口、1024px 和 1440px 展开窗口，并分别展示 Windows/macOS 平台差异。
- 组件库、设计 token 和全部状态矩阵。

- 空、错、离线、权限拒绝、安全受限、账号封禁和强制升级页面。

## 13. UI 验收

- **AC-UI-001**：在 375dp 屏幕和 200% 字体下，登录、举报和注销流程可完成且无横向滚动。
- **AC-UI-002**：用户拒绝定位后，可在两步内选择城市并继续发现。
- **AC-UI-003**：任一资料卡上，认证徽章与 VIP 徽章视觉、文案和解释均不同。
- **AC-UI-004**：聊天页在两步内可以拉黑或举报，且拉黑不要求先提交举报。
- **AC-UI-005**：会话关闭后输入区不可编辑，并清楚说明原因和可执行动作。
- **AC-UI-006**：金币余额的每次变化都能进入对应账本明细，不只显示最终余额。
- **AC-UI-007**：所有正文和交互控件满足 WCAG AA 对比度与 44dp 触控目标。
- **AC-UI-008**：关闭动画后，匹配、消息和购买状态仍可理解。
- **AC-UI-009**：在 1024px 至 1440px 桌面窗口中，导航、列表和详情按规则切换，无手机页面机械拉伸或无界留白。
- **AC-UI-010**：Windows/macOS 客户端仅使用键盘即可完成聊天、举报、拉黑和注销，焦点顺序稳定且始终可见。
- **AC-UI-011**：账号远程登出或被封禁后，所有桌面窗口立即隐藏敏感内容并返回安全状态页。
