## 3. Goal

### Problem

App 会处理观看者账号、设备、偏好、互动、浏览历史、平台话题、会员和金币信息。用户需要理解数据如何使用，并能修改设置、导出或注销账号；但部分账务、安全和法律证据不能简单即时物理删除。如果只提供一个“删除账号”按钮或仅在本机隐藏数据，就无法满足真实的数据权利、跨设备一致性和审计要求。

### Solution

在“我的”建立账号摘要、设备、站内通知、隐私推荐、互动历史、拉黑名单、数据导出、注销、帮助和申诉的统一入口。所有设置由服务端按用途和版本保存；导出与注销使用可查询、可重试的 Workflow。用户可见数据及时停止使用或删除，依法保留的数据隔离、最小化并不再参与推荐、营销或普通运营。

### Impact

- 提高用户对账号、推荐、通知和数据使用的可理解与可控制程度。
- 降低删除不彻底、导出越权、跨设备设置不一致和敏感数据泄漏风险。
- 为目标地区隐私政策、商店审核和客服处理建立可验证流程。
- 确保未来 Web 迁移后仍有统一的数据主体请求入口与状态。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 普通观看者 | 管理账号、偏好和历史 | 设置易找、跨设备生效、不会公开个人资料 |
| 心享会员 | 查看当前权益和金币摘要 | 注销影响清楚，不出现购买/退款伪入口 |
| 隐私敏感用户 | 关闭个性化、清除数据、导出或注销 | 处理范围、期限和例外透明 |
| 受限账号用户 | 仍能访问必要数据权利 | 限制不阻断合法导出、申诉和注销入口 |
| 客服/隐私人员 | 处理数据请求和争议 | 身份核验、最小访问、SLA 和审计 |
| 安全/法务 | 隔离保留必要证据 | 不用保留例外继续产品化使用数据 |

## 5. User Stories

- 作为用户，我想看到账号、会员、金币和设备摘要，以便理解当前状态。
- 作为用户，我想修改账号昵称和头像，以便识别自己的账号，但不进入真人发现列表。
- 作为用户，我想关闭个性化推荐并清除相关记录，以便控制行为数据使用。
- 作为用户，我想管理浏览历史、搜索历史、通知偏好和拉黑名单，以便控制 App 体验。
- 作为用户，我想下载一份可理解的数据副本，以便查看平台持有哪些本人数据。
- 作为用户，我想查询导出进度并在文件过期后重新申请，以便安全获取数据。
- 作为用户，我想申请注销并清楚知道会员、金币、消息和保留数据会如何处理，以便作出决定。
- 作为受限用户，我想继续访问帮助、申诉和数据权利入口，以便不被账号限制剥夺基本权利。
- 作为隐私人员，我想按身份核验、期限和范围处理请求，以免泄漏其他用户、真人或管理员信息。

## 6. Requirements

### 6.1 Functional Requirements

#### “我的”信息架构与账号资料

- **PDR-FR-001**：“我的”至少包含账号摘要、当前会员、金币摘要、个人内容中心、设备安全、站内通知、隐私与推荐、拉黑名单、数据导出、注销、帮助和申诉入口。
- **PDR-FR-002**：账号昵称和头像仅用于本人账号、设置和允许的会话识别，不生成 `Person`、`PersonProfile`、真人认证或公开发现资料。
- **PDR-FR-003**：会员和金币区域只显示服务端权威摘要；App 1.0 不显示在线支付、充值、提现、礼物或装扮消费入口。
- **PDR-FR-004**：账号、会员、金币、设备和数据请求状态分别加载；单一区域失败不得伪造成整体账号退出或错误余额。
- **PDR-FR-005**：账号受限时仍保留条款、隐私、帮助、申诉、导出、注销和安全退出入口，法律/安全明确限制的单项除外并需显示依据类别。

#### 隐私与推荐设置

- **PDR-FR-010**：设置至少区分个性化推荐、浏览历史、搜索历史、站内通知和可选产品分析等不同目的，不使用一个总开关替代全部选择。
- **PDR-FR-011**：关闭个性化推荐后，新推荐会话使用非个性化模式，不再读取账号喜欢、关注、收藏、浏览和搜索行为作为排序信号。
- **PDR-FR-012**：用户可分别清除浏览历史、搜索历史和推荐偏好；每项显示影响范围且通过服务端 Workflow 跨设备生效。
- **PDR-FR-013**：关闭历史记录只停止未来对应记录；现有历史应提供同步清除选项，不用默认保留误导用户。
- **PDR-FR-014**：站内通知偏好按消息、互动、会员/金币、系统/安全和营销分类；必要账号/安全通知不得因关闭营销而丢失。
- **PDR-FR-015**：App 1.0 不集成系统推送；通知设置不得请求 APNs/FCM 权限或显示不可执行系统设置入口。
- **PDR-FR-016**：App 渠道的可选分析/营销选择与现有 Web 选择按用途和渠道分别记录，不能因为用户在 Web 的地区默认值而伪造 App 明示同意。
- **PDR-FR-017**：必要安全、鉴权、审计和服务运行事件不受可选分析开关控制，但必须最小化并在隐私说明中区分。
- **PDR-FR-018**：设置响应包含政策/schema 版本、更新时间和生效状态；未知选项旧客户端安全忽略，不能默认开启。

Search-1 已按 `PDR-FR-010/012/013` 完成默认关闭的独立搜索历史服务端基线：读取搜索不会隐式记录；开启/关闭使用乐观版本，关闭只停止未来写入；逐条删除与全部清除提升版本并阻止旧在途请求重新写回；自由搜索词不进入 URL、审计或分析事件。到期物理清理由显式策略控制且不依赖搜索 capability 保持开放。production 保留期、purge 启用与用户隐私文案仍须 OQ-020 审批，详见 `docs/app/SEARCH_1_PERSON_SEARCH_HISTORY_INTEGRATION.md`。

#### 历史、关系和拉黑管理

- **PDR-FR-020**：用户可从设置进入喜欢、关注、收藏、浏览历史和搜索历史的查看/清除入口，具体互动规则以 F-06 为准。
- **PDR-FR-021**：拉黑名单仅本人可见，至少展示可识别的最小资料、拉黑时间和解除操作；资料不可用时不显示受保护媒体。
- **PDR-FR-022**：解除拉黑只解除安全关系，不自动恢复关注、喜欢、收藏、历史、会话或通知订阅。
- **PDR-FR-023**：清除操作展示目标数据、推荐影响和不可恢复说明；批量清除提交中禁止重复操作并返回可查询状态。

#### 数据导出

- **PDR-FR-030**：用户可创建本账号数据导出请求；创建前执行新鲜会话或再次身份验证，不能仅凭持有旧页面访问权限下载。
- **PDR-FR-031**：导出持久化状态至少包含 `requested`、`collecting`、`ready`、`expired`、`failed`、`cancelled`；`verification_required` 是创建/取消前的交互状态，不持久化为已创建申请状态。
- **PDR-FR-032**：导出至少包含账号资料、身份方式摘要、同意/设置、设备摘要、推荐偏好与可解释推荐证据、喜欢/关注/收藏/历史、拉黑状态与时间线、旧版图库点赞、会员/entitlement、金币明细、本人会话与消息、举报/申诉状态和数据请求历史中依法可提供部分。
- **PDR-FR-033**：导出不得包含密码/Token/验证码、其他用户身份、真人非公开资料、管理员身份、内部备注、风控规则、授权原件或其他账号的平台话题。
- **PDR-FR-034**：导出包提供人类可读索引和结构化数据，使用私有 R2 对象、短期单次/受限下载凭证和完整性校验；链接不得进入日志或分析。
- **PDR-FR-035**：App 通过站内通知和状态查询告知导出就绪，不依赖系统推送；过期后删除可下载副本，用户可重新申请。
- **PDR-FR-036**：重复请求按策略合并或返回在途任务；不得并行生成大量相同导出导致资源滥用。
- **PDR-FR-037**：导出失败展示可重试原因类别和支持入口，不暴露内部对象 key、查询或其他主体存在性。

#### 账号注销与删除

- **PDR-FR-040**：注销入口不得隐藏在客服后；提交前展示将停止的能力、会员/金币影响、消息/互动处理、保留例外、可取消阶段和预计进度。
- **PDR-FR-041**：App 1.0 的手动会员和不可提现金币不构成阻止注销的理由；注销生效后相关权益停用，用户在确认页明确知悉无法继续使用。
- **PDR-FR-042**：注销持久化状态至少包含 `scheduled`、`processing`、`completed`、`cancelled`、`failed`；`requested` 和 `verification_required` 是提交前交互状态。目标地区不允许等待期时，由正式策略把计划时间配置为立即可处理，不能由客户端跳过服务端状态机。
- **PDR-FR-043**：请求通过验证后立即阻止新平台话题、互动、会员发放和金币运营调整，撤销登录/实时连接，并在不可逆处理前保留必要的取消路径。
- **PDR-FR-044**：注销按数据类别执行删除、匿名化或法定隔离保留；依法保留的数据不得继续用于推荐、营销、普通内容运营或重新识别账号。
- **PDR-FR-045**：消息、举报、安全、账务和审计的保留范围以 OQ-020 最终政策为准；用户可见说明描述类别和目的，不暴露调查细节。
- **PDR-FR-046**：注销完成后身份标识按政策释放、封存或防重建；不得因同一邮箱再次注册而自动恢复旧互动、平台话题、会员或金币。
- **PDR-FR-047**：Workflow 失败采用 forward-fix 并保持账号受限，不把部分删除账号重新开放为正常状态。
- **PDR-FR-048**：未来存在在线购买时，退款、恢复购买和商店账户关系需由新 Feature 扩展；App 1.0 不显示不存在的退款步骤。

#### 帮助、申诉与真人权利入口

- **PDR-FR-050**：帮助中心提供账号、设备、推荐、互动、会员、金币、平台话题、举报、导出和注销主题，并显示当前真实支持渠道/服务时段。
- **PDR-FR-051**：用户可从账号限制、举报结果、金币明细和数据请求失败进入对应申诉/支持流程；工单关联对象 ID，不要求用户复制敏感凭证。
- **PDR-FR-052**：真人或权利人请求更正、限制展示、撤回授权和争议使用公开独立入口，不要求先注册普通观看者账号，也不等同 App 1.0 真人认领。
- **PDR-FR-053**：客服只能在工单范围查看必要账号和请求状态；查看导出内容、平台话题正文或高敏感证据需要独立审批和审计。

#### 审计与指标

- **PDR-FR-060**：设置变化、清除请求、导出、下载、注销、取消、失败恢复和客服访问记录操作者/账号、目的、版本、结果、时间和请求 ID。
- **PDR-FR-061**：指标至少包括设置采用率、个性化关闭率、清除完成率、导出完成时长/失败率、注销完成时长/失败率、申诉量和保留例外数量。
- **PDR-FR-062**：分析事件不得包含用户导出内容、设置自由文本、平台话题正文、下载 URL 或敏感身份标识。
- **PDR-FR-063**：数据权利 SLA 必须按目标地区与 OQ-025 责任人配置、告警和升级，不能只在客服手工表格跟踪。

### 6.2 主流程

隐私设置：

```text
我的 → 隐私与推荐 → 查看用途和当前值
→ 修改/确认 → 服务端版本化保存 → 跨设备同步与下游生效
```

数据导出（Privacy-1 控制面）：

```text
我的 → 隐私与数据权利 → 阅读当前范围 → 密码二次验证
→ 幂等创建 requested 申请 → 查询记录/详情/时间线
→ 服务端允许时再次验证并按版本取消
```

数据导出（Privacy-2A/2C 当前默认关闭源码边界）：

```text
requested → collecting → 生成私有制品与完整性证据
→ ready → 再次验证后签发短期下载凭证 → expired 并清理副本
```

账号注销（Privacy-1 控制面）：

```text
我的 → 注销说明 → 三项明确确认 → 密码二次验证
→ 创建 scheduled 申请 → 立即撤销会话并限制新业务写入
→ 使用申请级状态凭证查询 → 允许阶段再次验证并取消
```

账号注销（Privacy-2B 当前默认关闭源码边界）：

```text
scheduled → 正式等待规则到期 → processing
→ 删除/匿名化/依法隔离保留 → completed 与完成证据
```

### 6.3 数据处理矩阵

| 数据类别 | 用户控制 | 导出 | 注销处理 |
|----------|----------|------|----------|
| 账号资料/设置 | 修改、清除部分 | 本人数据 | 删除或匿名化 |
| 互动/历史 | 撤销、清除、关闭记录 | 本人记录 | 删除或匿名化 |
| 会员/金币 | 只读与申诉 | 权益/分录 | 停用；必要账务隔离保留 |
| 平台话题 | 导出本人依法可得内容 | 排除其他账号/内部备注 | 按政策删除、匿名化或隔离 |
| 举报/安全证据 | 查看必要状态 | 依法可得摘要 | 必要期限隔离保留 |
| 审计 | 不可由用户修改 | 依法可得摘要 | 最小化隔离保留 |

### 6.4 权限矩阵

| 操作 | 账号本人 | 客服 | 隐私人员 | 安全/法务 | 其他用户 |
|------|----------|------|----------|-----------|----------|
| 修改设置/清除数据 | 允许 | 不允许代操作，除批准恢复流程 | 不允许代替用户选择 | 不允许 | 不允许 |
| 创建/下载导出 | 允许且需验证 | 仅看状态 | 按案件管理 | 按法定范围 | 不允许 |
| 查看导出内容 | 允许 | 默认不允许 | 审批后最小查看 | 审批后最小查看 | 不允许 |
| 创建/取消注销 | 允许且需验证 | 只提供帮助 | 按 Workflow 处理 | 可设置合法保留 | 不允许 |
| 修改审计/保留证据 | 不允许 | 不允许 | 不允许 | 不允许；纠错写新事件 | 不允许 |

### 6.5 异常与恢复矩阵

| 异常 | 用户状态 | 恢复方式 |
|------|----------|----------|
| 设置版本冲突 | 显示最新值与重新确认 | 重新提交当前版本 |
| 导出生成失败 | 显示可重试/支持 | Workflow 从安全检查点重试 |
| 下载链接过期 | 不自动公开新链接 | 再次验证后重新签发/申请 |
| 注销部分失败 | 账号保持受限 | forward-fix，不回滚为正常 |
| 账号受限 | 保留权利入口 | 独立验证与申诉 |
| 无系统推送 | App 内查询/站内通知 | 不影响核心流程 |

### 6.6 Non-Functional Requirements

- **PDR-NFR-001**：隐私设置和数据权利 API 执行对象归属、新鲜会话和风险校验，响应禁止共享缓存。
- **PDR-NFR-002**：Privacy-1 使用 D1 申请状态机、幂等命令和只追加事件建立控制面；Privacy-2 的导出与不可逆注销处理再使用 Cloudflare Workflows/Queues 等异步编排，并具备进度、有限重试、检查点和审计。
- **PDR-NFR-003**：导出包和高敏感证据位于私有存储，使用短期凭证、访问次数/期限限制和服务端下载审计。
- **PDR-NFR-004**：用户清除和注销包含 D1、R2、Durable Objects 投影、本地缓存、日志/备份计划和第三方适配器的处理清单。
- **PDR-NFR-005**：依法保留数据与普通产品查询物理或逻辑隔离，访问使用独立角色、目的和审批。
- **PDR-NFR-006**：设置、导出和注销页面支持屏幕阅读器、动态字体、键盘、错误汇总和不依赖颜色的状态。
- **PDR-NFR-007**：退出、远程退出和注销立即清理 Token、必要消息、账号投影和不再授权媒体，不等待系统推送。
- **PDR-NFR-008**：数据请求任务有 SLO、积压告警、Owner、Runbook 和恢复演练；具体时限在 OQ-025 关闭后冻结。

### 6.7 实施前门禁

- OQ-002/OQ-024：首发地区、数据位置、跨境和运营主体。
- OQ-003：资格/年龄数据及其导出、删除和保留规则。
- OQ-020：各数据类别、日志、备份和安全证据保留期。
- OQ-025：数据主体请求 Owner、公开渠道、SLA 和隐私事件响应。
- OQ-030：目标商店与登录适配器对注销、账号恢复的要求。

未关闭 OQ-020/OQ-025 前可以实现默认关闭的申请控制面和状态 UI，但不能运行真实导出/删除 Workflow、冻结生产删除计划或对外承诺完成时限。

### 6.8 Privacy-1 历史开发边界

Privacy-1 已按 App API v2 `1.17.0` 完成“可登记、可追踪、可取消”控制面，所有 capability 默认关闭：

- Cloudflare D1 使用不可变策略快照、账号绑定申请、只追加事件、验证尝试、step-up token、申请级状态 token 和幂等命令；密码、原始 token 和导出内容不入库。
- App 使用本人会话读取总览、列表与详情，并分别为导出创建、注销创建和取消执行密码二次验证。注销创建要求会员金币、消息/依法保留、全设备退出三项确认。
- 注销登记成功立即撤销 App/Web 会话并限制账号；D1 约束阻止新互动、收藏、历史、搜索历史、平台话题、会员申请/发放和钱包调整。
- 普通会话失效后，App 仅用系统安全区保存的请求级状态凭证读取、重新验证和取消绑定申请；凭证不能访问其他申请或普通产品 API。
- 注销成功响应丢失时，App 以系统安全区暂存的原幂等标识和发起 Access Token 恢复同一创建结果；服务端只接受被该注销动作撤销的原 session，不创建新申请、不恢复普通会话。密码和 step-up token 不持久化。
- Nuxt `ADM-PRI-01/02` 提供管理员最小化总览、队列和详情；Owner 可领取、开始处理、标记失败、重试或凭证据取消。没有真实制品或不可逆处理证据时不提供“完成”动作。
- Operations-1 只按超过策略 `deadline_at` 且仍非终态的申请生成 `data_rights_overdue` 事件，不复制账号敏感内容。

Privacy-1 本身不包含导出快照、R2 制品、下载凭证、不可逆删除/匿名化、依法保留隔离或完成证明；这些源码已分别由 Privacy-2A/2B 承接，但真实处理仍必须在 OQ-002/OQ-020/OQ-024/OQ-025 等门禁关闭后开放。

### 6.9 Privacy-2A/2B/2C 当前开发实现

- Privacy-2A 已完成 35 类原始白名单、rowid 纳入边界、可恢复 Queue、私有 R2 README/manifest/TAR、重新验证、短期一次性下载票据、KMP 流式保存和两阶段到期清理。
- Privacy-2B 已完成九步前向可恢复注销、逐步零残留核验、七类 `compliance_only` 保留隔离、完成证据与 KMP 本地终态清理；管理员不能人工伪造 completed。
- Privacy-2C 在前 35 类 ordinal 不变的前提下追加 6 类，新制品当前为 41 类；执行器按 artifact 自身 scope 数完成，旧 35-scope 任务可以继续恢复。
- 推荐会话与条目使用集中账号 HMAC 定位，只导出本人可解释字段，`account_hash`、`context_hash`、内部账号 ID、密钥和原始上下文全部排除；稳定密钥是导出与删除的共同 fail-closed 门禁。
- 本轮只完成源码和文档，不执行 migration、配置、构建、测试、模拟器/真机、截图或生产处理；capability 继续默认关闭。

## 7. Acceptance Criteria

- **PDR-AC-001**：Given 用户修改账号昵称和头像，When 保存成功，Then 仅更新 `Account` 展示信息且不创建真人资料或公开投影。
- **PDR-AC-002**：Given 用户关闭个性化，When 在另一设备开始新推荐会话，Then 服务端使用非个性化模式且不读取账号行为信号。
- **PDR-AC-003**：Given 用户关闭营销站内通知，When 发生账号安全事件，Then 必要安全通知仍可见且不被营销开关吞掉。
- **PDR-AC-004**：Given App 1.0 未集成推送，When 导出完成，Then 用户通过站内状态/通知获得结果且流程可完成。
- **PDR-AC-005**：Given 用户申请导出，When 任务完成，Then 包中包含本人依法可得数据，不包含管理员内部备注、授权原件或其他账号的平台话题。
- **PDR-AC-006**：Given 攻击者获得过期导出 URL，When 尝试下载，Then 服务端拒绝且不泄漏包是否仍存在。
- **PDR-AC-007**：Given 同一用户重复提交导出，When 已有有效在途任务，Then 返回该任务或策略限制，不并行生成重复包。
- **PDR-AC-008**：Given 用户确认注销，When Workflow 启动，Then 立即停止新平台话题、互动和运营发放，并撤销会话。
- **PDR-AC-009**：Given 注销存在依法保留数据，When 处理完成，Then 数据与产品查询隔离且不再用于推荐、营销或账号恢复。
- **PDR-AC-010**：Given 注销中途发生部分失败，When 用户再次打开状态页，Then 账号保持受限并显示处理中/支持，不恢复正常功能。
- **PDR-AC-011**：Given 已注销用户使用同一身份重新注册，When 创建新账号，Then 不恢复旧互动、平台话题、会员或金币。
- **PDR-AC-012**：Given 账号被安全限制，When 用户打开“我的”，Then 仍能访问隐私、导出、注销、帮助和申诉入口。
- **PDR-AC-013**：Given 客服没有敏感数据审批，When 尝试查看导出包或平台话题正文，Then 服务端拒绝并记录越权审计。
- **PDR-AC-014**：Given 用户使用屏幕阅读器，When 修改设置并查询导出/注销进度，Then 状态、影响和操作均可理解。
- **PDR-AC-015（Privacy-1）**：Given processing capability 关闭，When 用户查看数据副本申请，Then 页面明确说明当前只登记申请且不显示下载或完成入口。
- **PDR-AC-016（Privacy-1）**：Given 用户未完成三项影响确认或密码二次验证，When 尝试提交注销，Then 服务端拒绝且不创建申请。
- **PDR-AC-017（Privacy-1）**：Given 注销申请创建成功，When 任一旧 App/Web 会话访问普通账号能力，Then 会话失效或账号状态拒绝，且新增受保护业务事实被数据库约束阻断。
- **PDR-AC-018（Privacy-1）**：Given 普通会话已因注销失效，When 用户持有某申请的有效状态凭证，Then 只能查询、再次验证和取消该申请，不能访问其他申请或普通 App API。
- **PDR-AC-019（Privacy-1）**：Given 两个管理员并发更新同一申请，When 后提交者使用旧版本，Then 服务端返回版本冲突且不覆盖先前事实。
- **PDR-AC-020（Privacy-1）**：Given 没有真实导出制品或不可逆处理证据，When 管理员查看申请详情，Then 后台不提供完成动作。
- **PDR-AC-021（Privacy-1）**：Given 服务端已创建注销申请并撤销会话但成功响应丢失，When App 使用原幂等标识和发起 Access Token 重试，Then 只返回同一申请及其状态凭证，不创建第二个申请或恢复普通权限。
- **PDR-AC-022（Privacy-2C）**：Given 升级前已经存在 35-scope 导出任务，When 新版执行器继续处理，Then 在原第 35 类后进入 finalizing，不要求新增分类且不生成错误的部分制品。
- **PDR-AC-023（Privacy-2C）**：Given 新建 41-scope 导出包含本人推荐证据，When 生成 NDJSON，Then 会话与条目通过账号 HMAC 正确归属，且账号摘要、上下文摘要、密钥和其他账号证据均不进入副本。

## 8. Out of Scope

- 普通观看者创建或编辑公开真人资料、提交真人认领。
- App 1.0 在线购买、退款、充值、提现、礼物和系统推送设置。
- 允许用户修改或删除必要的安全、账务、审计和法律证据原始历史。
- 承诺所有数据立即物理删除而不考虑目标地区合法保留义务。
- 把 Web 地区默认营销状态自动解释为 App 用户明示同意。
- 家庭账号、账号转让、匿名账号和企业数据管理门户。
