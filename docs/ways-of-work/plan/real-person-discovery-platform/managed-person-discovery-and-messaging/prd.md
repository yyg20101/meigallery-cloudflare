## 3. Goal

### Problem

现有 MeiGallery 数据以图库为中心，无法直接表达“真人主体、公开资料、运营归属和消息接收方”。观看者希望按地区、热度和偏好发现真人并进行私信，但当前真人尚未本人入驻，因此必须准确区分公开资料、观看者账号和实际消息接收主体。

### Solution

建立由管理员准入的真人资料供给、可解释的个性化发现和单向互动体系。普通账号只作为观看者；有效心享会员可从真人详情直接创建和发送私信，到期后既有会话只读。未认领真人的会话进入管理员代运营工作台，入口和会话持续披露实际接收主体；未来真人完成认领后，新会话可切换至本人接收。

### Impact

- 将 MeiGallery 的人物素材升级为可运营、可认证、可推荐的真人资料。
- 支持地区、热度和行为偏好推荐，同时保留非个性化浏览入口。
- 形成喜欢、关注、收藏到会员私信的清晰转化路径。
- 在真人尚未入驻时提供可审计的互动服务，并避免身份误导。
- 为未来真人认领和本人运营保留平滑切换能力。

## 4. User Personas

| Persona | 目标 | 约束与关注点 |
|---------|------|--------------|
| 普通观看者 | 发现、喜欢、关注和收藏真人 | 不创建公开资料，不能发起私信 |
| 心享会员 | 向感兴趣的真人资料发起私信 | 受等级 entitlement、频控和安全规则约束 |
| 内容管理员 | 导入、认证并发布真人资料 | 必须核实来源、授权、内容质量和展示状态 |
| 代运营管理员 | 接收并处理未认领真人的会话 | 以平台运营身份回复，操作全量审计 |
| 审核/客服人员 | 处理举报、申诉和会话异常 | 仅按最小权限查看必要证据 |
| 未来入驻真人 | 认领资料并接收后续互动 | 必须完成身份、授权和账号安全核验 |

## 5. User Stories

- 作为观看者，我想按地区、热度、最新和分类浏览真人，以便主动探索感兴趣的内容。
- 作为观看者，我想让系统参考我的喜欢、关注、收藏和浏览行为，以便推荐更符合偏好的真人。
- 作为观看者，我想关闭个性化推荐或清除相关记录，以便控制数据使用。
- 作为观看者，我想分别管理喜欢、关注和收藏，以便表达不同强度的兴趣。
- 作为普通观看者，我想在点击私信时看到明确的会员要求和服务说明，以便决定是否购买。
- 作为心享会员，我想不经双方匹配直接创建私信，以便使用会员互动权益。
- 作为心享会员，我想知道消息由真人本人还是平台运营接收和回复，以便正确理解互动对象。
- 作为内容管理员，我想只有认证且发布的真人进入所有公开列表，以便保证资料可信。
- 作为代运营管理员，我想看到分配队列、会话上下文和响应时限，以便稳定处理消息。
- 作为审核人员，我想按举报查看必要的资料和会话证据，以便处理风险且不过度访问隐私。
- 作为未来入驻真人，我想完成认领后接收新的私信，以便开始本人运营。

## 6. Requirements

### Functional Requirements

#### 真人资料准入与状态

- **MPM-FR-001**：真人资料只能由管理员上传、MeiGallery 导入，或由外部主体提交后经管理员审核创建。
- **MPM-FR-002**：每个真人资料必须关联稳定的 `personId`，并记录内容来源、授权依据、认证状态、运营模式、展示状态和审计历史。
- **MPM-FR-003**：公开状态至少包括草稿、待审核、已认证、已发布、已暂停、已归档；只有同时满足 `verified + published` 的资料可以出现在公开入口。
- **MPM-FR-004**：认证和发布必须是可分离权限；撤销认证、暂停或归档后，资料应立即从推荐、列表、搜索和分享落地页移除。
- **MPM-FR-005**：普通注册账号不得创建、认领或自动获得公开真人资料，也不得因头像、昵称或地区与真人资料相似而建立关联。
- **MPM-FR-006**：真人详情必须展示管理员配置且审核通过的名称/展示名、地区范围、标签、职业、简介、媒体、认证标识和运营说明；不得公开精确住址或实时位置。

#### 发现、推荐与搜索

- **MPM-FR-007**：首页至少提供推荐、附近地区、热门、最新和关注更新入口；“附近地区”只使用城市或配置的模糊区域，不展示精确距离轨迹。
- **MPM-FR-008**：推荐候选集只能包含已认证且已发布的真人，并支持地区、标签、职业、风格、内容热度、时效性和观看者行为信号。
- **MPM-FR-009**：推荐排序不得把会员等级或消费金额作为真人认证真实性的信号，也不得承诺认识、回复或线下见面。
- **MPM-FR-010**：用户可以切换至非个性化排序；账号设置提供个性化推荐开关、行为记录清除和隐私说明。
- **MPM-FR-011**：搜索支持展示名、地区、职业和标签；筛选项与可保存条件数量由会员 entitlement 控制，但基础搜索向登录用户开放。
- **MPM-FR-012**：列表卡片需支持封面、认证标识、地区、核心标签、热度/更新状态和快捷互动；不得显示无法证明的“在线”“正在输入”或精确距离。

#### 喜欢、关注、收藏与历史

- **MPM-FR-013**：喜欢、关注、收藏为三个独立的单向关系，均不触发配对、匹配、通知对方已互相喜欢或用户间聊天。
- **MPM-FR-014**：喜欢用于轻量偏好信号；关注用于接收内容更新；收藏支持文件夹管理。三类操作必须幂等且支持撤销。
- **MPM-FR-015**：浏览历史默认仅账号本人可见，支持逐条删除和全部清除；历史保留时长可由会员 entitlement 配置。
- **MPM-FR-016**：被暂停或归档的真人资料不得继续出现在推荐中；已有收藏显示不可用状态，并隐藏受保护媒体。

#### 私信资格与建会话

- **MPM-FR-017**：只有持有有效 `direct_message.create` entitlement 的心享会员可以创建新私信，不要求真人同意、双方喜欢或匹配。
- **MPM-FR-018**：服务端必须同时校验会员有效期、新会话额度、目标资料状态、账号安全状态、拉黑关系和频率限制；客户端按钮状态不构成授权。
- **MPM-FR-019**：同一观看者与同一真人默认复用一条有效会话；重复请求通过幂等键返回既有会话，不重复消耗额度。
- **MPM-FR-020**：普通用户点击私信时展示心享会员权益页；会员额度不足时展示明确原因、恢复时间和升级入口，不创建空会话。
- **MPM-FR-021**：新会话首屏必须展示接收模式：`平台运营接收` 或 `真人本人接收`，并提供“了解消息服务”入口。

#### 管理员代运营会话

- **MPM-FR-022**：未认领真人的所有新会话进入代运营队列，并根据真人、地区、语言、班次和负载分配给有权限的管理员。
- **MPM-FR-023**：管理员回复在用户侧统一显示为“平台运营回复”，可以同时显示客服昵称，但不得使用真人头像、口吻标识或虚假状态使用户误认为真人本人回复。
- **MPM-FR-024**：会话页需持续展示当前接收主体；接收模式发生变化时生成不可删除的系统消息，不依赖一次性弹窗。
- **MPM-FR-025**：系统记录每条管理员消息的实际操作员、代运营身份、会话、时间、客户端和审核结果；实际操作员信息仅供授权后台和审计使用。
- **MPM-FR-026**：管理员不得伪造真人已读、正在输入、在线或位置状态。已读回执只代表实际接收主体已查看。
- **MPM-FR-027**：工作台支持待分配、处理中、待用户回复、已关闭、已升级和安全冻结状态，以及转派、协作备注和响应时限。
- **MPM-FR-028**：内部备注与用户消息物理或逻辑隔离，任何客户端 API 不得返回内部备注。

#### 消息能力与安全

- **MPM-FR-029**：App 1.0 用户消息支持文本、表情和系统消息；图片在内容审核 Feature 通过后启用，语音、视频、文件和位置不在 1.0 范围。
- **MPM-FR-030**：发送接口必须使用幂等键、频率限制、内容安全检查和会话状态检查；失败时不制造虚假送达或已读状态。
- **MPM-FR-031**：观看者可以举报消息/真人、拉黑真人、静音会话和关闭会话；管理员可以升级审核，但不得删除账务或安全证据。
- **MPM-FR-032**：系统必须提供消息失败、审核中、发送受限、网络重试、账号冻结和会话关闭等明确状态。
- **MPM-FR-033**：删除账号、数据导出和执法留存必须遵循数据权利与法定义务；前台“删除会话”只控制用户可见性，不承诺立即删除必要审计证据。

#### 真人认领与交接

- **MPM-FR-034**：认领流程至少包含申请、身份核验、权利/授权复核、账号安全检查、管理员批准和绑定生效。
- **MPM-FR-035**：认领成功后，默认仅将新建会话路由至真人本人；已有代运营会话继续由平台处理，除非双方同意且合规审批通过。
- **MPM-FR-036**：交接时必须向观看者展示新接收主体并生成系统消息；真人本人不得自动看到交接前的历史私信和内部备注。
- **MPM-FR-037**：认领被撤销、真人退出或账号受限时，系统可暂停新私信或切回平台运营，所有变化写入审计日志。

#### 埋点与运营指标

- **MPM-FR-038**：前台至少记录合规聚合后的列表曝光、详情访问、喜欢、关注、收藏、私信门槛曝光、会话创建和举报事件。
- **MPM-FR-039**：后台至少统计资料审核时长、发布供给量、推荐覆盖、私信创建率、首次响应时长、关闭率、举报率和认领转化。
- **MPM-FR-040**：指标不得以公开排行榜形式暴露观看者消费金额、消息数量或敏感偏好。
- **MPM-FR-041**：只有持有有效 `direct_message.send` entitlement 的心享会员可以发送私信；会员到期后既有会话保留为只读。

### Non-Functional Requirements

- **MPM-NFR-001**：公开列表和搜索查询必须在服务端统一应用认证、发布和安全过滤，不能由客户端过滤未发布资料。
- **MPM-NFR-002**：推荐响应必须返回排序模式和可解释理由代码，支持规则版本、灰度、回滚和审计。
- **MPM-NFR-003**：消息写入采用客户端消息 ID 和服务端幂等键；重试不得产生重复消息、重复额度扣减或重复通知。
- **MPM-NFR-004**：消息正文、身份证明和内部备注不得写入通用日志、分析事件或崩溃报告。
- **MPM-NFR-005**：后台会话访问遵循最小权限、短期授权和操作审计；批量导出默认关闭。
- **MPM-NFR-006**：列表、详情和会话提供加载、空、错误、离线、已下架、无权限和安全受限状态。
- **MPM-NFR-007**：关键按钮、卡片、消息气泡和接收主体说明支持屏幕阅读器、动态字体、键盘导航和高对比度。
- **MPM-NFR-008**：服务端可在不升级客户端的情况下调整排序权重、筛选目录、会话额度、频控和运营披露文案；新交互能力仍需客户端版本支持。

## 7. Acceptance Criteria

- **MPM-AC-001**：Given 一个普通注册账号，When 完成注册并上传头像，Then 该账号仍不会生成公开真人资料或进入发现列表。
- **MPM-AC-002**：Given 一个已导入但未认证的真人，When 访问推荐、热门、地区、搜索或分享链接，Then 前台均不可展示该真人。
- **MPM-AC-003**：Given 一个已认证且发布的真人，When 观看者按地区和标签筛选，Then 结果仅包含满足公开状态和筛选条件的资料。
- **MPM-AC-004**：Given 观看者喜欢并关注同一真人，When 真人没有登录账号，Then 系统分别记录单向关系且不创建匹配或聊天。
- **MPM-AC-005**：Given 普通观看者点击“私信”，When 服务端确认无有效 entitlement，Then 展示会员权益和实际接收主体说明，且数据库不存在新会话。
- **MPM-AC-006**：Given 有效会员重复提交同一建会话请求，When 幂等键相同，Then 返回同一会话且只消耗一次额度。
- **MPM-AC-007**：Given 目标真人未认领，When 会员发出消息并收到回复，Then 用户侧显示“平台运营接收/回复”，后台可追溯实际操作员。
- **MPM-AC-008**：Given 管理员打开代运营会话，When 尝试发送内部备注到用户消息通道，Then 服务端拒绝且产生安全审计事件。
- **MPM-AC-009**：Given 真人资料被暂停，When 用户从收藏或旧通知打开详情，Then 展示不可用状态且不能创建新私信。
- **MPM-AC-010**：Given 用户关闭个性化推荐并清除行为记录，When 再次请求首页，Then 使用非个性化模式且返回相应排序理由。
- **MPM-AC-011**：Given 真人完成认领，When 新观看者创建私信，Then 会话进入本人收件箱并显示“真人本人接收”；既有会话历史不自动暴露。
- **MPM-AC-012**：Given 用户举报某条消息并拉黑真人，When 操作成功，Then 新消息发送被阻止，举报进入审核队列且证据可审计。

## 8. Out of Scope

- 普通用户创建公开交友资料或申请进入发现列表。
- 双方喜欢、打招呼、匹配、解除匹配和匹配成功动画。
- 普通用户之间的聊天、群聊、随机聊天或匿名聊天。
- 管理员未披露身份地模仿真人本人回复。
- 首版语音消息、视频消息、文件、实时位置、音视频通话和直播。
- 线下见面撮合、回复时效承诺、真人一定回复或关系结果保证。
- 认领时自动向真人开放历史代运营私信。
- 公开展示观看者行为、消费或敏感偏好的排行榜。
