## 3. Goal

### Problem

现有 MeiGallery 的人物内容主要以图库、标签和媒体存在，不能证明每个图库等同一个真人，也不能默认现有展示授权覆盖独立 App、推荐和互动。管理员还需要直接上传新的真人资料。如果上传、导入、去重、授权证据和失败重试没有统一规则，可能产生重复真人、无授权公开、legacy 强耦合和不可回滚的数据污染。

### Solution

建立统一“来源登记 → 私有暂存 → 校验 → 候选匹配 → 生成真人/资料草稿 → 人工补全 → 提交审核”流程。管理员上传和 MeiGallery 导入都只生成不可公开的候选或草稿，使用稳定来源映射、逐项幂等和追加审计。媒体和授权证据进入私有存储，只有下游认证与发布审核通过后才生成公开投影。

### Impact

- 将合法的 MeiGallery 人物素材转为可审计、可回滚的真人资料供给。
- 降低重复人物、错误合并、授权缺失和批量失败造成的运营风险。
- 支持管理员单条上传与批量迁移使用同一数据质量规则。
- 保证 App 永远不直接读取 legacy 表或未审核导入结果。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 内容编辑 | 上传单个真人和媒体并形成草稿 | 字段清晰、进度可保存、错误可修复 |
| 迁移管理员 | 批量选择 MeiGallery 内容生成候选 | 幂等、逐项结果、映射和可回滚 |
| 权利/认证审核员 | 查看来源与授权证据 | 证据完整、范围明确、敏感材料隔离 |
| Owner | 配置来源和批次策略 | 最小权限、批次控制、风险概览 |
| 审计人员 | 追溯谁导入了什么 | 输入、映射、前后状态和失败证据 |
| 观看者 | 只看到审核发布结果 | 导入中、失败和草稿永不公开 |

## 5. User Stories

- 作为内容编辑，我想手动创建真人草稿并上传审核后的展示素材，以便新增供给。
- 作为内容编辑，我想暂存未完成资料，以便稍后补充授权和标签。
- 作为迁移管理员，我想按 MeiGallery 图库、标签或批次筛选候选，以便控制迁移范围。
- 作为迁移管理员，我想在执行前看到重复、授权缺失和媒体问题预检，以便避免污染正式数据。
- 作为迁移管理员，我想只重试失败条目，以便不重复创建成功真人和媒体。
- 作为审核员，我想看到每个字段和媒体来自哪里，以便判断证据是否覆盖 App 用途。
- 作为审核员，我想阻止系统自动合并疑似同名真人，以免错误关联现实主体。
- 作为 Owner，我想暂停或撤销未发布批次，以便在发现来源问题时快速止损。
- 作为审计人员，我想查看输入哈希、映射、操作者和输出，以便还原任何导入结果。

## 6. Requirements

### 6.1 Functional Requirements

#### 来源与对象边界

- **SRC-FR-001**：App 真人资料来源只允许 `admin_upload`、`meigallery_import` 和未来经审核的 `external_submission`；App 1.0 只验收前两种。
- **SRC-FR-002**：每次创建必须先登记来源、来源系统、来源实体 ID、导入批次、操作者和时间；无来源记录不得创建真人草稿。
- **SRC-FR-003**：`Gallery`、`Person` 和 `PersonProfile` 必须分离；一个图库不能因标题或文件夹名称自动等同一个真人。
- **SRC-FR-004**：一个真人可关联多个图库，一个图库涉及多个真人时必须逐一建立主体/媒体权利关系，无法拆分时保持待审核且不可公开。
- **SRC-FR-005**：普通用户、会员账号、头像和昵称不得作为真人供给源；账号与真人的未来绑定只能通过认领流程。
- **SRC-FR-006**：所有草稿使用 v2 stable ID；legacy 自增 ID 只保存在受限映射表，不作为公开 API ID。

#### 管理员手动上传

- **SRC-FR-010**：有 `person.source.create` 权限的管理员可以创建真人主体候选和公开资料草稿；创建时不得选择 `published`。
- **SRC-FR-011**：草稿必填最小字段包括来源说明、展示名候选、地区粒度、内容用途、运营模式和至少一个合法联系人/权利证据引用；法定姓名如非公开必要不得进入展示字段。
- **SRC-FR-012**：媒体上传使用私有暂存区和服务端签发的受限上传凭证；客户端/浏览器不得持有 R2 长期写凭证。
- **SRC-FR-013**：上传完成后校验文件签名、MIME、扩展名、尺寸、大小、恶意内容、重复哈希和必要元数据；仅通过扩展名不得视为有效。
- **SRC-FR-014**：发布派生资源前移除 EXIF、精确位置和非必要设备信息；原始文件与派生文件使用不同对象和权限。
- **SRC-FR-015**：编辑器支持保存草稿、自动保存恢复、删除未提交媒体、调整展示顺序和预览审核后效果；预览不得生成公开 URL。
- **SRC-FR-016**：删除未发布草稿使用可恢复状态和审计；已进入审核或被证据引用的对象不能直接物理删除。

#### MeiGallery 候选选择与预检

- **SRC-FR-020**：迁移管理员可按图库 ID、标签、地区、时间和显式选择建立导入批次；默认不允许“全库自动公开”。
- **SRC-FR-021**：导入前必须生成只读预检，至少统计候选图库、媒体、疑似主体、已有映射、授权完整、授权未知、媒体失败、重复和跳过数量。
- **SRC-FR-022**：现有 Web 可公开展示不等于授权覆盖独立 App、推荐或互动；用途范围未知或过期的条目必须标记 `authorization_required`。
- **SRC-FR-023**：预检必须展示字段映射和 taxonomy 归一化结果；未知标签可以生成待审核候选，但不得直接进入生产公开 taxonomy。
- **SRC-FR-024**：疑似重复使用 stable source mapping、媒体哈希和人工可理解候选提示；系统不得仅以展示名、脸部相似或标签自动合并真人。
- **SRC-FR-025**：导入任务启动前展示影响预览并要求原因；高风险或大批次是否双人复核由 OQ-008 的最终策略控制。

#### 批量处理与逐项结果

- **SRC-FR-030**：每个导入任务包含不可变输入快照、schema 版本、映射版本、操作者、幂等键和内容哈希。
- **SRC-FR-031**：每个条目独立处理，单项失败不得阻塞其他有效条目，也不得回滚已经成功生成的其他草稿。
- **SRC-FR-032**：重复执行同一任务/条目只返回原输出或安全重试失败步骤，不得重复创建 `Person`、`PersonProfile`、媒体、证据或映射。
- **SRC-FR-033**：条目状态至少包括 `queued`、`validating`、`needs_input`、`ready`、`creating_draft`、`succeeded`、`failed`、`skipped`、`cancelled`。
- **SRC-FR-034**：失败结果必须包含用户可执行错误代码、阶段和修复建议；不得把 Token、私有对象 key、证件或内部堆栈展示给普通管理员。
- **SRC-FR-035**：任务可暂停新条目、取消未开始条目、重试可重试失败和导出脱敏结果；已经成功的草稿通过独立撤销流程处理。
- **SRC-FR-036**：任务完成后生成数量、哈希、映射、失败、跳过、待补证和输出草稿对账报告。

#### 草稿生成与映射

- **SRC-FR-040**：首次确认新主体时生成 `Person`；展示版本生成 `PersonProfile` 草稿；图库通过 `profile_galleries` 关联，不复制业务身份。
- **SRC-FR-041**：如果来源实体已有有效 v2 映射，导入必须进入“更新候选”或“跳过”，不得静默创建第二个主体。
- **SRC-FR-042**：更新候选展示来源版本与当前草稿差异，管理员逐字段选择或按批准规则合并；已发布资料不被批量导入直接覆盖。
- **SRC-FR-043**：媒体以来源哈希和目标 ID 建立映射；重复文件可复用经验证的存储对象，但每个用途权利关系仍独立记录。
- **SRC-FR-044**：所有导入输出默认 `verification_status=unverified`、`publish_status=draft`，不写公开投影、不进入搜索索引。
- **SRC-FR-045**：系统为草稿生成完整性检查清单，包括来源、授权、认证、必填字段、媒体审核、taxonomy、运营归属和发布门禁。

#### 授权证据与敏感数据

- **SRC-FR-050**：授权记录至少包含主体、用途范围、适用渠道/地区、证据引用、有效期、状态和记录人；不以自由文本“已授权”替代结构化范围。
- **SRC-FR-051**：身份和授权证据存放在私有、分权存储，内容编辑只看到完成工作所需摘要；公开资料和日志不得返回证件原件。
- **SRC-FR-052**：证据过期、撤回或争议时，关联草稿进入阻断状态；若已有关联发布内容则触发下游暂停 Workflow。
- **SRC-FR-053**：目标用途超出现有授权范围时必须补充证据或排除相应媒体/字段，不能由 Owner 强制绕过而不留审批结论。
- **SRC-FR-054**：证据保留和删除以 OQ-020 最终结论为准；删除前保持引用完整性并记录合法保留依据。

#### 后台页面与权限

- **SRC-FR-060**：后台至少提供来源列表、上传编辑器、MeiGallery 候选选择、预检、任务进度、条目详情、差异合并、证据摘要和输出草稿入口。
- **SRC-FR-061**：内容编辑可以创建和编辑草稿但不能认证或发布；迁移管理员只能处理授权来源范围内的批次。
- **SRC-FR-062**：Owner 配置来源适配器和字段映射；任何配置变化版本化，不影响运行中的不可变批次。
- **SRC-FR-063**：所有创建、上传、删除、映射、重试、取消和证据变更记录操作者、原因、前后状态和请求 ID。

#### 埋点与运营指标

- **SRC-FR-070**：供给指标至少包括任务耗时、条目成功率、待补证率、重复率、媒体失败率、草稿完成率和从草稿到发布的周期。
- **SRC-FR-071**：分析事件不得包含证件、授权原文、私有媒体 URL、个人联系方式或导入 Token。
- **SRC-FR-072**：重复、授权未知和媒体失败必须可按来源批次聚合，以便决定是否暂停某来源。

### 6.2 主流程

管理员上传：

```text
创建来源记录 → 创建真人/资料草稿 → 私有上传媒体
→ 文件与元数据校验 → 补充授权/标签/运营归属
→ 完整性检查 → 提交认证审核
```

MeiGallery 导入：

```text
选择范围 → 生成不可变预检 → 处理重复/授权问题
→ 确认批次 → 逐项生成候选/草稿 → 对账报告
→ 人工补全 → 提交认证审核
```

### 6.3 权限矩阵

| 操作 | 内容编辑 | 迁移管理员 | 认证审核 | Owner | 审计只读 |
|------|----------|------------|----------|-------|----------|
| 手动创建/编辑草稿 | 允许 | 按授权范围 | 只读 | 允许 | 只读 |
| 建立 MeiGallery 批次 | 不允许 | 允许 | 只读 | 允许 | 只读 |
| 查看敏感证据摘要 | 最小摘要 | 最小摘要 | 允许 | 按需 | 审批后只读 |
| 认证/发布 | 不允许 | 不允许 | 由下游权限决定 | 由下游权限决定 | 不允许 |
| 修改来源适配器 | 不允许 | 不允许 | 不允许 | 允许 | 只读 |

### 6.4 异常与恢复矩阵

| 异常 | 处理 | 是否可自动重试 |
|------|------|----------------|
| 来源不可达 | 暂停新拉取，保留任务输入 | 是，指数退避 |
| 授权未知/过期 | `needs_input`，阻止草稿提交 | 否，需人工补证 |
| 疑似重复 | 展示候选差异，禁止自动合并 | 否，需人工决定 |
| 单个媒体失败 | 条目标记部分失败，其他条目继续 | 视错误类型 |
| 文件类型/签名不符 | 隔离并拒绝 | 否 |
| 任务重复提交 | 返回原任务或幂等冲突 | 不创建新结果 |
| 运行中配置改变 | 当前任务继续使用快照版本 | 新任务使用新版本 |

### 6.5 Non-Functional Requirements

- **SRC-NFR-001**：完整批量导入使用 R2 暂存与 Queue/Workflow 异步处理，API 请求不直接承载大包解压和长任务。
- **SRC-NFR-002**：任务和条目具备幂等、断点续跑、有限重试、死信/人工恢复和逐项对账能力。
- **SRC-NFR-003**：私有媒体和证据采用最小权限、短期凭证、静态/传输加密和访问审计。
- **SRC-NFR-004**：任何导入任务失败或关闭 v2 feature flag 都不得影响现有 MeiGallery Web 写路径。
- **SRC-NFR-005**：批量任务容量和并发由配置控制；限流/降级时优先保护现有公开浏览和安全撤权。
- **SRC-NFR-006**：后台列表和表单支持键盘导航、缩放、明确焦点、错误汇总和不依赖颜色的状态。
- **SRC-NFR-007**：导入 schema、taxonomy mapping 和适配器版本兼容；破坏性变化必须新建版本和迁移策略。
- **SRC-NFR-008**：同一批次在相同输入和映射版本下可重现相同校验与映射结果。

### 6.6 实施前门禁

- OQ-006：逐项确认现有 MeiGallery 授权是否覆盖独立 App、推荐和互动。
- OQ-007：冻结认证证据类型和公开声明范围。
- OQ-008：冻结上传、认证、发布和高风险批次的双人分离策略。
- OQ-020/OQ-024：证据保留期、数据位置和跨境结论。

未关闭 OQ-006/OQ-024 前，不得把真实授权证据或生产媒体导入 v2 生产环境。

## 7. Acceptance Criteria

- **SRC-AC-001**：Given 内容编辑手动创建真人，When 保存草稿，Then 资料保持 `unverified + draft` 且所有公开入口不可见。
- **SRC-AC-002**：Given 一个 MeiGallery 图库已公开，When 其 App 用途授权不明确，Then 预检标记待补证且不能进入发布审核通过状态。
- **SRC-AC-003**：Given 一个图库包含多个真人，When 系统无法可靠拆分权利关系，Then 不自动建立单一真人并保持人工处理状态。
- **SRC-AC-004**：Given 两条来源记录展示名相同，When 没有稳定映射或人工确认，Then 系统只提示疑似重复而不自动合并。
- **SRC-AC-005**：Given 同一批次和幂等键重复执行，When 首次已生成草稿，Then 返回原输出且不复制真人、资料、媒体和映射。
- **SRC-AC-006**：Given 批次中一项媒体损坏，When 处理继续，Then 该项失败可修复，其他有效条目仍成功且不会被重复处理。
- **SRC-AC-007**：Given 导入运行时 taxonomy 配置更新，When 任务完成，Then 当前批次仍使用启动快照并可复现映射结果。
- **SRC-AC-008**：Given 媒体含 EXIF 精确位置，When 生成可发布派生资源，Then 派生资源不含该元数据，原件仍受私有权限保护。
- **SRC-AC-009**：Given 管理员没有迁移权限，When 调用批量导入或查看其他来源任务，Then 服务端拒绝且记录越权审计。
- **SRC-AC-010**：Given 授权记录被撤回，When 关联资料仍在草稿或已发布，Then 草稿被阻断，已发布资料触发暂停流程。
- **SRC-AC-011**：Given 管理员取消运行中任务，When 部分条目已成功，Then 未开始条目停止，成功草稿保留并通过独立撤销处理。
- **SRC-AC-012**：Given 审计人员查看任务，When 选择任一条目，Then 可关联输入哈希、来源、映射版本、操作者、输出、错误和时间线。

## 8. Out of Scope

- 爬虫、未经授权的第三方自动采集和从公开网络抓取真人资料。
- 普通用户上传公开媒体、创建真人或直接提交到公开列表。
- 仅凭人脸识别自动确认身份、合并真人或生成认证结论。
- 导入任务直接发布资料或绕过认证/发布审核。
- 把现有 Web 展示权自动解释为独立 App、推荐、互动或商业用途授权。
- App 1.0 视频转码、Cloudflare Stream 生产接入和用户消息媒体处理。
- 真人本人认领和账号绑定。
