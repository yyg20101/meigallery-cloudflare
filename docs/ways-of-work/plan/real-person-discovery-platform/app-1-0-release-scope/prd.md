## 3. Goal

### Problem

产品文档同时规划了真人发现、会员平台话题、在线支付、金币充值、礼物、装扮、推送、真人认领和普通用户桌面端，但当前明确不接入支付和推送，桌面端也未形成真实需求。如果不区分“App 1.0 必须交付”“仅预留长期模型”和“未来必须升级客户端”，研发会把规划能力误认为首发范围，无法准确估时、验收和发布。

### Solution

将 App 1.0 建议范围收敛为“真人发现 + 五级会员站内申请与手动发放 + 平台话题与运营接收 + 管理员金币账本”的可运营闭环，待客户确认后再冻结为实现范围。支付、金币充值、礼物和装扮保留长期 PRD、领域边界与兼容原则，但不创建 1.0 上线依赖；系统推送、商店购买和新的原生能力在未来独立立项，并允许通过正常 App 升级交付。普通用户桌面客户端不作承诺，运营桌面场景继续由 Nuxt 管理后台承担。

### Impact

- 让 1.0 的功能拆分、UI、API、数据、测试和运营使用同一发布边界。
- 在不引入支付和推送复杂度的前提下验证真人供给、发现、会员申请、平台话题和运营接收模式。
- 首版即建立五级会员、entitlement、金币账本和审计，避免未来修改核心身份和权限模型。
- 明确配置可调整与必须升级 App 的边界，避免远程配置承诺不可执行能力。

## 4. User Personas

| Persona | 1.0 目标 | 1.0 主要能力 |
|---------|----------|--------------|
| 访客 | 理解产品、条款和服务边界 | 品牌、必要条款和有限公开预览 |
| 普通观看者 | 发现并保存喜欢的真人 | 推荐、搜索、详情、喜欢、关注、收藏、历史、举报和账号管理 |
| 心享会员 | 使用会员平台话题 | 普通能力 + 发起话题、等级额度和会员筛选 |
| 内容管理员 | 建立可信真人供给 | 导入、认证、发布、暂停、归档、标签和推荐运营 |
| 平台话题运营 | 接收未认领真人相关话题 | 队列、分配、平台身份回复、内部备注和安全升级 |
| 商业运营 | 手动管理首版会员 | 五级目录、entitlement、有效期、手动发放和撤销 |
| 财务/授权管理员 | 处理金币调整 | 加币、扣币、复核、冲正、明细和审计 |
| 审核/客服 | 处理风险与争议 | 举报、拉黑、申诉、必要证据和用户支持 |

## 5. User Stories

- 作为观看者，我想浏览管理员认证并发布的真人，以便发现感兴趣的内容。
- 作为观看者，我想清楚知道五级会员的功能、精确额度和平台话题限制，以便理解不同等级。
- 作为观看者，我想在 App 内提交会员申请并查看处理状态，以便完成从了解权益到等待发放的闭环。
- 作为心享会员，我想不经匹配直接发起由平台接收的话题，以便使用会员权益。
- 作为心享会员，我想持续看到消息由平台运营还是真人本人接收，以便理解真实服务主体。
- 作为用户，我想查看金币余额和每一笔管理员调整说明，以便核对变动原因。
- 作为运营人员，我想手动授予五级会员和有效期，以便在没有在线支付时运营首版。
- 作为管理员，我想加币、扣币和冲正且保留完整明细，以便进行活动、补偿和纠错。
- 作为发布人员，我想知道哪些未来能力不能靠远程配置开启，以便避免发布不可执行的目录或入口。

### Functional Requirements

#### 1.0 必须交付

- **SCP-FR-001**：注册只创建观看者 `Account`，普通账号不得创建公开真人资料。
- **SCP-FR-002**：公开发现只包含 `verified + published` 真人资料，并支持推荐、地区、热门、最新、分类、搜索和筛选。
- **SCP-FR-003**：真人详情支持受控媒体、喜欢、关注、收藏、“发起话题（平台接收）”门槛、举报、拉黑和分享。
- **SCP-FR-004**：首版同时展示心遇、心悦、心知、心契、心耀五级；五级均可由授权管理员手动发放并设置有效期。
- **SCP-FR-005**：五个有效会员等级均具有 `direct_message.create` 和 `direct_message.send` 基础 entitlement；等级可以配置新会话额度和未来附加权益，但不得把等级名称写入授权逻辑。
- **SCP-FR-005A**：五级建议基线为每日新话题 `1/2/4/6/10`、保存筛选 `1/3/6/12/20`、收藏夹 `3/5/10/20/30`；正式 catalog 仍须关闭 OQ-014 后发布。
- **SCP-FR-005B**：用户可选择等级并提交站内会员申请，查看已提交、处理中、待补充、已通过、已拒绝和已取消状态；申请不产生 entitlement，管理员 grant 生效后才获得权限。
- **SCP-FR-006**：无有效会员、会员到期、额度不足、目标不可用、已拉黑或安全受限时不得创建会话。
- **SCP-FR-007**：未认领真人的新会话由平台运营接收和回复；入口、会话列表和会话页持续披露接收主体。
- **SCP-FR-008**：首版用户消息支持文本、表情和系统消息；图片消息在内容审核能力完成前不得启用。
- **SCP-FR-009**：首版提供站内消息、互动、会员/金币和系统安全通知；不依赖 APNs、FCM 或其他系统推送完成核心流程。
- **SCP-FR-010**：管理员可以向任意有效账号加币、扣币、补偿和冲正；只能新增账本分录，用户可查看数量、原因、时间和申诉入口。
- **SCP-FR-011**：金币不具现金价值；首版不提供购买、充值、提现、转账、兑换或消费入口，余额用于迁移、活动、补偿、运营调整和未来能力准备。
- **SCP-FR-012**：Nuxt 管理后台必须覆盖真人供给、认证发布、标签地区、推荐运营、平台话题、举报审核、会员申请与发放、金币调整和审计。
- **SCP-FR-014**：App 1.0 首次业务发布采用限量邀请 Beta；建议在至少 80 个可公开真人资料、3 个地区组和服务时段 1 人在岗 + 1 人备岗的条件下开放。
- **SCP-FR-015**：平台话题队列达到配置容量的 70%/85%/100% 时分别预警、限流或暂停新话题；客户端展示真实繁忙状态，不伪装为会员或额度问题。
- **SCP-FR-013**：账号提供设备、隐私推荐、数据导出、注销、帮助和申诉能力。

#### 仅保留设计、不作为 1.0 上线验收

- **SCP-FR-020**：订单、商店凭证、金币包、退款、礼物、头像框、主页皮肤和聊天皮肤继续保留长期领域模型、PRD 和兼容原则，但 1.0 不要求部署对应生产表、API、SDK、页面或运营商品。
- **SCP-FR-021**：未启用能力不得显示可点击购买入口、虚假价格、余额充值、赠礼或装备成功状态；服务端目录必须通过 capability 控制隐藏。
- **SCP-FR-022**：未来上线商店支付、金币充值、礼物、装扮、图片消息或系统推送前，必须独立完成 Feature PRD、平台适配、安全/商店评审、测试和 App 发版。
- **SCP-FR-023**：真人本人认领及历史会话交接属于后续阶段，不影响 1.0 未认领真人的平台代运营闭环。
- **SCP-FR-024**：普通用户 Windows/macOS 客户端不属于已承诺路线；未来只有在独立需求和成本评审通过后才立项。当前桌面运营需求由 Nuxt 管理后台满足。

#### 远程配置与升级边界

- **SCP-FR-030**：1.0 可以远程调整已支持的五级名称副文案、视觉 token、entitlement 数值、筛选目录、推荐权重、地区、服务说明、频控和功能开关。
- **SCP-FR-031**：远程配置不得启用客户端未实现的页面、支付流程、系统推送、消息媒体类型、相机/相册、视频播放方式或其他原生能力。
- **SCP-FR-032**：客户端收到未知 capability、entitlement、商品类型或枚举时必须安全忽略，不崩溃、不显示伪入口、不扩大权限。
- **SCP-FR-033**：未来能力需要新增原生依赖、权限、页面或审核声明时，允许并要求正常升级 App，不以“无需升级”为发布目标。

### Non-Functional Requirements

- **SCP-NFR-001**：1.0 的权限、会员有效期、会话资格、金币余额和管理员操作均以服务端权威状态为准。
- **SCP-NFR-002**：五级会员、会话、消息、金币账本和 capability 使用版本化 schema，并兼容未知字段。
- **SCP-NFR-003**：不因支付、推送和虚拟商品未启用而引入空页面、失效按钮或不可完成的核心路径。
- **SCP-NFR-004**：管理员手动会员和金币操作必须具备最小权限、强认证、原因、审计和高风险复核。
- **SCP-NFR-005**：Android/iOS 在无系统推送、无支付 SDK 的构建中完成全部 1.0 核心 E2E。
- **SCP-NFR-006**：页面覆盖加载、空、错误、离线、无权限、下架、额度不足和安全受限状态，并满足动态字体与屏幕阅读器要求。

## 7. Acceptance Criteria

- **SCP-AC-001**：Given 一个普通账号，When 浏览和上传账号头像，Then 不会生成公开真人资料或进入发现列表。
- **SCP-AC-002**：Given 五级会员目录，When 1.0 用户打开会员页，Then 可以查看全部五级明确权益，但看不到在线支付或自动续订入口。
- **SCP-AC-003**：Given 管理员手动授予任意一个有效心享等级，When 用户创建并发送平台话题消息，Then 服务端按 `direct_message.create`、`direct_message.send` 和额度判断，而不是按等级名称判断。
- **SCP-AC-004**：Given 未认领真人，When 会员创建并使用会话，Then 用户持续看到“平台运营接收/回复”，管理员操作可审计。
- **SCP-AC-005**：Given App 未取得系统推送权限或未集成推送 SDK，When 用户在 App 内刷新通知和会话，Then 仍可完成全部核心旅程。
- **SCP-AC-006**：Given 用户打开钱包，When 管理员完成加币、扣币或冲正，Then 用户看到权威余额和可理解明细，但找不到充值、提现、赠礼或装扮购买入口。
- **SCP-AC-007**：Given 服务端误下发未来商品或未知 entitlement，When 1.0 客户端解析，Then 安全忽略且不出现可执行入口、不崩溃、不获得额外权限。
- **SCP-AC-008**：Given 未来决定开放支付、推送、礼物或装扮，When 评审发布计划，Then 必须包含新 Feature PRD、客户端版本门槛和应用商店/安全验收，不能仅修改远程配置。
- **SCP-AC-009**：Given 普通用户桌面客户端没有立项，When 运营人员在桌面处理资料、平台话题、会员和金币，Then 通过 Nuxt 管理后台完成，不阻塞 App 1.0 发布。
- **SCP-AC-010**：Given 无有效会员的观看者，When 提交会员申请，Then 申请进入后台队列但不获得话题权限；只有管理员 grant 生效后权限才可用。
- **SCP-AC-011**：Given 运营队列达到满载阈值，When 用户尝试发起新话题，Then 系统暂停创建并展示可恢复说明，历史可见能力不被误撤销。
- **SCP-AC-012**：Given App 1.0 逐页清单，When 执行需求一致性校验，Then 49 个移动端页面、43 个管理后台页面、54 个 P0、31 个 P1 和 7 个 P2 与页面目录完全一致。
- **SCP-AC-013**：Given 两份客户确认 DOCX，When 按 Page ID 检查功能说明和图片，Then 92 个页面均包含需求追踪键和默认原型，54 个 P0 页面均包含关键状态原型，总计 146 张且无错配。
- **SCP-AC-014**：Given 一个未来能力需求，When 检查 App 1.0 页面和原型，Then 该能力只出现在未来范围说明中，不存在可执行入口、占位按钮或暗示已可用的文案。

## 8. Out of Scope

- App 1.0 在线购买会员、自动续订、恢复购买和商店退款。
- App 1.0 金币充值、用户间转账、提现和消费。
- App 1.0 礼物、头像框、主页皮肤和聊天皮肤购买或装备。
- App 1.0 APNs、FCM 或其他系统推送。
- App 1.0 图片、语音、视频、文件、位置消息和音视频通话。
