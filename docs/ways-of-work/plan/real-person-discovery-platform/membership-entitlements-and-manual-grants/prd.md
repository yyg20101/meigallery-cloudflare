## 3. Goal

### Problem

App 1.0 需要同时展示五级会员，并让所有有效会员都能发起平台话题。首版不接入在线支付，用户只能提交会员申请，最终由管理员审核和手动发放；如果仍沿用旧 Web 的 `vip/svip` 名称或在客户端按等级名写条件，未来增加权益、调整额度、迁移旧会员或扩展第五级以后都会迫使客户端重构，并容易出现会员显示、实际权限和后台记录不一致。

### Solution

建立“展示目录、用户申请、会员发放、权限定义、权限解析”五层模型。心遇、心悦、心知、心契、心耀只承担品牌展示；服务端使用数值 `rank` 和有类型的 entitlement 进行授权。用户申请仅建立待处理请求，不产生任何会员权限；管理员通过可预览、可审计、可撤销的流程审核申请或直接发放有效期会员，客户端读取权威权限快照并展示明确额度、期限、获取方式和限制。

### Impact

- 五级会员在 App 1.0 可完整展示、手动发放、到期和撤销。
- 平台话题与后续功能只依赖稳定 entitlement，不依赖中文名称或 UI 样式。
- 旧会员迁移、临时补偿和运营发放具有一致记录和可追溯来源。
- 后续增加礼物、装扮、系统推送等能力时，可以复用权限框架，但必须遵守客户端 capability 门槛。
- 权益争议可以还原当时目录版本、发放依据和实际解析结果。

## 4. User Personas

| Persona | 目标 | 约束与关注点 |
|---------|------|--------------|
| 普通观看者 | 了解五级会员、提交申请并查看进度 | 1.0 无在线购买，申请不等于获得会员 |
| 心享会员 | 查看当前等级、期限、额度和可用权益 | 到期、额度耗尽和权限变化必须可理解 |
| 会员运营 | 为指定账号发放、续期或撤销会员 | 只能在授权范围内操作并填写原因 |
| 复核人员 | 复核批量或高风险会员操作 | 发起人与复核人必须分离 |
| 客服人员 | 解释权益、处理发放异常和申诉 | 只能查看必要摘要，不能直接扩大权限 |
| 审计人员 | 还原目录、grant 和权限变化 | 历史不可被覆盖或删除 |

## 5. User Stories

- 作为观看者，我想同时比较五级会员的具体权益，以便理解差异，而不是只看到“更多特权”。
- 作为观看者，我想知道会员当前只能由平台发放，以免误以为可以在线购买。
- 作为观看者，我想选择意向等级、填写联系说明并查看申请进度，以便理解平台是否已处理。
- 作为会员，我想看到生效时间、到期时间、新会话剩余额度和重置时间，以便正确使用权益。
- 作为会员，我想在权限变化时收到站内通知，并在多设备上得到一致结果。
- 作为会员运营，我想先预览发放后的等级、期限和权益变化，再提交操作，以免误发。
- 作为会员运营，我想选择立即发放、续期、替换、预约生效或撤销，以便处理不同业务场景。
- 作为复核人员，我想看到发起人、目标账号、变更前后、原因和风险提示，以便独立判断。
- 作为客服，我想按账号和业务单号查询发放历史，以便解释到期、撤销或额度不足。
- 作为审计人员，我想恢复任意时间点使用的目录版本和解析规则，以便验证当时授权是否正确。

## 6. Requirements

### 6.1 Functional Requirements

#### 五级展示目录

- **MBR-FR-001**：App 1.0 会员目录必须同时包含心遇、心悦、心知、心契、心耀五级，对应唯一且递增的 `rank=10/20/30/40/50`；免费状态使用 `rank=0`，不作为可发放会员等级。
- **MBR-FR-002**：等级名称、颜色、徽章和主文案只用于展示，不得参与 API、数据库或客户端权限判断。
- **MBR-FR-003**：目录版本发布后不可原地修改；调整名称、说明、权益或顺序时创建新版本，记录生效时间、适用地区、最低客户端版本、发布人和回滚目标。
- **MBR-FR-004**：会员页必须显示每级获取方式、有效期规则、具体 entitlement/额度、与上一级差异、平台话题实际接收主体、限制和“不保证回复或关系结果”说明。
- **MBR-FR-005**：App 1.0 不显示在线价格、购买、续订、自动续费、退款或恢复购买入口；获取方式统一表达为“提交申请，由平台审核后发放”，并提供申请进度和帮助入口。
- **MBR-FR-006**：五级有效会员均配置 `direct_message.create=true` 和 `direct_message.send=true`。建议基线如下，全部属于 OQ-014 待客户确认值，不得在确认前作为正式售卖承诺：心遇/心悦/心知/心契/心耀每日新话题分别为 1/2/4/6/10 个，保存筛选分别为 1/3/6/12/20 个，收藏夹分别为 3/5/10/20/30 个；高级筛选分别为无/基础/完整/完整/完整。历史保留期等其余权益继续配置化，不在本轮擅自冻结。
- **MBR-FR-007**：高等级默认继承低等级权限；若某项不继承，必须在 entitlement 定义中显式声明合并策略，不能依靠名称推断。

#### Entitlement 定义与解析

- **MBR-FR-008**：每项 entitlement 必须具有稳定 key、值类型、schema 版本、默认安全值、合并策略、周期规则、客户端 capability 和用户可见说明。
- **MBR-FR-009**：值类型至少支持布尔、整数额度、枚举、集合、时间窗和周期重置；未知类型或未知 key 在旧客户端安全忽略，不得扩大权限。
- **MBR-FR-010**：App 1.0 至少定义 `direct_message.create`、`direct_message.send`、`direct_message.new_threads_per_day`、`discovery.filter_tier`、`discovery.saved_filters`、`history.retention_days`、`favorite.folder_count`；具体数值由 OQ-014 在契约冻结前关闭。
- **MBR-FR-011**：服务端解析结果必须包含目录版本、当前等级、rank、每项值、来源、有效区间、已用/剩余额度、重置时间、最低客户端版本和快照生成时间。
- **MBR-FR-012**：存在多个有效会员 grant 时，当前等级取最高有效 rank；tier entitlement 按 rank 继承后，再应用经授权的账号级例外 grant。账号级拒绝项优先于允许项，冲突必须返回可审计原因。
- **MBR-FR-013**：会员到期、撤销、账号受限或目录失效后，服务端立即重新解析；无其他有效 grant 时回落 `rank=0`，不能依赖客户端本地倒计时完成撤权。
- **MBR-FR-014**：受限 API 每次校验权威 entitlement；客户端快照只用于渲染和预提示，不构成授权。
- **MBR-FR-015**：周期额度由服务端按 entitlement 指定时区和周期计算；创建会话时原子预占/消耗，失败或命中既有会话不得重复消耗。
- **MBR-FR-016**：只允许为客户端已声明支持的 capability 下发可执行权益；新页面、原生 SDK、消息类型或交互能力需要最低 App 版本，不能仅靠远程配置启用。

#### 用户会员申请

- **MBR-FR-038**：普通观看者可从会员页、会员门槛弹层和“我的”提交会员申请；申请字段至少包含意向等级、联系方式、联系时段、申请说明和已阅读服务说明确认。联系方式应优先复用已验证账号标识，新增自由文本需最小化收集并受权限保护。
- **MBR-FR-039**：申请状态至少包括 `draft`、`submitted`、`processing`、`approved`、`rejected`、`cancelled`、`expired`；同一账号同时只允许一条 `submitted/processing` 的有效申请，重复提交返回原申请而不是创建多个工单。
- **MBR-FR-040**：提交申请只创建会员申请记录和站内回执，不创建 grant、不修改 rank、不下发 entitlement。前台必须持续显示“申请不代表已获得会员，以实际发放结果为准”。
- **MBR-FR-041**：后台提供待处理申请队列，支持按状态、意向等级、提交时间和处理人筛选，并展示最小必要账号信息、当前会员、历史申请与风险提示；管理员仍可在无申请时按授权直接发放会员。
- **MBR-FR-042**：管理员可将申请标记为处理中、批准、拒绝、取消或过期。批准申请必须继续进入正式 grant 预览/复核/发放流程，只有 grant 生效后申请才可显示“已发放”；拒绝必须选择用户可见原因类别。
- **MBR-FR-043**：建议服务时段为每日 10:00—22:00，通常在 1 个服务日内处理；该值在 OQ-010 关闭前只能作为建议基线。前台从服务端读取当前服务说明，不承诺固定结果或必然通过。
- **MBR-FR-044**：申请提交、查看、处理、取消、批准关联、拒绝和超时均记录业务事件与审计；分析不得包含联系方式或申请自由文本，后台导出必须经过权限和脱敏控制。

#### 管理员手动发放

- **MBR-FR-017**：会员运营只能通过账号 ID、已验证登录标识或明确业务单查询目标账号；搜索结果需展示脱敏标识、账号状态和当前会员，避免同名误发。
- **MBR-FR-018**：发放动作支持立即发放、预约生效、按当前到期日续期、替换当前等级和提前撤销；“续期”从较晚的当前到期时间或指定生效时间起计算，不能静默覆盖剩余期限。
- **MBR-FR-019**：提交前必须展示变更前后等级、rank、生效区间、关键 entitlement、重叠 grant、用户可见结果和风险提示。
- **MBR-FR-020**：每次操作必须填写标准原因、用户可见说明、内部备注和外部工单/活动批次引用；用户说明不得包含内部风控信息。
- **MBR-FR-021**：发放请求使用幂等键和唯一业务单号；同键同请求返回原结果，同键不同请求拒绝，网络重试不得产生重复期限或重复通知。
- **MBR-FR-022**：批量发放、跨权限范围、异常长有效期、高频操作或配置阈值以上的发放进入双人复核；发起人不得批准自己的请求。
- **MBR-FR-023**：待复核操作在批准前不得生效；拒绝、取消、失败和过期必须保留原因。批量任务逐项执行，单项失败不回滚已成功项，也不重复执行成功项。
- **MBR-FR-024**：撤销不删除或改写原 grant，而是创建撤销事件并结束其有效性；误操作通过新的补偿 grant 修复。
- **MBR-FR-025**：管理员不能直接编辑 entitlement 快照、当前 rank 或已用额度；目录、grant 和额度修复分别走受控流程。
- **MBR-FR-026**：发放、续期、替换、撤销、复核和失败均写审计事件，包含发起人、复核人、前后状态、原因、请求/工单和规则版本。

#### 用户体验与状态

- **MBR-FR-027**：我的页面展示免费、待生效、生效中、即将到期、已到期、已撤销和账号受限状态；“即将到期”的时间窗为配置项。
- **MBR-FR-028**：会员详情优先展示当前可执行权益、剩余额度和重置时间；历史等级只在“发放记录/帮助”中展示，不与当前状态混淆。
- **MBR-FR-029**：发放、续期、替换、撤销和到期生成站内通知；实时事件只提示客户端重新拉取 HTTP 权威快照。
- **MBR-FR-030**：多设备缓存版本落后时显示“权益正在同步”，受限操作以服务端结果为准；失败文案说明原因、恢复时间或客服入口。
- **MBR-FR-031**：额度耗尽时展示具体额度名称、重置时间和可用替代操作；不得使用“系统错误”掩盖资格不足。
- **MBR-FR-032**：目录或 entitlement 不兼容当前客户端时，隐藏不可执行入口并按能力返回升级提示；已支持权益不得因一个未知字段导致整个会员页不可用。

#### 迁移、客服与分析

- **MBR-FR-033**：旧 `vip/svip` 只在来源、rank/权益和有效期证据明确时转换为独立迁移 grant；不直接把旧名称映射成新等级承诺。
- **MBR-FR-034**：迁移批次记录 legacy ID、目标账号、原始值、映射规则版本、结果和校验哈希；重复运行保持幂等。
- **MBR-FR-035**：客服可查看用户可见会员摘要、grant 时间线、权限解析原因和通知状态；修改权限必须转交会员运营流程。
- **MBR-FR-036**：至少记录目录曝光、等级查看、权益说明展开、话题门槛曝光、申请提交/状态变化、grant 生效/撤销/到期、快照刷新、额度消耗和异常差异事件。
- **MBR-FR-037**：运营看板按等级、来源、申请状态、发放状态和时间统计申请、发放、活跃、到期、撤销、话题使用和异常；不得公开个人会员或消费排行榜。

### 6.2 主流程

#### 用户查看与使用权益

```text
进入会员页
→ 拉取目录和本人 entitlement 快照
→ 展示五级比较与当前状态
→ 用户发起受限操作
→ 服务端重验账号、grant、有效期、额度和 capability
→ 原子执行或返回可恢复原因
→ 客户端刷新余额/额度/通知状态
```

#### 用户申请会员

```text
从会员页或话题门槛进入申请
→ 选择意向等级并查看对应权益与限制
→ 填写最小必要联系信息和申请说明
→ 确认“申请不等于获得会员”
→ 服务端幂等创建申请并返回业务单号
→ 前台显示已提交/处理中状态与服务时段
→ 管理员处理申请并进入正式 grant 流程
→ grant 生效后刷新 entitlement，申请显示已发放
```

#### 管理员手动发放

```text
查找并确认目标账号
→ 选择等级、动作、生效时间和有效期
→ 填写原因、用户说明和工单
→ 系统预览变更前后及风险
→ 低风险授权内直接生效 / 高风险进入独立复核
→ 写入 grant 与审计事件
→ 刷新 entitlement 并生成站内通知
→ 后台显示最终逐项结果
```

|------|-------------|------|----------|----------|------------|

| 查看本人权益快照 | 仅本人 | 按工单最小摘要 | 按授权范围 | 按复核单 | 审计读取 |
| 创建/续期/替换 grant | 否 | 否 | 是 | 否 | Owner 可授权 |
| 批准高风险 grant | 否 | 否 | 否 | 是，且非发起人 | Owner 应急需审计 |
| 撤销 grant | 否 | 否 | 按权限发起 | 高风险时批准 | Owner 应急需审计 |

### 6.4 异常与恢复矩阵

| 场景 | 用户/后台表现 | 服务端规则 | 恢复方式 |
|------|---------------|------------|----------|
| 会员到期 | 显示已到期和失效权益 | 立即回落免费权限 | 新 grant 生效后刷新 |
| 多个 grant 重叠 | 展示当前最高等级和来源摘要 | 按 rank、区间和例外优先级解析 | 运营查看冲突明细 |
| 重复提交 | 返回原业务单结果 | 幂等，不重复延长 | 使用原业务单追踪 |
| 复核被拒绝 | 后台显示拒绝原因 | 不写生效 grant | 修订后新建请求 |
| 客户端不支持权益 | 隐藏入口或提示升级 | 不下发可执行 capability | 升级 App 或继续使用兼容权益 |
| 目录回滚 | 客户端刷新版本 | 新请求使用回滚后的生效版本 | 保留旧版本审计 |
| 快照暂时不可用 | 展示同步失败，不虚构会员 | 受限操作 fail-closed | 重试 HTTP/联系客服 |
| 迁移证据不足 | 不授予新会员 | 标记待复核 | 补充证据后重新处理 |
| 重复申请 | 返回原申请和当前状态 | 账号级有效申请唯一约束 | 等待处理或取消原申请 |
| 申请获批但 grant 失败 | 显示仍在处理中，不显示会员生效 | 保留申请与失败原因，不伪造 rank | 修复后重试同一业务流程 |

### 6.5 Non-Functional Requirements

- **MBR-NFR-001**：权限解析必须是确定性的纯规则；相同目录、grant、时间和账号状态产生相同结果。
- **MBR-NFR-002**：grant、复核和额度消耗具有事务性、幂等性和并发保护，不得重复发放或超额消耗。
- **MBR-NFR-003**：会员目录和 entitlement schema 支持 Kotlin/TypeScript 契约生成、破坏性变更检测和安全默认值测试。
- **MBR-NFR-004**：账号级会员和发放记录禁止共享缓存；日志和分析只记录 ID、状态和原因代码，不记录登录凭证或内部备注正文。
- **MBR-NFR-005**：到期、撤销和账号冻结的写权限撤回必须独立于客户端在线状态，并触发实时连接权限刷新。
- **MBR-NFR-006**：后台表格、比较表和复核流程支持键盘、缩放、屏幕阅读器和非颜色状态表达。
- **MBR-NFR-007**：权限解析异常、重复 grant、过期未撤权和目录版本漂移具备监控、告警、对账和 Runbook。

## 7. Acceptance Criteria

- **MBR-AC-001**：Given App 1.0 用户打开会员页，When 目录可用，Then 同时看到心遇至心耀五级、具体权益、获取方式、期限与限制，且不存在价格或在线购买入口。
- **MBR-AC-002**：Given 任一五级会员 grant 在有效期内，When 发起并发送平台话题，Then `direct_message.create` 和 `direct_message.send` 校验通过；具体新话题额度仍按该等级 entitlement 执行。
- **MBR-AC-003**：Given 管理员重复提交相同发放请求，When 幂等键和请求内容相同，Then 只存在一个业务结果、一个生效 grant 和一次用户通知。
- **MBR-AC-004**：Given 当前会员仍有剩余有效期，When 运营选择续期，Then 新到期日从较晚的当前到期日延展，且预览与实际结果一致。
- **MBR-AC-005**：Given 高风险发放需要复核，When 发起人尝试自行批准，Then 服务端拒绝且会员状态不变化。
- **MBR-AC-006**：Given 会员到期或被撤销，When 用户保持 App 和实时连接在线，Then 新受限请求立即失败、客户端刷新为免费权限，历史会话仍按会话策略展示。
- **MBR-AC-007**：Given 新目录包含旧客户端未知 entitlement，When 旧客户端解析，Then 已知权益正常展示，未知项被安全忽略且权限不扩大。
- **MBR-AC-008**：Given 旧 `vip/svip` 记录缺少有效期或来源证据，When 运行迁移，Then 不生成新会员 grant，并在逐项报告中标为待复核。
- **MBR-AC-009**：Given 客服查询会员争议，When 输入业务单号，Then 能查看用户可见结果、grant 时间线、解析依据和通知状态，但不能修改权限。
- **MBR-AC-010**：Given 管理员误发会员后执行撤销，When 撤销完成，Then 原 grant 和审计仍存在，新撤销事件结束权限且用户收到可理解通知。
- **MBR-AC-011**：Given 普通观看者提交会员申请，When 申请状态为已提交或处理中，Then 账号 rank 和 entitlement 保持不变，所有受限 API 仍按非会员拒绝。
- **MBR-AC-012**：Given 管理员批准申请但正式 grant 尚未生效，When 用户刷新申请页，Then 显示“处理中”而非“已成为会员”；只有 grant 事务成功后才显示已发放并刷新权益。

## 8. Out of Scope

- App 1.0 在线购买、续订、自动续费、退款、恢复购买和价格展示。
- 金币充值、会员赠币、礼物、头像框、主页皮肤和聊天皮肤的执行能力。
- 通过会员等级获得真人认证、本人回复保证、线下见面或关系结果。
- 客户端按“心遇/心悦”等名称硬编码权限。
- 管理员直接编辑当前 rank、权益快照、已用额度或历史 grant。
- 证据不足的旧 `vip/svip` 自动映射。
- 仅通过远程配置启用客户端从未实现的新页面、SDK、消息类型或原生能力。
