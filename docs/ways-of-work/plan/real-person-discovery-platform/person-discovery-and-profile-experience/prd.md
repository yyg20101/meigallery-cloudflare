## 3. Goal

### Problem

MeiGallery 当前以图库为主，无法直接向观看者提供以真人为中心的推荐、搜索和资料体验。概念稿中的在线状态、精确距离和“快速匹配”不符合产品实际，也可能误导用户。平台需要在只展示认证发布真人的前提下，用地区、热度、标签和偏好帮助用户发现内容，同时提供非个性化选择和受保护媒体访问控制。

### Solution

建立统一的真人公开投影和四类发现入口：推荐、地区/热门/最新/分类、搜索筛选、真人详情。所有入口读取相同的 `verified + published + rights_valid + visible` 候选集，返回排序模式、理由代码和运营标识。客户端只渲染服务端明确提供的公开状态，通过短期凭证访问受保护媒体，并在资料暂停、授权撤销或账号受限时安全降级。

### Impact

- 提高认证真人资料的有效曝光、详情访问和关注/收藏转化。
- 为冷启动、主动探索和个性化回访提供互补入口。
- 减少虚假在线、精确位置和认证含义不清造成的信任投诉。
- 为推荐规则灰度、解释、关闭和审计建立稳定产品契约。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 访客 | 了解平台内容质量 | 只能查看有限公开预览，不泄漏受保护内容 |
| 新观看者 | 快速找到感兴趣的真人 | 冷启动可用、筛选清楚、无需先产生大量行为 |
| 回访观看者 | 获得更符合偏好的推荐 | 理由可理解、可以关闭个性化和清除记录 |
| 心享会员 | 使用高级筛选和受控媒体权益 | 权益明确，服务端授权，不出现伪入口 |
| 内容/推荐运营 | 管理供给与运营推荐 | 运营位与认证、自然热度明确分离 |
| 审核/隐私人员 | 处理下架和推荐争议 | 可追溯规则版本、曝光理由和撤回效果 |

## 5. User Stories

- 作为新观看者，我想选择感兴趣的地区和标签，以便在没有行为历史时看到相关真人。
- 作为回访观看者，我想看到“为什么推荐”，以便理解列表排序。
- 作为重视隐私的用户，我想关闭个性化并使用热门、最新或分类排序，以便控制行为数据使用。
- 作为主动探索用户，我想按地区、职业、风格和标签筛选，以便缩小结果。
- 作为用户，我想搜索展示名、地区、职业和标签，以便找到已知或相关真人。
- 作为用户，我想进入真人详情查看认证范围、模糊地区、简介和图库，以便决定是否关注或私信。
- 作为普通观看者，我想在受保护媒体上看到明确门槛，以便理解为什么不能查看。
- 作为收藏过下架资料的用户，我想看到安全的不可用说明，以免误认为网络故障。
- 作为运营人员，我想配置运营推荐位且明确标识，以便推广内容而不冒充自然热度或认证。
- 作为屏幕阅读器用户，我想按稳定顺序浏览卡片和媒体，以便完成发现旅程。

## 6. Requirements

### 6.1 Functional Requirements

#### 统一公开候选集

- **DSP-FR-001**：推荐、地区、热门、最新、分类、搜索、详情和分享必须从同一公开资格规则读取，仅包含 `verification_status=verified`、`publish_status=published`、用途授权有效且未被安全隐藏的真人资料。
- **DSP-FR-002**：公开列表不得由客户端过滤草稿、待审核、暂停、已归档、授权过期或安全隐藏资料；服务端不得先返回再要求客户端隐藏。
- **DSP-FR-003**：公开投影使用稳定、不可枚举的 `profileId`；`personId` 仅在业务确有需要时返回，不暴露 legacy 自增 ID 或敏感身份记录。
- **DSP-FR-004**：公开字段只包含审核通过的展示名、认证说明、模糊地区、标签、职业/风格摘要、简介、媒体派生资源、运营模式和可执行能力。
- **DSP-FR-005**：会员等级、运营推荐和热度不得改变认证状态；三类标识必须使用不同语义、图标和无障碍标签。

#### 推荐首页

- **DSP-FR-010**：推荐首页提供“推荐、地区、热门、最新”页签以及搜索、筛选和站内通知入口。
- **DSP-FR-011**：推荐模式至少支持 `personalized`、`non_personalized` 和 `editorial`；每个结果返回 `reasonCode`、`ruleVersion` 和用户可展示理由键。
- **DSP-FR-012**：个性化可使用用户主动偏好、喜欢、关注、收藏、浏览、地区范围、标签、职业、风格、热度和时效，但不得使用精确位置轨迹、私信正文或管理员内部备注。
- **DSP-FR-013**：无行为历史时优先使用用户主动偏好；未设置或关闭个性化时使用规则型非个性化候选，不显示空首页。
- **DSP-FR-014**：用户可从首页和设置切换非个性化模式；关闭后下一次新推荐会话不再使用账号行为信号，并展示相应模式说明。
- **DSP-FR-015**：推荐分页游标绑定规则版本与会话；规则变化或游标失效时重新开始，不拼接不同规则导致重复/跳项。
- **DSP-FR-016**：同一推荐会话应控制短时间重复曝光；资料不足时允许明确的回退池，但不得放宽公开资格。
- **DSP-FR-017**：运营置顶/精选必须返回 `editorial` 标识和原因，不伪装成自然热门，也不参与真人认证徽章。

#### 地区、热门、最新与分类

- **DSP-FR-020**：地区目录使用后台配置的国家/地区组/省市等模糊层级；App 1.0 不请求持续定位，不展示精确距离或实时轨迹。
- **DSP-FR-021**：热门排序基于版本化、抗刷量的聚合信号和时间衰减；不得以用户消费金额、会员等级或私信数量直接作为真人价值排名。
- **DSP-FR-022**：最新排序使用公开投影的首次/最近有效发布时间，后台编辑但未重新发布不得伪造“最新”。
- **DSP-FR-023**：分类入口来自统一 taxonomy，至少支持地区、身份、性格、风格、职业、发型、服饰、场景和内容类型中已启用类别。
- **DSP-FR-024**：目录项下线或合并时，旧客户端收到别名/未知项应安全忽略或重定向，不崩溃、不扩大筛选范围。

#### 搜索、筛选与保存条件

- **DSP-FR-030**：搜索覆盖审核后的展示名、地区、职业和标签；不得索引法定姓名、证件、精确地址、内部备注或未发布字段。
- **DSP-FR-031**：基础搜索和基础筛选向登录观看者开放；高级筛选与可保存条件数量分别由 `discovery.filter.advanced` 和 `discovery.saved_filter.max` entitlement 判断。
- **DSP-FR-032**：筛选页显示当前条件、可选项、结果数、清空操作和冲突条件说明；应用筛选前不修改当前结果。
- **DSP-FR-033**：受限高级筛选可以展示名称和价值说明，但点击时只进入权益说明，不返回受限结果或创建订单。
- **DSP-FR-034**：保存条件必须记录 taxonomy 稳定 ID 和目录版本；已下线项在编辑时标记失效并允许移除。
- **DSP-FR-035**：无结果时提供放宽筛选、清空条件或查看热门的建议，不以未认证资料填充结果。
- **DSP-FR-036**：搜索历史默认只在本人账号范围使用，支持逐条和全部清除；敏感自由文本不进入分析日志。

#### 真人卡片与详情

- **DSP-FR-040**：列表卡至少展示审核封面、展示名、真人认证说明、模糊地区、核心标签、推荐理由/排序说明和当前可执行互动状态。
- **DSP-FR-041**：卡片不得显示未经真实事件支持的在线、输入中、本人已读、精确距离、保证回复、保证见面或消费排名。
- **DSP-FR-042**：详情结构依次覆盖媒体头部、认证与展示名、地区/标签、简介、图库、运营/私信说明、互动操作和相关真人。
- **DSP-FR-043**：认证标识必须可打开说明，展示实际核验范围和更新时间，不使用“绝对真实”等超出证据的文案。
- **DSP-FR-044**：详情持续展示 `platform_managed` 或未来 `person_managed` 的接收主体说明；该说明不得被会员营销或媒体区域遮挡。
- **DSP-FR-045**：喜欢、关注、收藏、私信、举报、拉黑和分享只作为对应 Feature 的入口；服务端仍按各自权限再次校验。
- **DSP-FR-046**：分享链接每次打开重新读取当前公开状态；资料不可用时展示通用不可用页，不泄漏下架原因或旧受保护内容。
- **DSP-FR-047**：相关真人使用同一公开候选集和可解释理由，不允许因目标不足返回未审核资料。

#### 媒体浏览与访问控制

- **DSP-FR-050**：列表只加载已审核的派生封面/缩略图，不在滚动列表自动加载原图或启动视频播放器。
- **DSP-FR-051**：公开媒体使用版本化稳定资源；受保护媒体先请求服务端短期访问凭证，客户端不得拼接 R2 或 Stream 永久地址。
- **DSP-FR-052**：受保护媒体门槛必须展示所需 entitlement、当前状态和可执行下一步；App 1.0 不出现在线购买按钮。
- **DSP-FR-053**：访问凭证过期可在当前权限仍有效时静默刷新一次；权限失效、资料暂停或授权撤回后停止刷新并清理受保护缓存。
- **DSP-FR-054**：图片支持加载、失败重试、占位、内容描述、敏感预览模糊和手势浏览；原图保存/下载不属于 App 1.0。
- **DSP-FR-055**：视频只有在媒体 Feature 和 Cloudflare Stream 生产能力启用后显示播放入口；未启用时不得下发伪视频 capability。

#### 状态同步与用户控制

- **DSP-FR-060**：资料在用户浏览期间被暂停时，下一次 API、媒体凭证或实时撤权事件必须转为不可用状态并停止新互动。
- **DSP-FR-061**：用户关闭个性化或清除推荐记录后，客户端清理相应本地投影并刷新推荐会话；法定安全记录不作为推荐信号。
- **DSP-FR-062**：离线只展示最近同步且仍在缓存期限内的公开投影，并标记离线；受保护媒体不得因离线扩大访问。
- **DSP-FR-063**：客户端收到未知排序模式、理由代码、标签类型或 capability 时使用中性回退文案或隐藏组件，不崩溃、不授予权限。

#### 埋点与指标

- **DSP-FR-070**：至少记录推荐会话开始、合规曝光、卡片点击、搜索提交、筛选应用、无结果、详情访问、媒体门槛曝光和非个性化切换。
- **DSP-FR-071**：曝光事件包含 `profileId`、入口、位置、reasonCode、ruleVersion、模式和客户端版本，不包含精确位置、搜索敏感原文或私信内容。
- **DSP-FR-072**：核心产品指标包括有效曝光率、详情访问率、搜索成功率、无结果率、关注/收藏转化、非个性化使用率和资料撤回延迟。
- **DSP-FR-073**：推荐实验必须配置目标指标、反指标、样本范围、开始/结束和回滚条件；认证/授权过滤不得成为实验变量。

### 6.2 主流程

```text
登录/首次偏好 → 推荐会话 → 卡片曝光 → 真人详情
→ 查看公开/受保护媒体 → 喜欢/关注/收藏或私信门槛
```

```text
首页 → 搜索/筛选 → 结果列表 → 调整或保存条件
→ 真人详情；无结果 → 放宽条件/热门入口
```

### 6.3 排序与披露矩阵

| 入口 | 主要排序 | 必须披露 | 禁止信号 |
|------|----------|----------|----------|
| 推荐 | 偏好、行为、热度、时效 | 推荐理由、模式 | 精确位置、私信正文、消费额 |
| 地区 | 模糊地区相关性 | 地区粒度 | 实时轨迹、精确距离 |
| 热门 | 抗刷聚合 + 时间衰减 | 热门口径说明 | 认证等级、消费排行榜 |
| 最新 | 有效发布时间 | “最新发布” | 后台静默编辑时间 |
| 运营精选 | 人工配置 | “平台精选/推广” | 冒充自然热度或认证 |

| 操作 | 访客 | 登录观看者 | 有对应 entitlement 的会员 | 内容/推荐运营 |
|------|------|------------|-----------------------------|---------------|
| 查看有限公开预览 | 允许 | 允许 | 允许 | 预览权限内允许 |
| 查看完整公开列表/搜索 | 按 capability 限制 | 允许 | 允许 | 只读预览 |
| 使用基础筛选 | 不允许 | 允许 | 允许 | 配置目录，不代表认证 |
| 使用高级筛选/保存条件 | 不允许 | 按 entitlement | 按 entitlement | 配置规则，不读取个人条件 |
| 获取受保护媒体凭证 | 不允许 | 按 entitlement | 按 entitlement | 仅审核预览凭证 |
| 配置运营精选/排序规则 | 不允许 | 不允许 | 不允许 | 按角色、审批和审计 |
| 改变认证或公开资格 | 不允许 | 不允许 | 不允许 | 必须进入 A-03 审核，不能由推荐操作完成 |

### 6.5 页面状态矩阵

| 状态 | 列表 | 详情/媒体 |
|------|------|-----------|
| 加载 | 骨架屏，保留稳定布局 | 分区骨架，不显示伪内容 |
| 空 | 说明原因与其他入口 | 不适用 |
| 无结果 | 放宽/清空条件 | 不适用 |
| 离线 | 标记缓存时间 | 仅公开缓存，受保护内容重新鉴权 |
| 已暂停/归档 | 从新列表移除 | 通用不可用页 |
| 无 entitlement | 卡片可见但媒体锁定 | 显示门槛与获取说明 |
| 安全受限 | 停止相关曝光 | 说明、帮助/申诉入口 |
| 需升级 | 隐藏未知组件或升级页 | 不执行未知能力 |

### 6.6 Non-Functional Requirements

- **DSP-NFR-001**：所有公开入口复用可测试的服务端公开资格策略，资格过滤不得在各路由复制后产生差异。
- **DSP-NFR-002**：列表使用游标分页并稳定去重；相同规则版本和游标重复请求返回一致顺序或明确过期错误。
- **DSP-NFR-003**：推荐和搜索目标性能在技术方案中按真实数据量冻结；产品验收要求基准网络下首屏可见内容不被全量媒体下载阻塞。
- **DSP-NFR-004**：图片列表采用尺寸约束、预取上限和取消机制；快速滚动不得持续加载已离屏原图。
- **DSP-NFR-005**：公开与受保护媒体使用隔离缓存；退出、远程登出、会员失效和撤权后清理不再授权内容。
- **DSP-NFR-006**：推荐规则、taxonomy、公开投影和运营位版本化、可审计、可灰度和可回滚。
- **DSP-NFR-007**：双列卡在大字体/小屏自动切换单列；所有卡片、筛选和媒体支持屏幕阅读器、动态字体和减少动态效果。
- **DSP-NFR-008**：日志不得包含精确位置、未发布资料、授权证据、自由搜索敏感原文或签名媒体 URL。

### 6.7 实施前门禁

- OQ-007：认证核验范围和公开徽章文案。
- OQ-009：热门公式、运营推荐披露和反刷规则。
- OQ-014：高级筛选与保存条件 entitlement 数值。
- OQ-023：个性化推荐说明、关闭方式和目标地区合规结论。
- OQ-004/OQ-005：高保真卡片布局与“关注”信息架构，不阻塞 API/领域细化。

## 7. Acceptance Criteria

- **DSP-AC-001**：Given 任一未认证、未发布、暂停、归档或授权失效资料，When 请求任一发现、搜索、详情或分享入口，Then 不返回可公开内容。
- **DSP-AC-002**：Given 新账号没有行为历史且跳过偏好，When 打开首页，Then 返回非个性化合格资料而不是空页面。
- **DSP-AC-003**：Given 用户关闭个性化，When 开始新推荐会话，Then 响应模式为 `non_personalized` 且不使用账号行为信号。
- **DSP-AC-004**：Given 运营人员配置精选资料，When 用户看到卡片，Then 显示平台精选标识且认证徽章不变化。
- **DSP-AC-005**：Given 用户选择某城市和风格，When 应用筛选，Then 结果仅包含满足公开资格和全部有效条件的资料。
- **DSP-AC-006**：Given 搜索命中法定姓名但该姓名未被审核为展示名，When 查询，Then 不因敏感身份字段返回资料。
- **DSP-AC-007**：Given 用户没有高级筛选 entitlement，When 点击受限筛选，Then 进入权益说明且不出现在线支付或受限结果。
- **DSP-AC-008**：Given 搜索无结果，When 页面完成加载，Then 不使用未认证资料填充，并提供清空/放宽/热门入口。
- **DSP-AC-009**：Given 资料处于平台代运营模式，When 用户从列表进入详情，Then 卡片/详情不会显示真人在线，详情持续披露平台运营接收私信。
- **DSP-AC-010**：Given 用户请求受保护媒体且无权限，When 服务端拒绝，Then 客户端不展示缓存原图，只显示门槛和可执行说明。
- **DSP-AC-011**：Given 用户正在查看资料时管理员暂停发布，When 客户端刷新或请求新媒体凭证，Then 进入不可用状态并停止新凭证。
- **DSP-AC-012**：Given 推荐游标属于旧规则版本，When 请求下一页，Then 服务端返回明确游标失效，客户端开启新会话且不混排。
- **DSP-AC-013**：Given 客户端收到未知标签或理由代码，When 渲染卡片，Then 使用中性回退或隐藏该字段，不崩溃也不扩大权限。
- **DSP-AC-014**：Given 动态字体达到系统大字号，When 浏览推荐、筛选和详情，Then 布局切换为可读结构且认证、运营主体和操作不截断。
- **DSP-AC-015**：Given App 1.0 未启用视频，When 后台资料包含 legacy 视频，Then 客户端不显示不可执行播放器入口。

## 8. Out of Scope

- 普通用户公开资料、双向匹配、用户间聊天和“在线附近的人”。
- 精确定位、后台持续定位、实时距离和轨迹历史。
- 公开评论、榜单式消费排名、直播和短视频自动连播。
- 由客户端自行计算认证、热度、媒体权限或公开状态。
- App 1.0 媒体下载、离线原图、画中画、DRM 和视频生产接入。
- 喜欢、关注、收藏、浏览历史的数据写入细节；由 F-06 独立 PRD 验收。
- 会话创建、消息、会员发放和代运营工作台；由对应 Feature PRD 验收。
