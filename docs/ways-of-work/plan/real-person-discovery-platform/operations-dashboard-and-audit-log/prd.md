## 3. Goal

### Problem

真人认证发布、推荐规则、平台话题代运营、会员发放、管理员调币、安全处置和数据权利都由后台执行。若只有当前图库站的访问分析或零散日志，运营无法判断供给、队列和服务是否健康，审计也无法还原“谁在何时基于什么理由改变了什么”。反之，如果看板直接暴露平台话题正文、个人余额或敏感证据，又会把运营分析变成新的隐私风险。

### Solution

建立相互独立但可关联的三层能力：产品/运营指标用于聚合趋势，系统可观测性用于技术健康，追加式审计事件用于责任和事实追踪。Nuxt 后台提供按角色裁剪的总览、专题看板、异常队列和只读审计查询；所有管理员写操作、高风险读取、规则发布、会员/调币复核及安全处置必须关联 request/trace、业务对象、原因和前后状态。

### Impact

- 运营可以基于统一口径管理供给、发现、互动、消息、会员、金币、安全和数据权利。
- 高风险操作可从业务记录追溯至实际操作者、审批和审计事件。
- 异常从“用户投诉后发现”提前到可告警、可分派、可复盘的工作流。
- 看板坚持聚合和最小化，不泄露平台话题正文、证件、个人消费或内部备注。
- 为现有 Web 渐进迁移和后续 App 功能保留统一指标、审计与兼容边界。

## 4. User Personas

| Persona | 目标 | 约束与关注点 |
|---------|------|--------------|
| Owner/运营负责人 | 查看整体供给、互动、服务和风险健康 | 不应绕过专题权限读取敏感明细 |
| 内容运营 | 管理真人供给、认证发布和授权完整率 | 只查看内容域指标和授权范围对象 |
| 代运营组长 | 查看会话积压、等待和安全升级 | 不公开操作员/用户消息量排行榜 |
| 会员/财务负责人 | 查看发放、到期、调币和对账差异 | 聚合指标与账务明细权限分离 |
| 安全/隐私负责人 | 查看举报、处置、数据权利和异常访问 | 敏感证据按案件授权 |
| SRE/技术负责人 | 查看 API、DO、Queue、Workflow 和数据质量 | 不读取业务正文 |
| 审计人员 | 按对象、操作者和时间还原变更链 | 只读、可验证、导出受控 |

## 5. User Stories

- 作为 Owner，我想在一个总览中看到 App 1.0 各业务域健康状态和数据新鲜度，以便判断是否可以扩量。
- 作为内容运营，我想查看认证发布量、授权完整率、审核时长和暂停率，以便安排供给。
- 作为代运营组长，我想查看待分配会话、等待时长和安全升级，以便调整班次与容量。
- 作为财务负责人，我想查看会员发放、管理员调币、复核和账本差异，以便发现异常。
- 作为安全负责人，我想查看举报、拉黑、处置、申诉改判和高危队列，以便满足服务目标。
- 作为 SRE，我想从产品异常跳转到不含正文的 trace 和技术指标，以便排障。
- 作为审计人员，我想按业务单号查看申请、复核、生效和通知完整链路，以便处理争议。
- 作为审计人员，我想验证历史审计未被删除或重写，以便信任查询结果。
- 作为普通运营，我想只看到自己职责范围内的指标和对象，以免无意接触敏感数据。

## 6. Requirements

### 6.1 Functional Requirements

#### 三类数据边界

- **OAU-FR-001**：系统必须区分产品/运营指标、技术可观测性和审计事件；三者可以通过非敏感 request/trace/业务引用关联，但不得混存为一个无限权限日志表。
- **OAU-FR-002**：产品指标只用于聚合行为和业务结果，不保存平台话题正文、内部备注、证件、授权原件、完整登录标识、访问令牌或精确位置。
- **OAU-FR-003**：技术日志记录服务、错误码、耗时、资源和 trace，不记录业务正文；审计事件记录责任事实和必要前后状态，不承担全文内容仓库。
- **OAU-FR-004**：每个指标和审计 action 都必须登记 Owner、定义、来源、敏感级别、可见角色、保留策略和质量校验；未登记数据不得进入生产看板。

#### 运营总览与专题看板

- **OAU-FR-005**：运营首页提供数据更新时间、当前范围、关键门禁、严重异常和各专题摘要；数据缺失、延迟或不完整必须显示质量状态，不能用 0 代替未知。
- **OAU-FR-006**：供给专题至少包含候选真人、认证通过/拒绝、已发布、授权完整率、审核时长、暂停/归档和导入失败。
- **OAU-FR-007**：发现专题至少包含合格候选覆盖、推荐/非个性化曝光、详情访问、搜索成功、筛选使用、关注/喜欢/收藏和规则版本效果。
- **OAU-FR-008**：消息专题至少包含平台话题门槛曝光、会话创建、待分配量、等待时长、首次响应、有效往返、关闭、内容审核、举报和代运营披露投诉。
- **OAU-FR-009**：会员专题至少包含各等级手动发放、生效、续期、撤销、到期、权益刷新、新会话额度使用和异常 grant；不展示在线收入或虚构购买转化。
- **OAU-FR-010**：钱包专题至少包含加币、扣币、补偿、冲正、待复核、批量结果、失败和对账差异；个人余额与分录只能从受控财务页面查看。
- **OAU-FR-011**：通知专题至少包含生成、抑制、失败、重复、读取、深链失效和积压；App 1.0 明确标记“仅站内，不含系统推送”。
- **OAU-FR-012**：安全与数据权利专题至少包含举报、拉黑、审核 SLA、处置、申诉改判、数据导出、注销、失败和高危事件；不得展示举报证据正文。
- **OAU-FR-013**：平台健康专题至少包含关键 API、Durable Objects、D1、R2、Queues、Workflows、错误、延迟、积压、对账和客户端版本分布。
- **OAU-FR-014**：后续支付、礼物、装扮、系统推送和真人认领卡片默认不存在；只有对应 Feature 正式启用并登记口径后才进入看板。

#### 时间、筛选与口径

- **OAU-FR-015**：看板支持配置允许的时间范围、粒度、地区、客户端平台/版本、业务状态和规则版本；筛选项必须遵守角色数据范围。
- **OAU-FR-016**：每个指标显示定义、分子/分母、事件时间/处理时间口径、时区、新鲜度、是否采样和最后质量检查结果。
- **OAU-FR-017**：同名指标不能在不同专题使用不同定义；口径变更创建新版本和生效时间，历史趋势不得静默按新公式重算。
- **OAU-FR-018**：小样本、敏感维度或可能识别个人的交叉筛选必须抑制、合并或拒绝；阈值按首发地区隐私评审配置。
- **OAU-FR-019**：从聚合指标钻取明细时重新校验角色、对象范围和业务目的；看板权限不自动授予消息、证据、会员或钱包明细权限。
- **OAU-FR-020**：导出聚合报表需记录筛选、口径版本、生成时间、申请人和水印；敏感或大范围导出需要复核、短期下载凭证和到期删除。

#### 审计事件规范

- **OAU-FR-021**：所有管理员写操作、复核、发布/回滚、批量任务、应急操作和高风险敏感读取必须创建追加式审计事件；业务写成功而审计无法记录时按动作风险 fail-closed 或进入高优先级补偿队列。
- **OAU-FR-022**：审计事件至少包含 event ID、发生时间、actor 类型/ID/角色/范围、action、target 类型/ID/版本、结果、原因代码、用户说明引用、内部工单引用、request/trace ID、客户端/会话和策略版本。
- **OAU-FR-023**：变更事件记录经字段级过滤的 before/after 或差异摘要；密钥、令牌、平台话题正文、证件和完整证据不得复制进审计 payload，仅保存受控引用和内容哈希。
- **OAU-FR-024**：审批事件必须关联申请、发起人、审批人、结论和执行结果；发起、批准和生效不能被合并成一条无法区分的事件。
- **OAU-FR-025**：平台运营消息审计记录会话、消息引用、`senderType=platform_operator`、实际操作员、assignment 和审核结果，不在审计列表直接展示正文。
- **OAU-FR-026**：会员发放和调币审计必须关联 grant/申请/分录、风险规则、复核和站内通知，支持按业务单号还原完整链路。
- **OAU-FR-027**：敏感读取审计记录查询者、目的、案件/工单、对象范围、返回记录数和时间；不记录读到的正文内容。
- **OAU-FR-028**：审计事件不得编辑或删除；纠正错误标签或补充说明时新增关联更正事件，保留原值。
- **OAU-FR-029**：系统建立连续性和完整性检查点，至少检测 sequence 缺口、重复事件、业务成功无审计和存储内容变化；检查结果保存独立完整性清单并定期验证恢复。

#### 审计查询与事件详情

- **OAU-FR-030**：审计查询支持时间、actor、角色、action、target、结果、业务单号、request/trace 和风险级别，使用游标分页和限制范围。
- **OAU-FR-031**：审计详情按“谁、何时、做了什么、对什么、为什么、结果如何、谁批准、关联事件”展示，并对敏感字段脱敏。
- **OAU-FR-032**：普通管理员默认只查看自己操作和授权域；专职审计可跨域只读，敏感正文仍需独立案件授权。
- **OAU-FR-033**：审计导出需强认证、用途、范围预览、必要复核、水印、短期 R2 下载凭证和完整导出审计；默认不允许全量无限期导出。
- **OAU-FR-034**：任何角色都不能通过审计查询执行回滚、重放或修改业务；修复必须从对应业务流程发起新的受控动作。

#### 异常中心与响应

- **OAU-FR-035**：异常中心聚合关键门禁和告警，至少覆盖未授权发布、平台消息身份异常、会员到期未撤权、重复 grant、钱包不平、调币未审、审计缺失、内部备注泄漏、通知积压和数据权利逾期。
- **OAU-FR-036**：异常拥有严重级别、来源、首次/最后发生、影响范围、Owner、状态、关联 Runbook、处置时间线和复盘引用。
- **OAU-FR-037**：异常状态支持 open、acknowledged、investigating、mitigated、resolved 和 false_positive；关闭必须填写证据，不能只通过隐藏看板卡片消除。
- **OAU-FR-038**：P0/P1 异常支持暂停推荐规则、发布、代运营发送、会员发放或调币等明确的安全开关；开关权限、影响预览和恢复操作全部审计。

#### 指标使用约束

- **OAU-FR-039**：看板不得公开用户消费、金币余额、平台话题数量、敏感偏好或被举报次数排行榜，也不得用单纯消息量评价关系结果。
- **OAU-FR-040**：操作员质量关注合规、响应、升级和抽检，不建立诱导快速回复、冒充或刷消息量的公开排名。
- **OAU-FR-041**：北极星指标和反指标必须并列展示；增长结果不能隐藏授权缺失、披露投诉、越权、账本差异和严重安全事件。
- **OAU-FR-042**：至少记录看板访问、筛选、钻取、导出、审计查询、敏感详情访问、异常确认和安全开关操作，形成自身审计闭环。

### 6.2 主流程

#### 运营发现并处置异常

```text
进入运营总览
→ 确认时间范围、数据新鲜度和质量状态
→ 查看专题指标和反指标
→ 钻取到授权范围内的异常聚合
→ 在异常中心认领并关联 Runbook
→ 通过对应业务流程暂停/修复
→ 验证恢复和数据对账
→ 关闭异常并关联复盘
```

#### 审计还原业务操作

```text
输入业务单号/对象/requestId
→ 只读查询关联审计事件
→ 查看申请、复核、执行、通知和后续更正时间线
→ 如需敏感证据，发起案件级授权
→ 生成受控导出或形成调查结论
→ 查询和导出本身写入审计
```

### 6.4 异常与恢复矩阵

| 场景 | 页面表现 | 系统规则 | 恢复方式 |
|------|----------|----------|----------|

### 6.5 Non-Functional Requirements

- **OAU-NFR-001**：审计写入采用追加、幂等和可恢复语义；审计 ID、业务 ID、request/trace 映射唯一且可查询。
- **OAU-NFR-002**：指标层、日志层和审计层按不同保留、权限和存储路径隔离；任何看板查询都执行服务端数据范围过滤。
- **OAU-NFR-003**：看板查询具有时间/范围上限、分页、超时、缓存和资源预算，不能因大范围查询影响核心消息或账务写入。
- **OAU-NFR-004**：指标延迟、事件丢失、重复、schema 漂移和质量校验均可观测；数据质量状态与业务数值同时展示。
- **OAU-NFR-005**：敏感字段经过统一脱敏和日志扫描；平台话题正文、证件、令牌、内部备注和受保护 URL 泄漏为零容忍事件。
- **OAU-NFR-006**：Nuxt 后台支持键盘导航、屏幕阅读器、200% 缩放、非颜色状态表达、表格线性阅读和图表数据表替代视图。
- **OAU-NFR-007**：审计备份、完整性清单、按时间点恢复和查询重建需定期演练，恢复后可验证事件数量、sequence 和哈希一致性。
- **OAU-NFR-008**：所有时间以 UTC 存储，页面明确展示时区；指标事件时间和处理时间不能混用。

### 6.6 实施前门禁

| 门禁 | 对应决策 | 未关闭时允许继续 | 未关闭时禁止 |
|------|----------|------------------|------------|
| 数据与证据保留期 | OQ-020 | 设计分类和策略字段 | 冻结归档/删除任务 |
| 首发地区隐私口径 | OQ-002、OQ-024 | 聚合模型和角色原型 | 生产敏感看板/导出 |
| 安全 SLA 与 Owner | OQ-022、OQ-025 | 异常状态机和 Runbook 模板 | 对外扩量 |
| Cloudflare 容量预算 | OQ-031 | 小规模查询和完整性验证 | 大范围明细和长期保留上线 |

## 7. Acceptance Criteria

- **OAU-AC-001**：Given 看板数据源延迟，When 运营打开总览，Then 页面显示“数据延迟/未知”和最后更新时间，不把缺失数据显示为 0。
- **OAU-AC-002**：Given 内容运营查看消息专题，When 无消息明细权限，Then 只能看到聚合指标，不能钻取平台话题正文或用户列表。
- **OAU-AC-003**：Given 管理员完成会员发放，When 按业务单号查询，Then 可关联申请、复核、生效 grant、通知和实际操作者审计事件。
- **OAU-AC-004**：Given 管理员调币需要复核，When 查询审计时间线，Then 发起、批准、执行和分录是可区分且相互关联的事件。
- **OAU-AC-005**：Given 操作员发送平台消息，When 审计查看元数据，Then 包含实际操作员和 `platform_operator` 身份，但列表不暴露消息正文。
- **OAU-AC-006**：Given 有人尝试修改或删除历史审计事件，When 请求到达，Then 服务端拒绝并产生新的高优先级安全事件。
- **OAU-AC-007**：Given 小样本多维筛选可能识别个人，When 请求指标，Then 服务端抑制或拒绝结果，不能通过多次查询绕过数据范围。
- **OAU-AC-008**：Given 审计导出获批，When 下载，Then 文件带范围/时间水印、使用短期凭证，导出和下载行为均被审计。
- **OAU-AC-009**：Given 钱包余额与分录汇总不一致，When 对账发现，Then 异常中心产生高优先级事件并冻结受影响调币，不能静默隐藏差异。
- **OAU-AC-010**：Given 未来支付/礼物模块未启用，When 打开 App 1.0 看板，Then 不出现虚假收入、订单、礼物或系统推送指标。
- **OAU-AC-011**：Given 审计完整性检查发现 sequence 缺口，When 任务完成，Then 保留独立检查结果、告警和调查入口，原事件不被自动重写。
- **OAU-AC-012**：Given 用户查看任何榜单，When 数据涉及个人消息、余额、消费或敏感偏好，Then 产品不提供该榜单或个人可识别排序。

## 8. Out of Scope

- 用运营看板替代技术日志、账务账本、审核证据库或业务详情页。
- 在看板、分析事件或通用日志中保存平台话题正文、证件、内部备注、令牌和访问凭证。
- 个人金币余额、消费、平台话题数量、敏感偏好、举报或操作员刷量排行榜。
- 允许看板钻取权限自动扩大到消息、财务、安全或身份明细。
- 修改、删除、覆盖审计事件，或从审计页直接重放业务写操作。
- 无审批、无水印、永久链接的全量审计或敏感报表导出。
- 在对应 Feature 未上线时展示支付、礼物、装扮、系统推送或真人认领指标。
- 用“消息越多”或“消费越高”作为有效关系和产品成功的唯一依据。
