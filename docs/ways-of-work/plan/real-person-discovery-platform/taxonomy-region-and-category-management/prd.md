## 3. Goal

### Problem

现有 MeiGallery 标签是图库自由分类，已经包含地区、身份、性格、风格、职业、发型、服饰、场景和内容类型，但缺少完整层级、别名、状态、版本和迁移治理。若 App 直接复用名称或 slug，重命名、合并和未知标签会导致筛选失效、重复分类、精确位置泄漏以及推荐规则不可复现。

### Solution

建立版本化 taxonomy 与地区目录：每个词条拥有稳定 ID、类型、层级、展示名、别名、状态、排序和审计。MeiGallery 旧标签通过显式映射迁移，未知值进入待审核而不是自动公开。客户端使用目录版本和稳定 ID 搜索/筛选；停用、合并和重命名通过兼容映射安全演进。

### Impact

- 统一导入、资料编辑、搜索、筛选和推荐使用的分类事实源。
- 减少重复、错拼、自由文本和过度精确地区造成的数据质量风险。
- 允许分类调整而不破坏旧客户端、已保存筛选和历史资料。
- 为多语言、多地区和推荐解释保留稳定扩展边界。

### Taxonomy-1 开发基线（2026-08-09）

`0081_app_taxonomy_catalog.sql` 与 App API v2 `1.14.0` 已实现 production 默认关闭的稳定词条、不可变修订/目录快照、合并重定向、legacy 显式映射、人物内容版本关联、发布资格门禁和公开分类投影。公共目录支持 ETag 条件读取，人物公开 DTO 兼容新增 `taxonomyTerms`；后台已提供词条草稿/复核/生命周期/合并、目录生成发布、映射维护和人物标注服务端 API。

本阶段不 seed 真实词条、不导入 MeiGallery 旧标签、不修改 Wrangler、不执行 migration，也不启用现有环境。`restricted` 敏感词在隐私/法务升级审批完成前不能激活；细粒度权限、影响预览、多语言、灰度/回滚、迁移批次、Nuxt/KMP 页面和专项验证后置。完整工程边界见 `docs/app/TAXONOMY_1_CATALOG_AND_PROFILE_INTEGRATION.md`。

Search-2 已在该事实源上新增目录父子/合并 closure、stable ID 分组筛选、旧条件重定向和失效诊断；保存条件不复制展示名或 legacy 值。该扩展仍默认关闭，详见 `docs/app/SEARCH_2_FILTERS_AND_SAVED_FILTERS_INTEGRATION.md`。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 分类运营 | 创建和维护可理解目录 | 命名一致、影响可预览、变化可回滚 |
| 内容编辑 | 为真人资料选择有效标签和地区 | 只选已批准值，搜索方便 |
| 迁移管理员 | 映射 MeiGallery 旧标签 | 别名、未知值和重复值可处理 |
| 推荐/搜索运营 | 使用稳定分类配置规则 | ID 不随展示名变化，版本可追溯 |
| 审核/隐私人员 | 审查敏感或过细分类 | 不推断敏感属性，不泄漏精确位置 |
| 观看者 | 使用一致筛选和标签 | 重命名/下线后不出现错误或空白入口 |

## 5. User Stories

- 作为分类运营，我想创建分类型的标签和地区节点，以便内容编辑统一选择。
- 作为分类运营，我想预览重命名、停用或合并影响，以便避免破坏线上筛选。
- 作为迁移管理员，我想把多个 legacy 拼写映射到一个稳定词条，以便消除重复。
- 作为迁移管理员，我想让未知标签进入待审核，以免未经确认就公开。
- 作为内容编辑，我想按类型、名称和别名搜索词条，以便快速标注资料。
- 作为审核人员，我想限制敏感、歧视性或精确位置标签，以便保护真人和观看者。
- 作为推荐运营，我想引用稳定 ID 和目录版本，以便规则变化可复现。
- 作为观看者，我想在词条合并后继续打开已保存筛选，以便不丢失条件。

## 6. Requirements

### 6.1 Functional Requirements

#### 目录模型与类型

- **TAX-FR-001**：taxonomy 词条必须包含不可复用 stable ID、类型、父级、展示名、规范 slug、别名、状态、排序、可见范围、版本和审计字段。
- **TAX-FR-002**：App 1.0 支持地区范围、地区组、城市/国家、身份、性格、风格、职业、发型、服饰、场景和内容类型；新增类型必须经过 schema 与客户端兼容评审。
- **TAX-FR-003**：地区目录支持国家/地区、运营地区组、行政区域、城市和平台自定义模糊区域，不能保存或公开精确住址、实时坐标或轨迹。
- **TAX-FR-004**：词条展示名可按语言/地区扩展，但稳定 ID 和业务含义不随翻译、重命名或排序变化。
- **TAX-FR-005**：slug 在约定命名空间唯一，用于可读路由而非授权；所有 API 与规则使用 stable ID。
- **TAX-FR-006**：词条状态至少包含 `draft`、`pending_review`、`active`、`hidden`、`deprecated`、`merged`、`archived`。

#### 创建、编辑与审核

- **TAX-FR-010**：有 `taxonomy.edit` 权限的运营可创建草稿、编辑名称/别名/说明/排序和提交审核，不能直接使敏感词条 active。
- **TAX-FR-011**：提交前校验同类型同义/近似名称、slug、层级循环、父子类型、敏感词、地区精度和已存在 alias。
- **TAX-FR-012**：分类审核员可通过、退回、拒绝或要求隐私/法务升级；发布 taxonomy 与普通资料发布使用独立权限。
- **TAX-FR-013**：词条激活后修改语义、类型或父级必须生成新版本并展示影响；纯展示名修正也保留历史和 alias。
- **TAX-FR-014**：身份、性格等可能引发敏感推断的词条必须记录允许用途和公开性；不得基于观看者行为自动给真人增加此类标签。
- **TAX-FR-015**：内容编辑只能把 active 且允许用于真人资料的词条关联到候选版本；hidden 仅供内部兼容，不能作为新选择。

#### 地区规则

- **TAX-FR-020**：真人公开资料只关联允许公开的模糊地区节点；内部授权或运营地址与公开地区分离。
- **TAX-FR-021**：每个资料最多有一个主公开地区，可有经批准的服务/内容地区；客户端不根据设备位置自动改写资料地区。
- **TAX-FR-022**：地区筛选默认使用用户主动选择或账号模糊地区；App 1.0 不要求持续定位权限。
- **TAX-FR-023**：地区节点移动、合并或下线时保留 stable redirect/alias，使旧资料与保存条件可以迁移到有效节点。
- **TAX-FR-024**：目标地区未完成数据/运营评审时可保留内部节点但不得在公开目录启用。

#### MeiGallery 映射与未知值

- **TAX-FR-030**：每个 legacy 标签映射记录来源系统、旧 ID/值、目标 stable ID、映射类型、规则版本、操作者和时间。
- **TAX-FR-031**：映射类型至少包含 `exact`、`alias`、`split_required`、`unsupported` 和 `pending_review`；不可用自由文本默认为 `pending_review`。
- **TAX-FR-032**：未知标签可以创建不可公开候选词条，但不能自动 active 或直接影响公开资料、搜索和推荐。
- **TAX-FR-033**：一个 legacy 值需要拆分到多个词条时必须人工确认或使用已批准、版本化规则；规则不得静默改变已完成批次。
- **TAX-FR-034**：映射任务幂等，重复运行不复制词条、alias 或资料关联；结果可按批次对账和回滚未发布映射。
- **TAX-FR-035**：现有 Web 在迁移窗口继续使用 legacy 标签，v2 通过映射/投影读取，不进行无归属双写。

#### 合并、停用与归档

- **TAX-FR-040**：词条被资料、规则、保存筛选或路由引用时不得物理删除；使用 deprecated、merged 或 archived 表达生命周期。
- **TAX-FR-041**：合并前展示受影响资料、规则、保存条件、页面路由、别名和语言版本；确认后把源词条指向唯一目标词条。
- **TAX-FR-042**：合并是幂等 Workflow；源 stable ID 保留只读重定向，旧客户端请求可解析到目标，不扩大筛选集合。
- **TAX-FR-043**：deprecated 词条不再用于新标注，但可在兼容窗口继续显示；hidden 词条不进入公开目录但保留内部引用。
- **TAX-FR-044**：词条归档前必须清除或迁移所有有效公开关联；归档后不能直接恢复 active，需重新审核。
- **TAX-FR-045**：错误合并采用新版本和补偿映射纠正，不删除历史或复用 stable ID。

#### 目录发布与客户端同步

- **TAX-FR-050**：公开 taxonomy/地区目录以不可变 catalog version 发布，包含生效时间、目标地区/渠道、条目和兼容映射。
- **TAX-FR-051**：客户端缓存目录时保存版本和 ETag；版本更新后刷新，不将显示名当本地业务键。
- **TAX-FR-052**：旧客户端收到未知类型时隐藏对应入口或使用通用标签，不崩溃、不错误归类、不扩大权限。
- **TAX-FR-053**：保存筛选加载已合并/停用词条时自动解析兼容映射并提示用户确认；无法解析时标记条件失效而不扩大搜索。
- **TAX-FR-054**：目录发布失败时继续提供上一完整版本或安全空目录，不返回跨版本混合结果。

#### 后台页面、审计与指标

- **TAX-FR-060**：后台提供按类型树/列表、词条详情、alias、映射、引用影响、版本差异、审核队列和 catalog 发布历史。
- **TAX-FR-061**：所有创建、编辑、审核、合并、停用、归档、映射和目录发布记录原因、操作者、前后状态、版本和请求 ID。
- **TAX-FR-062**：指标至少包括 active 词条数、未知率、映射覆盖率、重复/合并率、无结果筛选、失效保存条件和目录同步错误。
- **TAX-FR-063**：不得公开按敏感标签统计的个体名单；运营分析使用满足最小样本和权限要求的聚合。

### 6.2 主流程

```text
创建/导入候选词条 → 校验重复、层级与敏感性
→ 分类审核 → 发布 catalog version → App/搜索/推荐同步
```

```text
选择合并/停用 → 影响预览 → 审批
→ 更新兼容映射和引用投影 → 发布新目录版本 → 对账
```

### 6.3 类型与公开性矩阵

| 类型 | 是否层级化 | 默认公开粒度 | 主要用途 |
|------|------------|--------------|----------|
| 地区 | 是 | 城市/模糊区域 | 浏览、筛选、推荐理由 |
| 身份/性格 | 可选 | 审核后最小展示 | 资料摘要、筛选 |
| 风格/职业 | 可选 | 审核后展示 | 搜索、筛选、推荐 |
| 发型/服饰/场景 | 可选 | 审核后展示 | 内容分类 |
| 内容类型 | 是 | 审核后展示 | 图库与媒体入口 |

|------|----------|----------|----------|----------|------------|
| 关联 active 词条 | 允许 | 允许 | 只读 | 只读 | 按角色 |
| 创建/编辑草稿 | 建议候选 | 允许 | 只读 | 建议候选 | 按角色 |
| 激活/合并/归档 | 不允许 | 提交 | 允许 | 不允许 | 按独立权限/只读 |

### 6.5 异常与恢复矩阵

| 异常 | 处理 | 客户端影响 |
|------|------|------------|
| 未知 legacy 标签 | 待审核，不公开 | 不显示 |
| 层级循环/重复 alias | 阻止提交 | 无影响 |
| 目录发布失败 | 保留上一完整版本 | 继续旧目录 |
| 保存条件引用 merged | 自动解析并提示 | 不丢失条件 |
| 保存条件引用 archived | 标记失效 | 不扩大查询 |
| 错误合并 | 补偿版本与映射 | 下次目录刷新修复 |

### 6.6 Non-Functional Requirements

- **TAX-NFR-001**：stable ID 永不复用；目录、映射和规则引用使用 ID + catalog version，不使用展示名判断。
- **TAX-NFR-002**：taxonomy 发布采用不可变版本、原子切换、ETag、灰度和快速回滚。
- **TAX-NFR-003**：合并/迁移 Workflow 幂等、可重试、逐项对账，并防止并发版本覆盖。
- **TAX-NFR-004**：公开目录不包含内部敏感标签、精确位置、证据或未审核 alias。
- **TAX-NFR-005**：目录更新能触发搜索、推荐和公开投影的一致性刷新，并具备差异告警。
- **TAX-NFR-006**：后台树、列表、差异和影响预览支持键盘、缩放、屏幕阅读器和非颜色状态。
- **TAX-NFR-007**：目录 API 在目标规模下支持缓存和增量/全量恢复；具体容量在技术方案压测后冻结。
- **TAX-NFR-008**：旧客户端未知类型和状态始终 fail-safe，不渲染错误入口或扩大筛选。

### 6.7 实施前门禁

- OQ-002/OQ-024：首发地区层级、公开粒度、数据位置和运营范围。
- OQ-006：MeiGallery 旧标签及其资料用途是否可迁移。
- OQ-020：历史目录、映射和敏感分类审计的保留期。
- OQ-023：哪些分类允许作为推荐信号和用户解释。

## 7. Acceptance Criteria

- **TAX-AC-001**：Given 内容编辑输入未知标签，When 保存导入草稿，Then 只生成待审核候选且不进入公开筛选或推荐。
- **TAX-AC-002**：Given 两个展示名不同但 alias 相同的词条，When 提交激活，Then 系统提示冲突并阻止未经确认的重复。
- **TAX-AC-003**：Given 词条被公开资料和保存条件引用，When 管理员尝试物理删除，Then 服务端拒绝并提供停用/合并流程。
- **TAX-AC-004**：Given 词条 A 合并到 B，When 旧客户端请求 A，Then 解析到 B 或安全失效，不扩大到 B 之外的结果。
- **TAX-AC-005**：Given 会员保存的筛选引用已合并词条，When 重新打开，Then 条件被迁移并明确提示，不静默丢失。
- **TAX-AC-006**：Given 地区节点包含精确坐标或住址，When 提交公开目录，Then 隐私校验阻止发布。
- **TAX-AC-007**：Given 一个词条仅为 hidden，When App 请求公开分类，Then 不返回该词条，但现有内部映射保持有效。
- **TAX-AC-008**：Given 目录发布中断，When App 刷新，Then 只获得上一完整版本或新完整版本，不出现混合目录。
- **TAX-AC-009**：Given 推荐规则引用 taxonomy stable ID，When 展示名被修改，Then 规则语义不变且新文案随目录版本更新。
- **TAX-AC-010**：Given migration 同一批次重复运行，When 映射已存在，Then 不复制词条、alias 或资料关联。
- **TAX-AC-011**：Given 旧客户端收到新标签类型，When 解析目录，Then 安全隐藏/通用展示，不崩溃且不扩大权限。
- **TAX-AC-012**：Given 审计查询一个 active 词条，When 查看时间线，Then 可追溯创建、审核、版本、alias、映射、合并和当前引用。

## 8. Out of Scope

- 用户自由创建公开标签、地区或分类。
- 保存精确地址、GPS 轨迹或以距离展示真人位置。
- 使用标签自动推断种族、健康、政治、宗教、性取向等敏感属性。
- 仅凭名称相似自动合并词条或真人。
- 用 taxonomy 状态替代真人认证、发布或媒体授权。
- App 1.0 多语言完整运营；模型保留本地化字段，具体语言随未来地区立项。
