## 3. Goal

### Problem

App 1.0 暂不接入 APNs、FCM 或其他系统推送，但平台话题回复、关注更新、会员发放/到期、管理员调币、安全处置和数据导出等异步结果仍需要可靠触达。若每个模块各自显示提醒，会产生重复红点、不可控营销、失效链接、敏感内容预览和多设备未读不一致。

### Solution

建立统一站内通知中心。业务事件通过版本化通知模板生成不可混淆的通知记录，客户端通过 HTTP 拉取列表和未读数；已连接实时通道只发送“有新通知”的刷新信号。通知按消息、互动、会员/金币、系统/安全和营销分类，必要账号、安全与账务通知不可被营销开关屏蔽，跳转前重新校验目标资源和权限。

### Impact

- 在不依赖系统推送的情况下完成 App 1.0 异步结果闭环。
- 统一红点、已读、多设备同步、通知偏好和失效状态。
- 避免在通知摘要、日志或深链中泄露平台话题正文和敏感信息。
- 为未来系统推送复用事件和模板，但不提前引入 SDK 或权限申请。

## 4. User Personas

| Persona | 目标 | 约束与关注点 |
|---------|------|--------------|
| 观看者/会员 | 及时查看消息、互动、权益和安全变化 | 不想被营销淹没，敏感摘要需克制 |
| 关闭个性化用户 | 只接收必要通知并控制可选类别 | 关闭营销不应影响账号/安全/账务结果 |
| 内容/会员/财务运营 | 让业务结果使用统一模板触达 | 不能任意群发或嵌入不安全链接 |
| 客服人员 | 查询用户是否生成/读取关键通知 | 只能查看状态和模板结果，不查看无关正文 |
| 安全/审计人员 | 验证必要通知是否完整送达站内 | 模板、目标和操作均需追溯 |

## 5. User Stories

- 作为用户，我想在一个页面按类别查看通知，以便快速找到平台话题、会员、金币或安全信息。
- 作为用户，我想知道每类未读数量并一键标为已读，以便管理红点。
- 作为用户，我想关闭营销和非必要互动通知，同时继续接收账号、安全和账务结果。
- 作为用户，我想从通知打开对应会话、真人、会员、金币明细或任务进度，以便完成下一步。
- 作为用户，我想在目标已下架、消息被撤回或权限失效时看到明确说明，而不是进入错误页面。
- 作为多设备用户，我想在一个设备阅读后其他设备同步已读状态。
- 作为运营，我想使用审核过的模板和业务事件生成通知，以免文案与真实结果不一致。
- 作为客服，我想按事件或用户查询通知状态，以便判断是业务未发生还是用户尚未阅读。
- 作为审计人员，我想还原通知模板版本、业务事件和深链目标，以便处理争议。

## 6. Requirements

### 6.1 Functional Requirements

#### 分类与信息架构

- **NTF-FR-001**：App 1.0 通知中心必须支持 `message`、`interaction`、`membership_coin`、`system_security`、`marketing` 五类稳定 category；未知类别归入安全的“其他通知”，不自动执行动作。
- **NTF-FR-002**：消息中心一级页面继续按“平台话题、互动、会员与金币、系统与安全”展示；营销通知在设置中可独立控制，可按产品设计归入互动信息流但必须显式标记“活动”。
- **NTF-FR-003**：通知列表项至少包含标题、克制摘要、类别、时间、未读状态、事件类型、模板版本、目标类型和可用状态；不得把内部对象 ID 作为用户文案。
- **NTF-FR-004**：消息通知只显示“你有一条新的平台运营回复”等安全摘要；锁屏级预览虽不在 1.0 范围，站内列表也不得直接复制完整平台话题正文。

#### 事件生成与模板

- **NTF-FR-005**：通知只能由已登记业务事件或有权限的后台运营任务生成；客户端不能自行创建权威通知。
- **NTF-FR-006**：App 1.0 事件至少覆盖平台新回复、消息审核结果、会话受限、关注真人更新、会员发放/续期/替换/撤销/到期、管理员加扣币/补偿/冲正、举报/申诉状态、数据导出就绪、注销状态和账号安全事件。
- **NTF-FR-007**：每个事件类型定义 category、必要性、模板、变量 schema、去重键、目标资源、有效期和隐私等级；模板变量不匹配时 fail-closed，不发送拼接错误文案。
- **NTF-FR-008**：通知模板版本发布后不可原地修改；新版本记录适用地区/语言、生效时间、审核人和回滚版本。
- **NTF-FR-009**：同一业务事件和用户使用稳定 `eventRef + templatePurpose` 去重；Queue 重试不得生成重复通知或重复增加未读数。
- **NTF-FR-010**：会员、金币、安全和数据权利通知必须引用权威业务记录，不能由运营人员自由填写结果或金额。

#### 偏好与必要通知

- **NTF-FR-011**：用户可分别配置消息提醒、互动更新和营销活动；会话静音优先于全局消息提醒，但不删除会话内新消息。
- **NTF-FR-012**：账号安全、条款必要更新、会员状态结果、金币账本结果、举报/申诉、导出和注销结果属于必要站内通知，不提供完全关闭，只允许调整非关键聚合展示。
- **NTF-FR-013**：关闭个性化推荐或可选分析不自动改变必要通知；关闭营销后不得再生成新的营销通知，已存在记录可保留至正常过期。
- **NTF-FR-014**：偏好修改跨设备生效并记录策略版本；客户端离线修改需在服务端确认后才显示成功。

#### 列表、未读与多设备

- **NTF-FR-015**：通知列表按服务端时间倒序并使用游标分页；置顶必要通知必须有明确规则和结束时间，不能无限占据首屏。
- **NTF-FR-016**：支持按 category 查询、标记单条已读和按 category 全部已读；操作幂等，已读时间以服务端首次确认时间为准。
- **NTF-FR-017**：未读数由服务端按 category 计算并返回汇总；本地可以短暂乐观更新，但失败必须回滚，负数或跨设备回退不得出现。
- **NTF-FR-018**：通知状态至少包括 `available`、`read`、`expired`、`withdrawn` 和 `suppressed`；`suppressed` 只在后台可见，用户端不占红点。
- **NTF-FR-019**：多设备收到 `notification.created` 或已读变化后，只把事件作为刷新提示；最终列表、未读数和状态通过 HTTP 获取。

#### 深链与失效处理

- **NTF-FR-020**：深链使用受控 `targetType + targetId + action`，不允许模板写入任意外部 URL；外部帮助链接必须来自受信任域名配置。
- **NTF-FR-021**：打开通知时服务端重新校验账号、对象归属、资料状态、会话权限和客户端 capability；通知存在不等于目标仍可访问。
- **NTF-FR-022**：目标已删除、暂停、撤回、过期或权限不足时，展示通知自身的安全详情和当前不可用原因，不循环跳转或暴露资源存在性。
- **NTF-FR-023**：需要新客户端能力的通知必须配置最低版本；旧客户端显示通用说明和升级入口，不解析未知 action。
- **NTF-FR-024**：金币和会员通知跳转至相应业务详情，并再次读取权威余额/权益；通知中的金额、等级或剩余额度不能直接作为当前状态。

#### 管理、客服与审计

- **NTF-FR-025**：后台提供事件类型、模板版本、生成结果、去重状态、抑制原因和读取状态查询；默认不提供按全体用户导出通知正文。
- **NTF-FR-026**：营销群发需明确目标规则、预计人数、频控、有效期、模板审批和取消计划；App 1.0 是否实际开展营销由运营立项决定，不影响核心通知交付。
- **NTF-FR-027**：必要通知生成失败、模板变量错误、积压、重复率异常和未读数漂移触发监控；补发必须复用原事件引用并防重。
- **NTF-FR-028**：客服只能查看通知类型、生成时间、状态、目标可用性和用户可见文案；访问用户级通知需工单理由并写审计。
- **NTF-FR-029**：模板发布、群发、补发、撤回和必要通知抑制均写审计；普通运营不得删除审计或伪造已读。

#### 分析

- **NTF-FR-030**：至少记录通知生成、抑制、列表曝光、打开、标记已读、深链成功/失效、偏好变更和失败原因事件。
- **NTF-FR-031**：运营指标按 category、eventType、模板版本和时间统计生成成功率、读取率、深链成功率、重复率和积压；不得把安全通知打开率用于营销画像。
- **NTF-FR-032**：分析事件不得包含平台话题正文、内部备注、完整调币原因、身份证明、导出下载地址或访问凭证。

### 6.2 主流程

#### 业务事件生成通知

```text
业务事务成功
→ 写入稳定事件引用
→ 通知服务匹配事件定义和用户偏好
→ 校验模板变量与去重键
→ 创建站内通知 / 按规则抑制
→ 更新服务端未读数
→ 已连接客户端收到刷新信号
→ 客户端通过 HTTP 拉取权威列表
```

#### 用户打开通知

```text
进入通知中心
→ 拉取分类未读数和列表
→ 打开通知并幂等标记已读
→ 服务端验证目标、归属、状态和 capability
→ 跳转目标页面 / 显示已失效安全详情
→ 多设备刷新已读状态
```

### 6.3 通知必要性矩阵

| 通知类型 | 默认生成 | 用户可关闭新提醒 | 可含内容摘要 | App 1.0 目标 |
|----------|----------|------------------|--------------|--------------|
| 平台新回复 | 是 | 可按会话静音 | 仅安全通用摘要 | 会话 |
| 关注真人更新 | 是 | 是 | 审核通过的公开摘要 | 真人详情 |
| 会员发放/撤销/到期 | 是 | 否 | 等级、期限和结果 | 会员详情 |
| 金币调整/冲正 | 是 | 否 | 变动数量和用户说明 | 金币明细 |
| 举报/申诉/数据权利 | 是 | 否 | 状态和下一步 | 任务详情 |
| 账号与安全 | 是 | 否 | 不含敏感证据 | 安全设置/说明 |
| 营销活动 | 按运营计划 | 是，默认遵循地区规则 | 审核模板 | 活动安全落地页 |

### 6.4 异常与恢复矩阵

| 场景 | 用户表现 | 服务端行为 | 恢复方式 |
|------|----------|------------|----------|
| 实时通道离线 | 无即时红点刷新 | 通知仍持久化 | 下次启动/前台 HTTP 拉取 |
| 重复业务事件 | 仅一条通知 | 去重并记录重复 | 无需用户处理 |
| 模板变量缺失 | 不生成错误文案 | 失败、告警、保留事件 | 修复模板后防重补发 |
| 目标已下架 | 展示已不可用 | 不返回受保护目标 | 返回通知详情/帮助 |
| 未读数漂移 | 刷新后纠正 | 按权威记录重算 | 自动对账或人工 Runbook |
| 关闭营销后仍有旧通知 | 旧记录正常存在 | 不生成新营销通知 | 到期/用户已读后归档 |
| 客户端不支持 action | 显示通用说明 | 不执行深链 | 提示升级或 Web 帮助 |
| 必要通知积压 | 可能延迟但不伪装成功 | 高优先级告警和补发 | 复用事件引用恢复 |

### 6.5 Non-Functional Requirements

- **NTF-NFR-001**：业务事件提交与通知生成采用可恢复 outbox/Queue 语义；至少一次投递下仍保证用户通知幂等。
- **NTF-NFR-002**：通知列表、未读数和偏好为账号私有数据，禁止共享缓存并执行对象级授权。
- **NTF-NFR-003**：通知模板、变量和 action 具有 schema 校验、契约测试、版本兼容和安全默认值。
- **NTF-NFR-004**：通知中心在冷启动、前后台切换、断线和多设备状态下最终一致；实时通道不是唯一可靠交付路径。
- **NTF-NFR-005**：通知标题、摘要、图标、未读和操作支持动态字体、屏幕阅读器、高对比度和非颜色表达。
- **NTF-NFR-006**：平台话题正文、访问凭证、敏感证据和内部备注不得出现在通知 payload、URL、日志、分析或崩溃报告。
- **NTF-NFR-007**：通知生成延迟、失败率、重复率、积压、深链失效率和未读漂移具备监控、分级告警和 Runbook。

### 6.6 实施前门禁

| 门禁 | 对应决策 | 未关闭时允许继续 | 未关闭时禁止 |
|------|----------|------------------|------------|
| 首发地区/必要通知政策 | OQ-002 | 定义分类、事件和模板 schema | 发布生产模板策略 |
| 数据保留期 | OQ-020 | 设计 `expiresAt` 和状态机 | 冻结通知清理 migration |
| 数据权利负责人/SLA | OQ-025 | 设计任务结果通知 | 对外承诺处理时限 |
| 客户端构建/渠道 | OQ-026、OQ-030 | 契约和原型 | 冻结深链与发版配置 |

## 7. Acceptance Criteria

- **NTF-AC-001**：Given App 未接入 APNs/FCM，When 平台生成新回复通知，Then 通知被持久化，在线客户端实时刷新，离线客户端下次 HTTP 拉取可看到。
- **NTF-AC-002**：Given 同一业务事件因 Queue 重试三次，When 通知处理完成，Then 用户只有一条通知且未读数只增加一次。
- **NTF-AC-003**：Given 用户关闭营销通知，When 新营销事件发生，Then 不生成营销通知；会员到期、调币和安全通知仍正常生成。
- **NTF-AC-004**：Given 用户在设备 A 标记某类全部已读，When 设备 B 刷新，Then 服务端未读数一致且不会回退。
- **NTF-AC-005**：Given 通知目标真人已经暂停，When 用户打开通知，Then 不返回受保护资料，显示目标不可用和安全下一步。
- **NTF-AC-006**：Given 平台话题含敏感文本，When 生成新回复通知，Then payload、列表摘要和分析事件均不包含完整平台话题正文。
- **NTF-AC-007**：Given 旧客户端收到未知 action，When 用户打开通知，Then 不执行未知深链、不崩溃，显示通用说明或升级提示。
- **NTF-AC-008**：Given 模板变量不满足 schema，When 消费业务事件，Then 不生成拼接错误通知，任务进入可告警的失败状态且补发保持防重。
- **NTF-AC-009**：Given 管理员调币成功，When 用户打开金币通知，Then 页面重新读取权威余额和分录，而不是直接信任通知中的历史余额。
- **NTF-AC-010**：Given 客服查询通知争议，When 获得工单授权，Then 可查看用户可见文案、事件引用和状态，但不能查看平台话题正文或伪造已读。

## 8. Out of Scope

- App 1.0 的 APNs、FCM、厂商推送、短信、邮件或系统通知权限申请。
- 通过远程配置启用客户端未实现的系统推送、富媒体通知或新原生 action。
- 在通知列表展示完整平台话题正文、证件、内部备注、导出凭证或敏感风控证据。
- 任意外部 URL 深链、未经审核的运营自由文案和无目标范围的全量群发。
- 用户关闭账号、安全、会员、金币或数据权利结果等必要站内通知。
- 用安全通知阅读行为构建营销画像，或向其他用户公开通知/互动排行榜。
- 把实时 WebSocket 作为唯一通知存储和交付机制。
