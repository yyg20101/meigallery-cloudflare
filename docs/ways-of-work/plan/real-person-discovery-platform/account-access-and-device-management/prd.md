## 3. Goal

### Problem

现有 MeiGallery 账号体系以 Web 邮箱登录和 Cookie 会话为主，独立 App 需要面向 Android/iOS 提供可续期、可撤销、可识别设备的会话，同时复用未来共享账号。注册用户只是观看者，不能因为昵称、头像、会员或历史数据映射而成为公开真人。首发地区、应用商店和最终登录适配器尚未冻结，因此产品流程必须稳定，而具体身份提供方可以替换。

### Solution

建立以 `Account`、`AccountIdentity`、`AccountDevice` 和服务端会话为核心的观看者账号流程。App 1.0 至少支持与现有系统可迁移的邮箱身份基线，并通过 capability 决定是否展示手机号或第三方登录；任何身份方式都必须完成相同的条款确认、风险验证、设备登记和服务端授权。用户可查看并远程退出设备，退出或撤权后客户端清理敏感缓存。

### Impact

- 为 Android/iOS 和现有 Web 建立同一账号主体与可迁移身份映射。
- 从产品入口上消除“注册即成为公开真人”的误解。
- 降低凭证泄漏、多设备滥用和会话不可撤销风险。
- 为会员、平台话题、金币、隐私设置和数据权利提供稳定账号前置。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 访客 | 理解产品后安全注册 | 登录方式、条款、资格要求和失败帮助 |
| 新观看者 | 创建只用于浏览和互动的账号 | 不填写公开交友资料，不被自动展示 |
| 已登录观看者 | 在多设备保持安全会话 | 会话续期、设备识别和远程退出 |
| 受限账号用户 | 理解限制并恢复或申诉 | 明确原因、可执行下一步和数据权利 |
| 客服/安全人员 | 处理账号与设备异常 | 最小证据、操作审计和不可见敏感凭证 |

## 5. User Stories

- 作为访客，我想在提交注册前查看条款、隐私和资格要求，以便决定是否继续。
- 作为新观看者，我想使用首发地区支持的身份方式注册，以便进入真人发现功能。
- 作为新观看者，我想明确知道账号头像和昵称不会成为公开真人资料，以免误解产品身份。
- 作为已有 MeiGallery 账号的用户，我想在身份验证后复用同一账号主体，以免产生重复账户。
- 作为已登录用户，我想在会话临近失效时无感续期，以便持续使用 App。
- 作为已登录用户，我想查看设备的名称、平台、最近活动和当前设备标识，以便发现异常登录。
- 作为已登录用户，我想远程退出其他设备，以便在设备丢失或异常时保护账号。
- 作为当前设备用户，我想退出账号后立即清理 Token、平台话题和受保护媒体缓存，以免下一位设备使用者看到数据。
- 作为受限用户，我想看到安全的限制说明和申诉入口，以便恢复账号或行使数据权利。
- 作为使用辅助技术的用户，我想独立完成登录、错误修复和设备退出，以便不依赖他人操作。

## 6. Requirements

### 6.1 Functional Requirements

#### 登录能力与身份边界

- **ACC-FR-001**：App 1.0 注册只创建 `Account` 和登录身份，不得创建 `Person`、`PersonProfile`、真人认证或公开投影。
- **ACC-FR-002**：登录页必须从服务端 capability 读取当前地区、渠道和版本允许的身份方式；未启用方式不得显示空入口。
- **ACC-FR-003**：邮箱身份作为迁移兼容基线；手机号和第三方登录只有在 OQ-002/OQ-030 关闭、适配器和政策验收通过后才可启用。
- **ACC-FR-004**：无论使用何种身份方式，服务端都必须把已验证身份解析到唯一 `accountId`；同一提供方主体不得绑定多个有效账号。
- **ACC-FR-005**：发现可能属于现有 MeiGallery 账号的身份时，系统必须先完成凭证验证或恢复流程再建立映射，不得仅凭相同邮箱、手机号、昵称或头像静默合并。
- **ACC-FR-006**：登录、注册、恢复和高风险操作必须支持服务端下发的人机验证或风险挑战；客户端不得假定固定挑战提供方。

#### 注册与条款

- **ACC-FR-010**：提交注册前必须能打开当前条款、隐私政策、平台话题与运营接收说明、必要资格说明和客服入口。
- **ACC-FR-011**：注册请求必须携带服务端要求的文档版本和用户决定；服务端保存同意记录，不接受客户端自行声明的过期版本。
- **ACC-FR-012**：当条款版本已变化时，服务端返回重新确认要求；用户未确认前只允许访问条款、帮助、退出和法律要求的数据权利入口。
- **ACC-FR-013**：注册成功页和首次引导必须明确“账号仅用于观看和互动，不会进入真人列表”，且不要求填写身高、职业、交友宣言等公开资料。
- **ACC-FR-014**：首次偏好设置可以跳过；跳过时进入非个性化或规则型推荐，不阻塞账号创建。

#### 会话与 Token

- **ACC-FR-020**：App 会话使用服务端签发、可撤销的短期访问凭证和续期凭证；凭证不得写入日志、分析事件、DataStore 或 Room 明文字段。
- **ACC-FR-021**：客户端只在可证明安全且未被撤销时自动续期；续期失败必须进入单次串行恢复，避免并发刷新产生凭证竞争。
- **ACC-FR-022**：服务端每次授权仍需读取账号状态、设备会话版本、角色、风险和必要资格；Token 本身不代表永久权限。
- **ACC-FR-023**：当前设备退出必须撤销当前会话，并清理本地凭证、必要消息、账号缓存和受保护媒体缓存；公开内容缓存可按隐私策略保留。
- **ACC-FR-024**：账号被禁用、删除、凭证轮换或服务端提升 `session_version` 后，相关设备的现有访问与实时连接必须失效。
- **ACC-FR-025**：用户重新登录后不得自动恢复已被服务端撤销的敏感本地数据；必须重新同步权威状态和访问凭证。

#### 设备管理

- **ACC-FR-030**：每个成功登录会话必须关联不可枚举的 `deviceId` 和设备记录，不以可变设备名称作为授权依据。
- **ACC-FR-031**：设备列表至少展示平台、用户可理解的设备名称、最近活动时间、首次登录时间、当前设备标识和状态；不展示广告 ID、硬件序列号或精确位置。
- **ACC-FR-032**：用户可以远程退出非当前设备；服务端撤销该设备全部相关会话并发送站内安全通知。
- **ACC-FR-033**：退出当前设备使用正常退出流程；“退出所有设备”属于高风险动作，必须重新验证并保留当前结果说明。
- **ACC-FR-034**：远程退出请求必须幂等；重复操作返回已退出状态，不因设备不存在而泄漏其他账号设备信息。
- **ACC-FR-035**：设备名称可以由用户修改，但权限判断仍使用服务端设备 ID 和会话版本。

#### 恢复、限制与账号入口

- **ACC-FR-040**：账号恢复必须使用已验证身份或经批准的客服安全流程，不提供仅凭公开资料或真人资料的找回方式。
- **ACC-FR-041**：登录失败应区分凭证错误、验证码失效、挑战失败、频控、账号受限、条款待确认、客户端需升级和网络错误，但不得暴露账号是否存在等可枚举信息。
- **ACC-FR-042**：账号受限页必须展示可公开的限制类型、是否临时、可重试时间、帮助/申诉和数据权利入口，不暴露内部风控阈值。
- **ACC-FR-043**：数据导出、注销、修改绑定和高风险设备操作从“账号与设备”进入；详细保留、撤回和删除规则由 F-13 PRD 冻结。
- **ACC-FR-044**：注销 Workflow 启动后立即阻止新敏感操作；完成、冷静期或取消规则以目标地区决策为准，客户端必须显示当前状态。

#### 页面与状态

- **ACC-FR-050**：至少提供启动检查、登录、注册、身份验证、条款确认、首次偏好、账号受限、设备列表、设备详情和退出结果页面/状态。
- **ACC-FR-051**：所有表单覆盖初始、输入中、提交中、成功、字段错误、服务端错误、离线、频控和需要升级状态；提交中禁止重复请求。
- **ACC-FR-052**：深链打开受保护页面时，登录成功后返回原目标；目标已下架或无权限时进入对应安全状态，不无限跳转。
- **ACC-FR-053**：会话失效时优先保存不含敏感正文的导航意图；重新登录后重新校验目标权限。

#### 埋点与运营

- **ACC-FR-060**：允许记录登录页曝光、身份方式选择、注册开始/完成、挑战结果类别、条款版本确认、会话恢复结果和设备退出结果。
- **ACC-FR-061**：账号分析事件只记录匿名会话 ID、身份方式枚举、结果代码、客户端版本和耗时，不记录邮箱、手机号、Token、验证码或设备指纹。
- **ACC-FR-062**：安全团队可按脱敏聚合查看异常失败率、刷新失败率、远程退出量和受限账号申诉量。

### 6.2 主流程

```text
启动 → 获取公开配置/最低版本 → 选择登录或注册
→ 完成身份验证与风险挑战 → 确认有效条款
→ 服务端创建/解析 Account 与 Device Session
→ 可跳过偏好设置 → 进入推荐首页
```

远程退出：

```text
我的 → 账号与设备 → 选择其他设备 → 二次确认
→ 服务端撤销设备会话 → 站内安全通知 → 列表显示已退出
```

### 6.3 权限矩阵

| 操作 | 访客 | 账号本人 | 客服/安全 | 其他用户 |
|------|------|----------|-----------|----------|
| 查看公开登录配置/条款 | 允许 | 允许 | 允许 | 允许 |
| 查看本人设备 | 不允许 | 允许 | 默认不允许；工单授权后最小查看 | 不允许 |
| 退出本人设备 | 不允许 | 允许 | 仅批准的恢复流程 | 不允许 |
| 查看凭证明文/验证码 | 不允许 | 不允许 | 不允许 | 不允许 |
| 修改账号状态 | 不允许 | 不允许 | 按角色、原因和审批 | 不允许 |

### 6.4 状态与异常矩阵

| 场景 | 用户界面 | 服务端结果 |
|------|----------|------------|
| 无网络启动 | 展示离线说明；只允许非敏感公开缓存 | 不创建会话 |
| 身份验证失败 | 保留非敏感输入，展示安全错误 | 不披露账号存在性 |
| 条款已更新 | 打开新版本并要求重新确认 | 限制敏感 API |
| 刷新凭证失效 | 进入重新登录，保留目标导航意图 | 撤销本地会话 |
| 远程退出当前设备 | 下次请求/实时事件触发退出页 | 拒绝旧凭证 |
| 账号受限 | 展示限制、帮助和申诉 | 拒绝受限操作 |
| 客户端版本过低 | 展示强制升级，不循环重试 | 返回 `APP_UPGRADE_REQUIRED` |

### 6.5 Non-Functional Requirements

- **ACC-NFR-001**：访问凭证和续期凭证分别存入 Android Keystore/iOS Keychain 支持的安全存储，公共层只依赖安全存储端口。
- **ACC-NFR-002**：账号、设备和会话 API 禁止共享缓存；所有对象访问执行服务端账号归属校验。
- **ACC-NFR-003**：登录、注册、恢复和远程退出具备速率限制、重放保护、请求关联 ID 和安全审计。
- **ACC-NFR-004**：单次会话刷新失败不得引发请求风暴；并发业务请求共享同一刷新结果。
- **ACC-NFR-005**：页面支持动态字体、屏幕阅读器、键盘/外接输入、减少动态效果和不依赖颜色的错误提示。
- **ACC-NFR-006**：账号相关日志和崩溃报告经过自动扫描，不得包含身份标识明文、验证码、Cookie、Token 或签名 URL。
- **ACC-NFR-007**：登录适配器不可用时只隐藏该方式；至少一个已验收的首发身份方式可用，否则停止开放注册并保留帮助入口。
- **ACC-NFR-008**：远程退出和账号禁用的撤权应在下一次 API 调用即时生效，并主动关闭可定位到的实时连接。

### 6.6 实施前门禁

- OQ-002/OQ-024：首发地区、数据位置与跨境结论。
- OQ-003：资格/年龄门槛及需要保存的最小证明。
- OQ-020：账号、设备、同意和安全证据保留期。
- OQ-027：iOS 最低版本。
- OQ-030：首发应用商店、最终登录方式和身份适配器。

未关闭上述门禁前可以完成领域模型、状态机、通用 UI 和契约草案，但不得冻结生产身份 schema 或发布注册功能。

## 7. Acceptance Criteria

- **ACC-AC-001**：Given 新用户完成注册，When 管理员查询真人供给，Then 不存在由该账号自动生成的 `Person`、`PersonProfile` 或公开投影。
- **ACC-AC-002**：Given 服务端只启用邮箱身份，When 打开登录页，Then 只显示已启用方式且不存在手机号/第三方空入口。
- **ACC-AC-003**：Given 已有 MeiGallery 身份命中候选账号，When 用户未完成原身份验证，Then 系统不自动合并账号。
- **ACC-AC-004**：Given 当前条款版本高于用户已同意版本，When 用户尝试进入推荐或平台话题，Then 先完成新条款确认且保存版本化记录。
- **ACC-AC-005**：Given 多个请求同时遇到访问凭证过期，When 客户端执行续期，Then 只产生一次有效刷新，其他请求复用结果。
- **ACC-AC-006**：Given 用户远程退出另一设备，When 该设备继续请求 API 或保持实时连接，Then 访问被拒绝、连接关闭且敏感缓存进入清理流程。
- **ACC-AC-007**：Given 用户退出当前账号，When 离线重新打开 App，Then 看不到上一账号平台话题、受保护媒体或凭证明文。
- **ACC-AC-008**：Given 账号被安全限制，When 用户登录，Then 看到不泄漏策略的限制原因、申诉和数据权利入口。
- **ACC-AC-009**：Given 攻击者枚举不同邮箱，When 触发注册/恢复错误，Then 响应不直接确认某个账号是否存在。
- **ACC-AC-010**：Given 动态字体和屏幕阅读器开启，When 完成注册、错误修复和远程退出，Then 所有控件可理解、可聚焦且关键文字不截断。
- **ACC-AC-011**：Given App 1.0 构建，When 扫描依赖和运行权限，Then 不包含支付或系统推送 SDK，也不请求对应权限。
- **ACC-AC-012**：Given 客户端版本低于服务端最低版本，When 访问账号入口，Then 展示单一可恢复升级路径且不发生登录循环。

## 8. Out of Scope

- 普通观看者创建、编辑或认领公开真人资料。
- App 1.0 在线支付身份、银行卡、商店订单和系统推送 Token。
- 在首发地区和登录适配器未决前承诺手机号或特定第三方登录。
- 企业 SSO、匿名账号、游客互动、家庭账号和账号转让。
- 以设备指纹、广告 ID、精确位置或通讯录作为账号必填条件。
- 详细的数据导出包、注销保留期和删除例外；由 F-13 独立 PRD 冻结。
