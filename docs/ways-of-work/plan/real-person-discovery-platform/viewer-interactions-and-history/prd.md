## 3. Goal

### Problem

观看者需要用不同强度保存感兴趣的真人，但“喜欢、关注、收藏”容易被误解为双方匹配或对方收到关系信号。浏览历史又会直接影响推荐与隐私，如果记录、清除、下架和拉黑后的行为没有明确规则，可能出现跨账号泄漏、撤销不彻底和推荐继续使用已清除记录等问题。

### Solution

建立四类独立、仅属于观看者的单向关系：喜欢用于轻量偏好，关注用于订阅已发布更新，收藏用于长期归档和文件夹，浏览历史用于本人回看。所有写入由服务端按 `accountId + profileId + type` 幂等处理，不产生匹配、对方通知或普通用户聊天。用户可撤销、整理和清除；下架、拉黑、注销和隐私设置触发统一抑制与删除 Workflow。

### Impact

- 提升详情回访、内容订阅、收藏整理和推荐反馈质量。
- 避免单向互动被误解为对方喜欢、匹配或已建立关系。
- 让用户可以控制哪些行为用于推荐以及保留多久。
- 为平台话题、通知和推荐提供稳定但最小化的互动信号。

## 4. User Personas

| Persona | 目标 | 主要关注点 |
|---------|------|------------|
| 普通观看者 | 保存和回看感兴趣的真人 | 操作可撤销、不同关系含义清楚 |
| 心享会员 | 使用更多收藏整理能力 | 额度透明，降级不丢失已有数据 |
| 隐私敏感用户 | 清除历史并关闭相关推荐使用 | 跨设备生效，不再继续用于个性化 |
| 内容运营 | 理解聚合互动趋势 | 不查看具体观看者名单或敏感偏好 |
| 客服/审核 | 处理下架、拉黑和删除争议 | 最小证据、状态可追溯、无越权 |

## 5. User Stories

- 作为观看者，我想喜欢某个真人，以便表达轻量偏好并改善推荐。
- 作为观看者，我想关注真人，以便在其发布新内容时收到站内更新。
- 作为观看者，我想把真人收藏到文件夹，以便长期整理和回看。
- 作为观看者，我想分别撤销喜欢、关注和收藏，以便控制自己的记录。
- 作为观看者，我想查看和清除浏览历史，以便管理隐私。
- 作为观看者，我想知道三类操作不会产生匹配或通知真人，以免误解。
- 作为会员降级用户，我想保留已有收藏夹内容，以免等级变化造成数据丢失。
- 作为拉黑用户，我想目标立即从推荐和个人内容中心消失，以免继续接触。
- 作为收藏过下架资料的用户，我想看到最小不可用说明并能移除记录，以便理解状态。
- 作为辅助技术用户，我想独立区分并操作喜欢、关注和收藏，以便完成内容管理。

## 6. Requirements

### 6.1 Functional Requirements

#### 关系语义与边界

- **VIR-FR-001**：喜欢、关注、收藏和浏览历史都是 `Account → PersonProfile` 的单向私有关系，不存在 reciprocal、matched、mutual 或配对状态。
- **VIR-FR-002**：只有已登录且账号状态允许的观看者可以写入互动；访客点击时进入登录说明，不创建临时云端关系。
- **VIR-FR-003**：真人是否已有账号、是否认领或是否由平台运营，不改变互动的单向性质。
- **VIR-FR-004**：喜欢、关注或收藏不得自动创建会话、消耗会员额度、授予会员权限或向目标真人/运营人员发送“某用户喜欢你”通知。
- **VIR-FR-005**：用户侧不得展示关注者/喜欢者名单、相互喜欢或关系排名；如展示聚合热度，只能使用抗刷、最小化且不披露个人身份的结果。

#### 喜欢

- **VIR-FR-010**：喜欢用于轻量偏好和推荐反馈，与关注、收藏分别保存；同一资料只有一个当前喜欢状态。
- **VIR-FR-011**：喜欢和取消喜欢使用幂等 PUT/DELETE；重复同一目标状态返回权威结果，不重复增加聚合计数。
- **VIR-FR-012**：取消喜欢后立即从“喜欢”列表移除，并不再把该喜欢作为新推荐会话的正向信号；依法保留的安全/审计证据不参与推荐。
- **VIR-FR-013**：客户端可乐观更新喜欢图标，但服务端失败、账号受限或资料不可用时必须回滚并展示明确结果。

#### 关注与更新

- **VIR-FR-020**：关注表示订阅真人资料后续公开更新，不表示订阅平台话题、在线状态或真人本人动态。
- **VIR-FR-021**：关注/取消关注幂等且独立于喜欢和收藏；取消关注不自动取消其他两类关系。
- **VIR-FR-022**：关注更新只包含审核并发布的新资料版本或内容，不发送草稿、审核中、内部运营或受保护内容摘要。
- **VIR-FR-023**：App 1.0 关注更新通过关注页和站内通知呈现，不依赖系统推送；相同发布事件对同一用户去重。
- **VIR-FR-024**：资料暂停、归档或授权失效后停止新关注更新；恢复后不补发暂停期间未公开事件，除非存在新有效发布版本。

#### 收藏与文件夹

- **VIR-FR-030**：收藏用于长期归档；系统提供不可删除的“全部收藏”聚合视图和至少一个默认收藏位置。
- **VIR-FR-031**：用户可创建、重命名、排序和删除自定义收藏夹；名称只对本人可见，并执行长度、重复名和内容安全校验。
- **VIR-FR-032**：同一真人可进入多个自定义收藏夹；全局收藏状态在至少一个有效收藏关系存在时为 true。
- **VIR-FR-033**：从某一文件夹移除不影响其他文件夹；取消全局收藏需明确确认并移除该资料的全部文件夹关系。
- **VIR-FR-034**：自定义收藏夹数量由稳定 `favorite.folder_count` entitlement 控制；单夹容量先由版本化策略提供技术上限，未来若形成会员差异须新增稳定 entitlement，不按会员展示名硬编码。
- **VIR-FR-035**：会员到期或配置降低额度时不得自动删除超额文件夹和内容；已有数据保持可读、可移除，达到新额度前不能继续新增。
- **VIR-FR-036**：删除收藏夹必须展示影响数量；删除后其中仅存于该文件夹的资料同步取消全局收藏，多处存在的资料继续保留。

#### 浏览历史

- **VIR-FR-040**：只有真人详情成功加载且达到可配置的有效浏览条件后才写入历史；卡片曝光、预取和失败详情不计入浏览历史。
- **VIR-FR-041**：同一真人重复浏览更新 `lastViewedAt` 和必要次数摘要，不在列表生成无限重复行。
- **VIR-FR-042**：浏览历史仅账号本人可见，按最近浏览分页，支持逐条删除和全部清除。
- **VIR-FR-043**：删除历史后立即从本人页面、本地缓存和新推荐信号中移除；服务端异步完成受保留策略约束的下游清理。
- **VIR-FR-044**：历史默认保留期和会员差异由 OQ-020/OQ-014 关闭后配置；到期自动删除，不因会员降级延长保留。
- **VIR-FR-045**：关闭浏览历史时不再创建新记录；详情浏览仍可产生必要的安全、计费外或匿名性能事件，但不得用于账号个性化推荐。

#### 个人内容中心

- **VIR-FR-050**：“关注”一级页作为个人内容中心，默认提供关注更新、喜欢、收藏夹和浏览历史二级入口；最终排布以 OQ-005 高保真结论为准。
- **VIR-FR-051**：四类列表分别提供加载、空、错误、离线、资料不可用、权限不足和同步冲突状态，文案不使用“匹配”“对方回应”等表达。
- **VIR-FR-052**：跨设备以服务端状态为准；客户端离线缓存只读，联网后按更新时间/版本同步，不把陈旧 true 状态覆盖已撤销关系。
- **VIR-FR-053**：分页项返回各关系的权威状态和资料可用性；客户端不得仅根据本地列表推导全局关系状态。

#### 下架、拉黑与账号状态

- **VIR-FR-060**：资料暂停/归档后从新推荐和关注更新移除；喜欢、收藏、历史列表只保留最小不可用占位和移除入口，不返回受保护媒体。
- **VIR-FR-061**：用户拉黑真人时立即停止推荐、关注更新、新互动和消息，并取消当前喜欢、关注、收藏关系及可见历史；解除拉黑不自动恢复任何旧关系。
- **VIR-FR-062**：账号注销 Workflow 必须处理互动和历史的删除/匿名化；法定保留数据与推荐、产品页面和普通运营查询隔离。
- **VIR-FR-063**：账号受限时按安全策略将互动写入设为拒绝或只读，不能通过离线队列绕过限制。

#### 埋点与指标

- **VIR-FR-070**：至少记录喜欢/关注/收藏的请求结果、收藏夹管理、历史清除、个人中心访问、下架占位移除和拉黑联动结果。
- **VIR-FR-071**：事件包含对象稳定 ID、入口、动作、结果代码、规则/entitlement 版本和客户端版本，不包含收藏夹名称、搜索原文或个人身份明文。
- **VIR-FR-072**：核心指标包括互动成功率、撤销率、关注更新打开率、收藏回访率、历史清除率、同步冲突率和资料不可用占比。
- **VIR-FR-073**：聚合互动计数必须排除已识别刷量、受限账号和回滚写入；不得作为认证真实性或安全处置优先级依据。

### 6.2 主流程

```text
推荐/搜索/详情 → 喜欢、关注或收藏
→ 服务端幂等写入 → 客户端更新权威状态
→ 个人内容中心回看、整理或撤销
```

```text
详情有效浏览 → 写入/更新浏览历史
→ 历史页回看 → 逐条删除/全部清除/关闭后续记录
```

| 异常 | 客户端行为 | 服务端结果 |
|------|------------|------------|
| 重复点击 | 合并在途请求，展示处理中 | 幂等返回当前状态 |

### 6.6 Non-Functional Requirements

- **VIR-NFR-001**：关系表使用账号、资料和类型唯一约束，收藏夹条目使用文件夹与资料唯一约束。
- **VIR-NFR-002**：写接口支持幂等、条件写和权威响应；重复请求不得造成计数漂移或重复通知。
- **VIR-NFR-003**：互动列表、历史和收藏夹属于私有响应，禁止共享缓存并执行对象归属校验。
- **VIR-NFR-004**：清除、拉黑和注销 Workflow 有可观测进度、失败重试、下游清理和对账，不以客户端隐藏代替服务端处理。
- **VIR-NFR-005**：互动和历史不写入通用日志明细；分析采用最小化稳定 ID 和聚合结果。
- **VIR-NFR-006**：关系按钮具有明确可访问名称、当前状态和结果提示；大字体下不依赖图标或颜色区分。
- **VIR-NFR-007**：列表采用游标分页、稳定排序和去重；资料状态变化不会使客户端无限刷新或重复条目。
- **VIR-NFR-008**：推荐信号使用与用户设置、清除状态一致的投影；关闭或删除后的行为不得继续进入新规则版本。

### 6.7 实施前门禁

- OQ-005：个人内容中心最终导航和默认入口。
- OQ-014：收藏夹/历史相关 entitlement 与额度。
- OQ-020：互动、历史、清除请求和必要安全证据的保留期。
- OQ-023：哪些互动信号可进入个性化、说明方式和关闭后的处理。

### 6.8 Interaction-1 保守开发基线

Interaction-1 只冻结喜欢与关注的账号私有关系，供 App 1.0 开发和本地/独立测试环境验证：

- 只有已登录且状态正常的观看者可写；访客只进入登录说明，不创建本地待同步关系。
- 喜欢与关注使用独立的 `Account + PersonProfile + type` 唯一关系；PUT/DELETE 均幂等，互不联动。
- 新增关系前必须重新校验资料仍满足认证、发布、用途授权、有效期、可见性和来源图库发布条件。
- 取消操作即使资料已不可见也必须可执行，避免用户无法清理自己的关系。
- 本人列表使用私有响应、稳定游标和服务端权威状态；资料失效时只返回最小不可用占位，不返回封面、标签或其他公开字段。
- 本阶段不生成目标侧通知、不开放互动者名单、不创建会话、不写聚合热度，也不把互动直接接入推荐信号。
- Interaction-1 只提供“已关注”基础列表；发布更新流与去重站内通知由 Interaction-3 独立契约和 capability 控制，不能随 `follow=true` 自动启用。
- 收藏、收藏夹、浏览历史、拉黑联动 Workflow 和数据保留任务不属于 Interaction-1；不得用扁平收藏临时表替代未来多文件夹模型。

开发能力随 Auth capability 最小权限启用；生产 Auth 未通过既有上线门禁前，Interaction-1 不得对外开放。

### 6.9 Interaction-2 服务端开发基线

Interaction-2 在不关闭 OQ-014、OQ-020、OQ-023 的前提下，冻结多文件夹收藏与浏览历史服务端契约：

- 收藏使用独立默认/自定义文件夹与条目表，不向 Interaction-1 关系表增加 `favorite`；同一人物可在多个文件夹，全局取消才删除全部关系。
- 默认文件夹不可删除；自定义文件夹使用客户端随机稳定 ID 幂等创建，编辑/删除使用版本条件。当前额度读取可执行 entitlement，降级保留已有数据并拒绝超额新增。
- 浏览历史默认关闭，只有显式开启、详情成功呈现且携带当前历史版本时才记录；卡片曝光、预取和详情失败不得调用记录接口。
- 逐条删除和全部清除都会原子提升历史版本，操作前的在途请求不得重新写回；关闭记录保持账号私有、服务端权威。
- 屏蔽人物同步清理喜欢、关注、收藏和当前可见历史，解除屏蔽不恢复；失效资料仅返回最小不可用占位。
- 当前只完成服务端代码、D1 schema 和 OpenAPI，运行门禁保持关闭；KMP、配置、migration、专项测试、远端联调和自动清理均按开发顺序后置。

详细边界见 `docs/app/INTERACTION_2_FAVORITES_HISTORY_INTEGRATION.md`。

### 6.10 Interaction-3 服务端开发基线

Interaction-3 在不接系统推送、不新增第二套发布事实、不向目标真人披露关注者身份的前提下，冻结关注更新与站内提醒：

- 更新事实直接读取 `person_publication_reviews` 已审核 `published` 记录；事件必须晚于当前关注建立时间与版本化策略生效时间。
- `/api/v2/me/follow-updates` 以账号绑定游标返回稳定更新 ID、资料/投影版本、发布时间和当前仍公开的人物卡片；不返回草稿、内部审核信息或受保护内容。
- 站内提醒在用户 HTTP pull 时按账号惰性写入 Message-3 Outbox，相同账号与发布事件只保留一项，不在发布事务同步枚举全部关注者。
- 投递前重验当前关注、屏蔽、认证、发布、授权、有效期、可见性与来源图库；取消关注或失效后的待投递项永久抑制，恢复时不补发旧事件。
- bootstrap 独立返回 `interactions.followUpdates`；Auth、运行开关、策略版本和 production-ready 任一缺失都安全关闭。
- 当前只完成服务端代码、D1 schema；其接口已包含在当前累计 OpenAPI `1.15.0` 中。KMP、配置、migration、专项测试和远端联调统一后置。

详细边界见 `docs/app/INTERACTION_3_FOLLOW_UPDATES_INTEGRATION.md`。

## 7. Acceptance Criteria

- **VIR-AC-001**：Given 用户同时喜欢、关注并收藏同一真人，When 查看关系，Then 系统保存三条独立语义且不创建匹配或会话。
- **VIR-AC-002**：Given 用户重复发送相同喜欢请求，When 请求到达多次，Then 只存在一个关系且聚合计数不重复增加。
- **VIR-AC-003**：Given 用户取消喜欢，When 开始新推荐会话，Then 已取消喜欢不再作为正向推荐信号。
- **VIR-AC-004**：Given 真人发布新审核内容，When 关注者打开 App，Then 收到去重的站内更新且目标真人不收到关注者身份通知。
- **VIR-AC-005**：Given 用户把同一真人放入两个收藏夹，When 从其中一个移除，Then 另一收藏关系和全局收藏状态仍存在。
- **VIR-AC-006**：Given 用户删除某收藏夹，When 资料仍在其他文件夹，Then 不取消其全局收藏。
- **VIR-AC-007**：Given 会员到期后收藏夹数量超过新额度，When 打开收藏，Then 已有内容可读可删、不会丢失，但不能继续超额创建。
- **VIR-AC-008**：Given 卡片仅曝光或详情加载失败，When 查看浏览历史，Then 不产生历史记录。
- **VIR-AC-009**：Given 用户清除全部历史并关闭记录，When 再浏览详情并请求推荐，Then 历史页为空且新推荐不使用账号浏览历史。
- **VIR-AC-010**：Given 已收藏资料被暂停，When 从收藏打开，Then 只显示不可用说明和移除入口，不展示受保护媒体。
- **VIR-AC-011**：Given 用户拉黑真人，When Workflow 完成，Then 关系和可见历史被取消、推荐/更新/消息停止；解除拉黑不恢复旧关系。
- **VIR-AC-012**：Given 另一账号尝试读取用户收藏夹，When 使用可枚举或已知 ID 请求，Then 服务端拒绝且不泄漏存在性。
- **VIR-AC-013**：Given 乐观关注操作被服务端拒绝，When 响应返回，Then UI 回滚并且不显示订阅成功。
- **VIR-AC-014**：Given 屏幕阅读器开启，When 聚焦喜欢、关注和收藏按钮，Then 可听到动作、当前状态和操作结果。

## 8. Out of Scope

- 双向喜欢、匹配、配对成功、打招呼和用户之间聊天。
- 向目标真人或平台运营展示具体喜欢者、关注者、收藏者名单。
- 公开收藏夹、社交分享收藏列表和协作收藏。
- 离线写入队列、跨账号合并互动和恢复拉黑前关系。
- 以互动数量承诺真人真实性、本人在线或一定回复。
- 平台话题、会员发放、礼物、评论和系统推送。
