# 首页真实案例与导航体验优化 PRD

### 1. Executive Summary

**Problem Statement**: 当前首页首屏按钮、地区发现区、底部加载更多和联系方式入口存在视觉干扰，用户反馈标签入口不明显，按城市查找内容的路径不够直接。站点已正式上线，后续开发需要与生产访问隔离，避免未完成的首页、案例和导航改版影响线上用户。

**Proposed Solution**: 以 `frontend-design` 指导 UI 方向，将首页调整为“珍珠杂志感 + 可信好评案例 + 明确标签导航”的体验：移除轮播图两个按钮，用真实案例轮播替代按地区发现，新增公开真实案例列表页和详情页，重做标签导航和悬浮联系入口，并新增可配置规则/引导悬浮窗。后续开发通过 Workers dev 子域进行测试，可读取正式数据但使用独立 dev Web/API Worker，确认后再本地部署生产。

**Success Criteria**:

- 首页首屏轮播图不再显示“浏览精选图库”和“地区精选”两个按钮，桌面端和移动端视觉焦点集中在封面、标题和内容本身。
- 首页标签导航在 375px、768px、1440px 三档宽度下首屏或首屏后一屏内可见，用户从首页进入具体城市结果页的点击路径不超过 2 次。
- 真实案例轮播在桌面端和移动端均可正常浏览，一个案例支持 2-9 张图片，图片加载失败率 P95 低于 1%。
- 真实案例列表页和详情页全部公开访问，用户从首页真实案例区进入案例详情的点击路径不超过 2 次。
- 联系站长悬浮入口点击率较改版前提升 20% 以上，统计口径为入口曝光后的点击次数。
- 首页不再因无限加载导致底部元素不可达；用户滚动到首页底部后必须能在 1 次滚动内看到页脚或新的底部转化区。
- dev 测试入口与生产主域隔离，未通过验证的改版不得部署到 `616618.xyz` 和 `api.616618.xyz`。

### 2. User Experience & Functionality

**User Personas**:

- 访客用户：希望快速判断站点是否可信，并按城市、地区或风格找到想看的内容。
- 潜在会员用户：关注真实反馈和站点规则，希望在联系站长前了解访问规则、会员说明和案例可信度。
- 案例浏览用户：从首页或案例列表进入，想连续查看多个真实案例图片组以判断站点可信度。
- 移动端用户：使用手机浏览首页，希望标签、真实案例和联系方式入口都清晰可点，不被复杂区块压住。
- Owner/管理员：需要在后台维护真实案例图片、规则说明和悬浮入口文案，不希望每次调整都重新部署。
- 开发/测试人员：在站点正式上线后，需要使用 dev 子域验证 UI 和功能，避免影响线上用户。

**User Stories**:

- As a 访客用户, I want 首页轮播图减少按钮干扰 so that 我能更专注地浏览精选封面和内容质感。
- As a 访客用户, I want 首页有明显的城市和标签导航 so that 我能快速进入具体城市或偏好类型的图库。
- As a 潜在会员用户, I want 查看真实用户好评案例 so that 我能判断站点内容质量和服务可信度。
- As a 案例浏览用户, I want 打开真实案例列表页 so that 我能集中浏览所有公开好评案例。
- As a 案例浏览用户, I want 打开真实案例详情页 so that 我能查看一个案例下的多张图片和完整说明。
- As a 潜在会员用户, I want 看到类似“新消息”的联系站长入口 so that 我知道可以点击咨询会员或访问问题。
- As a 潜在会员用户, I want 点击规则悬浮窗先看弹窗摘要并可跳转规则页 so that 我能快速了解本站规则与引导说明。
- As an Owner, I want 在后台上传和排序真实案例图片 so that 首页案例轮播可以持续更新。
- As an Owner, I want 在后台配置规则入口和富文本内容 so that 运营说明可以独立维护。
- As a 开发/测试人员, I want 使用 Workers dev 子域访问未上线改版 so that 我能用正式数据验证体验但不影响真实用户。

**Acceptance Criteria**:

- 轮播图必须去除“浏览精选图库”和“地区精选”两个按钮；如需行动入口，只能通过导航、标签区、真实案例或悬浮入口承接。
- “按地区发现”区块必须替换为“真实案例”轮播区块，标题建议为“真实案例”或“用户好评”，副标题强调用户反馈与站点可信度。
- 真实案例为后台可维护内容；每个案例至少包含标题、状态、排序、展示开关和 2-9 张图片。
- 真实案例必须提供公开列表页，建议路由为 `/testimonials`，支持分页、排序和空状态；首屏至少展示 6 个已启用案例。
- 真实案例必须提供公开详情页，建议路由为 `/testimonials/:slug`，展示标题、说明、图片组、发布时间、返回列表入口和联系站长入口。
- 真实案例详情页必须支持桌面端画廊布局和移动端滑动浏览，图片组不得一次性阻塞首屏加载。
- 首页真实案例轮播卡片必须可跳转对应案例详情页，列表页卡片也必须可跳转详情页。
- 真实案例图片必须存储在 R2，并通过公开图片接口或后续图片优化链路展示；不得引用未授权外部图片。
- 真实案例轮播桌面端展示为横向画廊或大图 + 缩略图组合，移动端展示为可滑动卡片，触控目标不小于 44px。
- 首页底部“加载更多”必须移除或改为明确的分页/查看更多入口，不能持续追加内容导致底部信息永远不可达。
- 首页底部元素需要删除或重新设计为可触达的转化区；如保留页脚，应展示简洁版权、规则入口和联系方式入口。
- 首页标签导航必须重新设计为更明显的分层导航，城市/地区标签优先展示，风格/身份/场景作为辅助筛选。
- 标签导航需支持“热门城市”“地区组”“风格偏好”至少 3 个可视分组，点击后跳转到发现页或搜索页的对应筛选结果。
- 联系站长悬浮入口必须从胶囊样式调整为消息 icon 样式，包含轻微跳动、未读红点或消息提示气泡，动效应克制且不遮挡内容。
- 联系站长入口上方必须新增规则/引导悬浮入口，支持后台配置标题、简短说明、图标、富文本内容和规则页跳转链接。
- 规则入口点击后默认打开弹窗，弹窗内展示富文本摘要，并提供“查看完整规则”跳转至规则页。
- 关于页面和后台关于页配置从产品范围中移除；前台主导航不得再出现“关于”。
- 正式上线后的所有功能开发必须先在 dev 子域验证；dev 子域可以连接正式 D1/R2 数据，但 Worker 名称、域名和部署命令必须与生产隔离。
- dev 子域必须有明显测试环境标识，避免内部测试人员误认为已上线；不得被公开导航、SEO sitemap 或生产页面链接到。
- 所有新增前台文案必须使用中文，禁止露骨、擦边、夸大疗效式或虚假承诺文案。

**Non-Goals**:

- 本轮不开放普通用户上传真实案例。
- 本轮不实现评论、评分、点赞、私信或社交互动系统。
- 本轮不引入第三方客服系统或非 Cloudflare 基础设施。
- 本轮不实现复杂 A/B 测试系统，仅预留曝光与点击统计口径。
- 本轮不重做后台整体框架，只新增真实案例和规则配置所需页面或设置项。
- 本轮不创建独立 dev 数据库；dev 环境允许只读或谨慎读写正式数据，但必须通过权限和流程约束避免误修改生产内容。
- 本轮不把 dev 子域公开给普通用户，不做 SEO 收录，不作为长期运营入口。

### 3. AI System Requirements (If Applicable)

**Tool Requirements**: 不适用。本需求不包含 AI 生成功能，不需要模型推理、向量检索或 AI 工具调用。

**Evaluation Strategy**: 不适用 AI 质量评估。效果评估以响应式 UI 验收、点击路径、真实案例后台配置、权限检查和构建验证为准。

### 4. Technical Specifications

**Architecture Overview**:

- 前端继续使用 Nuxt 3 + Vue 3 + Tailwind CSS v4，整体视觉按 `frontend-design` 要求执行“珍珠杂志感 + 消息信笺式悬浮入口”。
- 后端继续使用 Hono API Worker 和 D1；真实案例、规则配置和图片元数据由后台 Owner/Admin 维护。
- 图片资源继续存储在 Cloudflare R2；真实案例图片使用公开访问路径，但必须由管理员上传并经过授权确认。
- 首页通过公开 API 获取真实案例列表、规则入口配置和标签导航数据，SSR 首屏应可渲染默认内容。
- 开发测试使用 Workers dev 子域承载独立 Web/API Worker，默认连接正式 D1/R2 bindings 以复用真实内容数据；涉及写操作的后台测试必须限定管理员账号和操作范围。

**Integration Points**:

- `GET /api/settings/public`：新增规则悬浮入口公开配置，包括标题、短说明、图标类型、弹窗富文本摘要、规则页链接和启用状态。
- `PATCH /api/admin/settings`：Owner 可配置规则入口内容，保存后写入审计日志。
- `GET /api/testimonial-cases`：公开获取已启用真实案例列表，按排序和创建时间返回。
- `GET /api/testimonial-cases/:slug`：公开获取单个真实案例详情，返回标题、说明、图片组、发布时间和 SEO 元数据。
- `POST /api/admin/testimonial-cases`：管理员创建真实案例，包含标题、说明、排序和启用状态。
- `PATCH /api/admin/testimonial-cases/:id`：管理员编辑真实案例文案、排序和状态。
- `POST /api/admin/testimonial-cases/:id/images`：管理员上传真实案例图片到 R2。
- `DELETE /api/admin/testimonial-cases/:id/images/:imageId`：管理员删除案例图片并清理 R2 对象。
- `GET /api/tags`：继续作为首页标签导航数据源，前端按城市/地区/风格分组展示。
- 前台路由：新增 `/testimonials` 真实案例列表页、`/testimonials/:slug` 真实案例详情页；移除 `/about` 的主导航入口；如规则页需要独立页面，建议新增 `/rules`。
- Dev 环境：建议使用 Workers dev 子域，例如 `meigallery-web-dev.<workers-subdomain>.workers.dev` 和 `meigallery-api-dev.<workers-subdomain>.workers.dev`；生产仍为 `616618.xyz` 和 `api.616618.xyz`。

**Security & Privacy**:

- 真实案例必须由管理员上传，普通用户不得直接上传或发布。
- 真实案例图片必须确认授权来源，不允许包含用户隐私、聊天账号、联系方式、付款凭证或可识别个人敏感信息，除非已脱敏并有明确授权。
- 后台真实案例新增、编辑、删除、上传图片和规则配置变更必须写入审计日志。
- 规则富文本必须进行白名单清洗，仅允许安全标签和链接；外链必须使用 `rel="noopener noreferrer"`。
- 真实案例公开 API 只返回已启用内容，不返回后台备注、上传人、审计字段或 R2 私有 key。
- 联系站长和规则悬浮入口不得遮挡登录、注册、会员解锁、图片查看器关闭等关键操作。
- dev 子域不得出现在生产 robots、sitemap、主导航或公开链接中；建议添加 `X-Robots-Tag: noindex, nofollow` 或等价 meta。
- dev 环境如连接正式数据，后台写操作必须继续要求管理员权限、审计日志和显式测试提示。

### 5. Risks & Roadmap

**Phased Rollout**:

- MVP：更新首页 PRD/UI 结构；移除轮播按钮；替换地区发现为真实案例轮播；新增真实案例列表页和详情页；重做首页标签导航；改造联系站长与规则悬浮入口；移除关于页入口和后台配置；补充后台真实案例配置需求；明确 dev 子域开发测试流程。
- v1.1：增加真实案例曝光/点击统计，支持案例按设备端排序，优化移动端轮播手势和图片预加载；补充 dev 环境 smoke test 清单。
- v2.0：基于真实访问数据调整首页标签分组和规则入口文案，评估是否加入多版本运营配置或节日专题皮肤。

**Technical Risks**:

- 真实案例如果缺少授权或脱敏流程，会带来隐私与信任风险，必须在后台操作流程中显式提示。
- 真实案例图片数量过多可能影响首页首屏性能，需要懒加载、图片压缩和最大展示数量限制。
- 消息 icon 跳动过强可能显得廉价或打扰用户，动效需保持高级克制。
- 移除关于页后，站点规则、版权、联系方式和说明必须由规则页或规则弹窗承接，避免信息缺口。
- 标签导航如果展示过多城市，移动端会拥挤；必须按热门程度、地区组和折叠展开控制密度。
- dev 子域连接正式数据会降低造数成本，但存在误改生产内容的风险；后台写操作必须保留审计和测试提示。
- dev 子域如果被搜索引擎收录或被用户访问，可能造成未上线功能外泄；必须加 noindex 和非公开入口限制。
