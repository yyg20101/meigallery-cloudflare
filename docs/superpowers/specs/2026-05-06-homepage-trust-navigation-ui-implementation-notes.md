# 首页真实案例与导航体验 UI 实施备注

## 1. 目的

本备注补充 `docs/UI_DESIGN.md`、首页真实案例 PRD 和实施计划中容易在开发时跑偏的 UI 决策。开发时以本文件作为前端实现细节的裁定依据；如与旧示例冲突，以本文件为准。

## 2. 视觉方向锁定

整体方向为**珍珠杂志感 + 消息信笺式可信引导**。

关键词：暖白、留白、黑金、柔阴影、真实图片优先、轻量信任提示、克制动效。

避免：粉紫大渐变、通用营销页 hero、虚构评价、过度客服弹窗、强烈抖动动效、彩色标签堆叠抢图。

## 3. 字体策略

不新增远程字体依赖，避免加载风险。先使用系统内置高质量中文字体栈，并通过字重、字距和排版建立杂志感。

建议 CSS 变量：

```css
:root {
  --font-display: "Songti SC", "STSong", "Noto Serif CJK SC", serif;
  --font-body: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
  --font-label: "PingFang SC", "Hiragino Sans GB", sans-serif;
}
```

使用规则：

- 首页 hero 标题、真实案例标题、规则弹窗标题优先使用 `--font-display`，字距 `-0.04em` 到 `-0.02em`。
- 正文、标签、表单和后台继续使用 `--font-body`。
- 英文小标题如 `Discover`、`Private Contact` 使用 `--font-label`，大写、字距 `0.18em` 到 `0.26em`。
- 不使用 Arial、Roboto、Inter 作为显式首选字体。

## 4. URL 与导航参数

发现页筛选统一使用现有实现口径：

```text
/discover?tag=slug-a,slug-b&sort=latest
```

不要新增 `/discover?region=...&personality=...` 这类并行参数。标签导航、真实案例详情页 CTA、搜索页相关标签跳转都应复用 `tag` 参数，避免后端筛选逻辑分叉。

## 5. 首页标签导航

组件：`HomeTagNavigator.vue`。

分组固定为三类：

| 分组 | 数据来源 | 数量 | 跳转 |
|------|----------|------|------|
| 热门城市 | `city`、`city_country` | 最多 8 个 | `/discover?tag=<slug>` |
| 地区组 | `region_scope`、`region_group` | 最多 8 个 | `/discover?tag=<slug>` |
| 风格偏好 | `style`、`personality`、`scene` | 最多 12 个 | `/discover?tag=<slug>` |

视觉要求：

- 桌面端使用三列或三段式横排，每组有标题和 1 行短说明。
- 移动端优先展示“热门城市”，横向滚动，首屏至少露出 4 个入口。
- 默认态为暖白底 + 细边框；hover/active 使用黑底白字或黑金描边。
- 标签点击目标不小于 44px 高度或等效可点击面积。

## 6. 真实案例轮播

组件：`TestimonialCarousel.vue`。

桌面端：

- 推荐布局：左侧 1 张主图，右侧 2-4 张缩略图，下方或右侧显示标题、摘要、图片数量。
- 每屏最多展示 3 个案例或 1 个重点案例，不要把首页做成密集评价墙。
- 轮播控制使用左右箭头 + 当前序号，不强制自动播放。

移动端：

- 单卡横向滑动，卡片宽度约 `82vw` 到 `88vw`。
- 卡片图片比例优先 `4:3`；如果真实图片偏竖图，使用 `3:4`，同一区块内保持一致。
- 底部显示标题、图片数量和一行摘要，不显示长正文。

状态要求：

- 加载中：暖白骨架卡片，保留与真实卡片接近的高度，避免布局跳动。
- 空数据：首页显示紧凑空态，不使用假案例，不使用外部占位图。
- 图片失败：显示暖白渐变占位、案例标题和“图片暂不可用”，卡片仍可进入详情页。
- 无障碍：轮播按钮有 `aria-label`，卡片链接有明确标题。

## 7. 真实案例列表页与详情页

列表页 `/testimonials`：

- 桌面端 3 列杂志卡片；移动端 1 列大卡优先，只有图片质量稳定后再考虑 2 列紧凑卡。
- 顶部文案使用“真实案例”“授权反馈”“已脱敏展示”，避免写成“买家秀”“用户晒图”。
- 空状态文案固定：`真实案例整理中`。

详情页 `/testimonials/:slug`：

- 桌面端左图右文；右侧包括标题、摘要、发布时间、图片数量、联系站长入口。
- 移动端单栏：标题和说明在首图之前，图片组 lazy load。
- 底部 CTA 保持 2-3 个以内：`返回案例列表`、`联系站长`、`查看更多图库`。
- 不展示上传人、后台备注、R2 key、隐私字段或未脱敏截图。

## 8. 悬浮入口

联系入口：

- 从长胶囊收敛为消息 icon 或短胶囊，默认文案不超过 6 个中文字符。
- 可显示红点和“有新消息”，但动效周期不短于 4 秒。
- 展开浮层最大高度不超过视口 45%，内部滚动。

规则入口：

- 固定在联系入口上方，视觉更安静，不抢联系入口主 CTA。
- 弹窗标题使用黑金强调，正文 13-14px，列表行距充足。
- 弹窗底部只保留一个主链接：`查看完整规则`。

层级要求：

- 不遮挡底部 Tab Bar、图片查看器关闭按钮、登录/注册提交按钮。
- 图片查看器打开时，悬浮入口应隐藏或降低层级，避免误触。

## 9. 后台真实案例管理

后台风格保持工作台，不使用前台杂志装饰。

列表页：

- 空状态显示 `还没有真实案例`、`新建案例` 主按钮、`发布前需上传 2-9 张已授权、已脱敏图片。`
- 状态 badge：草稿灰色，已发布绿色，精选金色描边。
- 图片数低于 2 或高于 9 时在列表中显示黄色提示。

编辑页：

- 图片上传区使用虚线边框，文案明确 `仅上传已授权、已脱敏图片`。
- 图片排序优先用上移/下移按钮实现，避免首期引入拖拽复杂度。
- 发布按钮旁显示校验提示：`发布需要 2-9 张图片、标题和 slug`。
- 删除图片和删除案例必须二次确认。

## 10. 响应式验收点

开发完成后至少检查：

| 宽度 | 必查内容 |
|------|----------|
| 375px | 首页首屏不拥挤，标签导航首屏后一屏内可见，悬浮入口不挡底部 Tab |
| 768px | 标签导航不换行成混乱长列表，真实案例卡片比例稳定 |
| 1440px | 首页分区有足够留白，真实案例不显得稀疏，最新图库仍为 4 列 |

## 11. 开发优先级

先完成结构和状态，再打磨动效：

1. 首页去除轮播按钮、移除无限加载。
2. 标签导航和真实案例真实数据接入。
3. 空态、加载态、图片失败态。
4. 悬浮联系和规则入口。
5. hover、进入动效和细节阴影。

不得为了视觉效果牺牲可访问性、真实数据边界或 Cloudflare-only 架构约束。
