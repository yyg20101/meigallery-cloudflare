## 3. 内容和标签观察

公开分类以“地区/城市/国家”为主，适合迁移为结构化地区标签：

- `region_scope`：国内、海外、港澳台。
- `region_group`：华东、华南、华西、华北、国家组等。
- `region_name`：城市、国家或地区名称。

公开标签数量较少，且混合了内容身份、风格、服务意图等语义。建议迁移时拆分为：

- `identity`：模特、网红、留学生等。
- `style`：制服、反差等。
- `scenario`：伴游等敏感运营词需要审核后决定是否保留。
- `contact`：联系方式应迁移为系统配置，不应作为普通内容标签。

注意：现有分类和标签中存在较多敏感词。新平台如果坚持“面向所有人”，应把这些词从前台可见分类中清理或改名，例如把城市分类改为“城市/地区”，把敏感词迁移到后台内部标签或直接不迁移。

## 4. 内容模型观察

公开文章样本结构：

- 标题通常包含国家、城市、昵称或描述。
- 正文通常包含多张图片。
- 部分文章包含 mp4 视频。
- 正文末尾常有简短文字说明。
- 文章通过分类关联地区，通过标签关联风格或身份。
- 部分图片为纵向比例，常见宽高接近 9:16 或 3:4。
- 视频多为移动端竖屏比例。

新系统需要支持：

- 一个图库包含多张图片。
- 一个图库可包含 0 到多个视频。
- 图片和视频均需要记录原始宽高、展示比例、排序。
- 详情页必须优先适配竖图和竖视频。
- 文章标题需要解析为结构化字段，但保留原始标题用于迁移审计。

- 移动端菜单和搜索体验。

## 6. 迁移需求

需要新增迁移工具或后台导入模式：

- WordPress REST API 导入：导入文章、分类、标签、图片 URL、视频 URL。
- WordPress XML 导入：作为 REST API 不完整时的备选。
- 本地 zip 导入：用于新内容发布。
- 媒体抓取任务：从旧站媒体 URL 拉取图片和视频到 R2/Stream。
- 内容清洗任务：移除敏感词、统一地区命名、拆分标签类型。
- 迁移审计表：保存旧站 `post_id`、旧 URL、旧分类、旧标签、迁移状态和错误。

迁移后必须执行：

- 内容合规审核。
- 媒体授权确认。
- 标题和标签清洗。
- 图片和视频权限重新设置。
- SEO 跳转映射。

## 7. 技术风险

- 旧站直接暴露媒体 URL，不能作为新系统的权限模型。
- 当前右键禁用不是防盗链方案，新系统必须使用服务端授权。
- WordPress 正文是 HTML，需要解析图片、视频、段落、标题。
- 旧分类命名和新站“全龄内容”定位存在冲突，需要人工审核。
- 搜索热门词存在编码异常，需要新系统统一 UTF-8 处理。
- 当前站点使用第三方广告和追踪脚本，新系统应改为后台可配置。

## 8. 新系统机会点

- 将地区分类结构化，支持国内/海外/港澳台、多级地区、城市标签。
- 将旧标签拆分为身份、风格、场景、内容类型等标签组。
- 对每个图库生成“公开摘要”和“后台备注”，避免敏感运营文案直接展示。
- 建立媒体资源库，避免重复图片和视频。
- 建立迁移预览页，管理员确认后再发布。
- 用 Cloudflare R2/Stream 替代 WordPress uploads 公开直链。
